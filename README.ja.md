# ARTEX Mac：開発中のネイティブMac版

SwiftUIと、アプリが管理する専用Linux VMで構築しています。**現在は設計とVM技術実証の段階で、ARTEX全機能の移植は未完了です。** 既存のブラウザ版とデータは別環境として残しています。

## 確認できたこと

- AppleのVirtualization.frameworkで本物のARM64 Linuxを起動・正常停止し、2回連続の起動/停止に成功。
- Docker・ホスト共有・ネットワーク機器・永続ディスクなしで動作。
- 改変したカーネルはVM作成前に拒否。起動完了を返さない実ゲストはタイムアウトを表示し、強制停止で復旧。
- 機能一覧の漏れ、状態遷移、ハッシュ・パス・シンボリックリンク、共有/通信/ディスク禁止を確認する4件の基本テストが成功。
- ローカル署名した.appを起動。アプリ自身の診断からVMを起動・停止できることを確認。

ただしネイティブ画面の自動操作ツールに接続障害があり、実ボタンクリックと画面比較の最終判定は保留です。アプリ内部で取得したコンテンツ画像にはレイヤー合成の制限があるため、UI/UXの合格証拠として扱っていません。

## 開く・ビルドする

生成したアプリは `dist/ARTEX Mac.app` です。実行環境の画面で隔離Linuxを起動/停止できます。サイドバーはブラウザ版の順序と項目名を引き継ぎ、まだ操作できない機能には移植待ちを表示します。チャットやタスクが動くように見せたモックはありません。

開発環境はApple Silicon/macOS 15以降、Xcode/Swift 6、Python 3です。

```sh
./script/build_and_run.sh --verify
swift test
./script/test_vm.sh
python3 script/check_baseline.py /path/to/pinned/artex-global
```

ゲストのビルド材料はAlpine公式配布の固定バージョン/ハッシュを利用し、Linuxの実行ファイルをMac上で直接実行しません。この技術実証はビルド時もDocker不要です。.appには起動用ゲストを同梱します。アプリ利用時にPythonや手動サーバー起動は不要ですが、現段階のゲストにはARTEX本体・DB・データディスクがまだ入っていません。
