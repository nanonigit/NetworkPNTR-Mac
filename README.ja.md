# ARTEX Mac：開発中のネイティブMac版

SwiftUIと、アプリが管理する専用Linux VMで構築しています。**現在は隔離VMの技術実証とネイティブ画面の段階移植中で、ARTEX全機能の移植は未完了です。** 既存のブラウザ版とデータは別環境として残しています。

## 確認できたこと

- AppleのVirtualization.frameworkで本物のARM64 Linuxを起動・正常停止し、2回連続の起動/停止に成功。
- Docker・ホスト共有・ネットワーク機器・永続ディスクなしで動作。
- 改変したカーネルはVM作成前に拒否。起動完了を返さない実ゲストはタイムアウトを表示し、強制停止で復旧。
- 最新チェックポイントはSwift363件（成功362・AX1件明示スキップ）・Python60件成功。これだけでUI全体や実行環境の受け入れを完了とはしません。
- ローカル署名した.appを起動。アプリ自身の診断からVMを起動・停止できることを確認。

LLM画面では実際のクリックで作成・編集・入力検証・Return保存・有効設定の削除禁止まで確認しました。途中で操作ツールの接続が切れたため、全操作と画面比較の最終判定は保留です。アプリ内部で取得したコンテンツ画像にはレイヤー合成の制限があるため、UI/UXの合格証拠として扱っていません。

別のバックエンド検証用ゲストでは、ARTEX・PostgreSQL 16・認証付きvsock通信・専用保存ディスクが動作しました。通常再起動と強制停止後も認証情報とLLM設定を保持し、使い捨ての固定ブラウザ版と5つのAPI条件が一致しました。[検証記録](docs/phase2-verification.ja.md)を参照してください。現在は実際のバックエンドをアプリに同梱し、ネイティブの初期設定・ログイン・ログアウトとKeychain保存を接続しました。2 vCPUでは間欠的なカーネル異常が残っています。1 vCPUの直接ルート診断では認証の反復に成功し、別途見つかったDB復旧待ちの不具合を修正後、強制復旧3回にも成功しました。配布品質の安定性は未合格です。[調査記録](docs/bugs/guest-boot-investigation.ja.md)に経緯を残しています。

## 開く・ビルドする

生成したアプリは `dist/ARTEX Mac.app` です。実行環境の画面で隔離Linuxを起動/停止できます。サイドバーはブラウザ版の順序と項目名を引き継ぎます。LLM設定・ダッシュボード・チャット基本画面を実装し、比較検証中です。タスク一覧/詳細・作成と有限操作も実APIへ接続しましたが、単体/非表示レイアウト試験のみで実比較は未完了です。残る17画面は移植待ちです。[LLM検証記録](docs/llm-settings-verification.ja.md)にAPI比較と実操作の範囲を記録しています。ダッシュボードのデータ入り12通りの集計が、使い捨ての固定ブラウザ版・独立した計算と一致しました。[ダッシュボード検証記録](docs/dashboard-verification.ja.md)に実操作と未完了条件を記録しています。全21機能の受け入れ条件はまだ未完了です。チャットやタスクが動くように見せたモックはありません。

固定したソースから別途構築したLinuxカーネル候補で、実VMの復旧・署名済みアプリのサービス・ブラウザ版比較が成功しました。同じMac上の別コンテナによる2回の構築で、カーネルと設定のハッシュが一致しました。配布の信頼性、別環境・配布物全体の再現性とUI同等性は未完了です。[検証記録](docs/kernel-build-verification.ja.md)を参照してください。

開発環境はApple Silicon/macOS 15以降、Xcode/Swift 6、Python 3です。

```sh
# 最初にバックエンドを準備（開発時だけDockerを使用）:
python3 script/prepare_backend.py --source /path/to/pinned/artex-global
./script/build_and_run.sh --verify
swift test
./script/test_vm.sh
python3 script/check_baseline.py /path/to/pinned/artex-global
# バックエンド検証（固定したローカルブラウザ版イメージとDockerが必要）:
./script/test_backend.sh /path/to/pinned/artex-global
```

ゲストのビルド材料はAlpine公式配布の固定バージョン/ハッシュを利用し、Linuxの実行ファイルをMac上で直接実行しません。バックエンド構築時は固定したLinuxコンテナを使用します。.appにはARTEXとDBを含むゲストを同梱し、利用時はDocker・Python・手動サーバー起動を呼びません。アプリ専用の保存ディスクを作成します。ビルドで置き換える前はアプリを通常終了し、VMの保存と停止を完了させてください。安定性を調査中の開発版です。
