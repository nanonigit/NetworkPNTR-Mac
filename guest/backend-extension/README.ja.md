# 管理対象backend拡張

基準はe75ae371ad777ffd1eecdd28d2781a6519b05591。固定ブラウザcheckoutを変更しない。現在は認証付きの構造化メタデータAPIと、既存hash表記を維持した安全なBlob配信パッチを試験・コンパイル済み。VMゲスト／ネイティブ保存機能としては未導入。残りのhandler／認証／転送／ビルド／UI／実行条件はdocs/traffic-blob-design.mdを参照。

固定Linux／arm64のGoビルダーでgo.mod／go.sumを検証し、managed.patchを検査・適用し、ネットワークなしでtraffic／serverパッケージ全体を試験し、ブラウザUIを内蔵しないCGO不要のLinux／arm64 backendを/out/artexへビルドする。DB／fixture依存の既存スキップは未検証と明示する。ホストPythonは安全なGit archiveの配置とDocker操作だけを行い、アプリやGoコンパイラーをホストで実行しない。リポジトリrootから英語版README.mdの再現手順を使う。Pythonのtarfile.extractall(filter='data')に対応する環境が必要。

依存追加はなし。現在／旧形式のblobを、ディレクトリFD基準・非ブロッキング・シンボリックリンク非追跡で開き、通常ファイルだけを許可する。固定checkoutは変えず、管理対象コピーのBlobだけを安全な処理へ接続する。追加経路も既存JWT認証内に置き、生SQLエラーを出さず400／404／503を区別する。生HTTPのmarkerを所有関係とみなさず、保存用の架空の検出結果や紐付け変更を作らない。この手順でホスト共有、Docker socket、既存stateのマウント、外部スキャン、クラウド呼出し、通常ゲスト昇格は行わない。
