# エージェントのモデルと実行上限の検証

プロンプトタブでエージェントごとのモデル指定と引き継ぎを選べます。実行上限を表示する対象は固定ブラウザ版と同じで、0 は無制限です。保存先の範囲内の非負整数を入力できます。指定済みモデルが候補から消えている場合は保存済み ID を表示します。

認証済みの `PUT /api/agents/{key}/config` に変更した項目を送ります。モデルの指定解除には明示的な null を送り、未変更の項目は省略します。保存後に指定した値を読み直し、未編集の項目にはゲストの最新値を反映します。別の欄の下書きも保持します。結果が不明な場合は、再試行前に再読み込みを求めます。

`e75ae371ad777ffd1eecdd28d2781a6519b05591` の使い捨て Docker 参照環境で、検証用のモデル設定を指定して最大12回と45秒を保存し、null で引き継ぎへ戻しました。保存した上限は維持されました。キーの空欄はゲストに拒否されたため、実サービスに使えないダミー値と予約ドメイン example.invalid を使いました。モデルとエージェントは実行していません。表示条件と優先順位は固定版を基準とし、モデル選択の配置は Lazyweb の Cursor の例も参考にしました。

署名済み Mac 版を隔離 Linux VM に接続して、Goals ではモデル選択が表示され、上限欄は非表示になることを確認しました。Worker では検証用モデルと12回・45秒を保存でき、引き継ぎに戻して開き直すと保存済みの上限が表示されました。検証後に VM を停止し、一時キーチェーン項目と VM 状態を削除しました。

`swift test --filter AgentExecutionSettingsTests` で送信内容、項目の省略、検証、部分的な反映を試験します。Web 検索とシェルの設定、ツール紐付け、トリガー、認証後のブラウザ実画面比較は残っています。

Swift 1,078件とゲスト関連195件が成功し、既存の1件がスキップされました。リリースビルドと更新したプレビューの署名検証も成功しました。GitHub Actions は利用枠ポリシーに従いスキップしました。
