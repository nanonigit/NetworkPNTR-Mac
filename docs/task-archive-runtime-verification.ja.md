# T17b アーカイブ実行検証

有限のネイティブAPI試験、ゲスト内限定の固定障害注入、DEBUG限定の型付きソース送信クライアント、3起動VMプローブ、独立したPython参照を実装した。製品UI変更はなく、このインフラ段階はLazyweb対象外。ブラウザ比較元は未変更のe75ae371ad777ffd1eecdd28d2781a6519b05591。ソースカーネル候補は昇格していない。

実機: 新規2GiBディスク1つを1CPUのVZで3回起動し、ネットワークデバイス・外部経路・ホスト共有は0。1回目は新規認証設定と、タスク作成APIやAIを動かさない終端済み2タスク・3ファイルの投入。2回目は保持した認証トークンで接続し、一括アーカイブ、パッケージ隔離によるrestore_failedの観測、修復と明示的再試行、1つ目の正確な復元、2つ目の削除、1つ目の再アーカイブ。3回目は同じディスクと保持トークンで保存済みパッケージのメタデータ・ハッシュを確認し、タスクとファイルを復元、2つ目が削除されたままであることを確認した。3回とも転送を中断せず正常停止し、停止後の完全なシリアルログで隔離・秘密情報非出力・診断異常なしを確認。ディスク初期化は1回目だけ。PATHは/usr/bin:/binであり、ネイティブプローブがDocker CLIを必要としないことの証拠となる。Docker Desktop停止状態や未導入Macの受入試験ではない。

独立参照: キャッシュされた不変のゲスト実行イメージ735d063fを使用し、e75バックエンド実バイナリのSHA256一致を検証。新規のnetwork:none・ルート読取専用・状態tmpfsの別コンテナで、ホストバインド・公開ポート・特権モードなし。初期準備の権限はCHOWN/FOWNER/SETUID/SETGIDのみ。PostgreSQLはUID70、アプリはUID1000、JWT保存先はUID1000/0700。同じ使い捨て状態でバックエンドを3回起動し、ログインへのフォールバックなしで保持トークンを確認し正常停止した。Pythonが独立実装した同じAPI手順で、19項目・Unicodeメタデータ・3ファイル計1056バイトがネイティブと完全一致。動的アーカイブID・圧縮パッケージのハッシュは各環境内で検証し、独立生成されたパッケージ同士の一致は要求しない。固定3ログをサイズ制限付き読取で保存し、公開するのは正規化した証拠のみ。所有コンテナの削除・不存在と、既存ブラウザ4コンテナの同一性を確認した。

失敗した参照試行も保存: 準備時の権限名表記の不一致、items:nullの誤拒否、処理結果は一致したがDockerのtmpfsコピーに失敗して終了1となった試行。成功に書き換えず、最後の新規環境でnull処理・固定ログ読取を修正して全ゲートと終了0を確認した。詳細とRED履歴はbugs/task-archive-exercise-boundaries.ja.md。成功した元のVM試験を失敗の隠蔽目的で再実行していない。
