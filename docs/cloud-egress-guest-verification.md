# Linux cloud egress client verification

The cloud5 candidate includes the opt-in Linux client for host CID 2 and port 8790. It converts exact provider operations into the same wire format as the Mac broker. An invalid or unavailable route fails without falling back to a direct connection. The client uses a nonblocking Linux socket, keeps its write side open while reading, and closes the owned connection on cancellation. [Linux VSOCK interface](https://man7.org/linux/man-pages/man7/vsock.7.html)

An isolated pipe fixture checks exact Gemini request bytes, single-byte response fragmentation, malformed heads and frames, unexpected EOF and cancellation. Integration tests exercise the existing completion and model discovery entry points. The pinned SDK initially accepted an SSE DONE marker without the broker terminal, and replayed a POST four times after loss of its head. After the fix the SDK verifies the end frame for success and error responses, including 429 and 503, and an unconfirmed POST is sent once. The task router and worker classifiers also reject the outcome-unknown marker. A capture fixture verifies that recording preserves the terminal requirement and that incomplete quota responses remain errors. Anthropic and OpenAI Responses error events retain the provider error only after a verified terminal.

The offline Linux build uses the pinned browser commit, previous managed patches, the provider vsock patch, the pinned SDK terminal patch and the new client overlay. See the [receipt](../evidence/llm/cloud-egress-guest-verification.json) for input hashes and test counts. The fixture substitutes a pipe for AF_VSOCK. Signed VM delivery, activation, live APIs and frozen browser comparison remain separate acceptance tests. Hosted CI remains unverified.
