# F5d 証跡原文の全バイト保存

## 要件

固定版のGET findings/{finding}/traffic/{binding}/body?side=...&download=1とcontext_taskに対応し、スナップショットの元の長さ・SHA256に一致する本文全体を保存する。ヘッダ・表示文字列・blob参照・切れたプレビュー・ダイジェストだけで代用しない。既存添付の検証動作を維持する。プロバイダ通信・エージェント実行・ホスト共有・ゲストが任意指定するパス／URLを追加しない。

保存先はネイティブ保存画面で承認されたローカルURLのみ。ブラウザ同様に既存ファイルを壊さず、ファイル・シンボリックリンクを黙って置換しない。選択先の親を固定し、同じファイルシステムの非公開領域へ小分けに書き、実ファイルを検証して新規ファイルとして原子的に公開する。公開前の取消・失敗では所有する途中状態を消し、最終名を作らない。公開後は取消・破棄で保存済みファイルを消さない。公開後の清掃・ディレクトリ同期は別の状態で返し、「保存されていない」と誤報しない。

## 設計と段階

1. F5d1基盤：数値ID・側・文脈・64桁小文字ハッシュのFindingEvidenceDownload、固定認証要求、親ディレクトリの能力、0700の途中領域・0600本文、ストリーム書込とVerifiedEvidenceFile。既存HTTP解析に200のみの本文出力と要求ごとの長さ上限を追加。添付の128MiB既定値は維持し、証跡は64KiBのバッファで元サイズ通り扱う。受信長・ハッシュと、別途読んだ実ファイルの長さ・ハッシュを確認。fsync・inode／長さ／時刻確認・排他的rename後に成功とする。エラー本文はファイルへ出さず、既存名／リンクは上書きしない。親が移動しても固定したディレクトリへ書き、結果URLは記述子から現在の場所を求める。
2. F5d2接続：ソケット→VMの停止・取消所有権→クライアント→認証世代。古い認証・401・取消で途中ファイルを捨て、公開時にも認証を再確認。自動再試行しない。UIの選択・活動世代も公開前に一致させる。ゲスト経路は認証済みvsockのみ。
3. F5d3操作：明示的保存画面、日英の進捗・エラー・結果、要求／応答保存とF5c全操作。記録URLの表示だけで保存しない。接続されるまで全UIは未完了。
4. 実ゲスト／ブラウザで非空・バイナリ・大容量・取消・非上書きのバイト／ハッシュを比較し、解除済みMacで保存・キー操作・VoiceOver・画像を照合。今回の試験は所有する一時領域と合成ソケットのみ。

固定版server/finding_traffic.goはContent-Lengthを付け、ハッシュ・長さを検証するOpenBodyから送る。この経路にない転送／圧縮形式を拒否し、エラー応答は既存4MiB以内。清掃失敗は明示し、デストラクタは最後の手段。本文全体をメモリにためず、Content-Dispositionの名前を信用しない。保存先はゲスト内容から独立させる。

## 試験と完了条件

API欠落RED→固定経路・不正メタデータ／認証→JSONと添付の上限を超える実バイナリ保存→長さ・ハッシュ・切断・超過・形式・出力失敗・取消→既存ファイル／リンク／親移動→実ソケット保存→レビュー・全回帰・カバレッジ・署名付きビルド。F5d1はUI変更なしのためLazyweb対象外。画面の基準はfindings-traffic-ui-design.ja.mdを維持する。認証・VM接続、実ゲスト／プロバイダ／UI、製品全体の条件は別途の証拠が必要。GitHub課金制約によるCIも未検証条件。

## F5d2 保存結果の所有権

BackendEvidenceDownloadTransportは、検証済み作業ファイルとVM寿命の検証を持つMainActorのEvidenceExportReceiptを返す。VMControllerは転送とディスク再検証までソケット登録を保持し、タスクキャンセル／VM停止で中断、古い返答の作業ファイルを破棄する。専用epochを停止・異常・資源解放で更新し、転送後の結果も無効化する。クライアントは型付きマニフェストから固定経路だけを生成し、事前キャンセルとVM準備状態を確認する。

AuthenticationSession.authenticatedEvidenceExportは401処理前に元の認証revisionを確認し、サイズ／ハッシュ一致の成功だけを受け付け、弱参照の認証所有権検証を追加する。ログアウト／再ログイン後は画面のキャンセルに依存せず無効になる。EvidenceExportReceipt.commit(validate:)は1回だけ消費し、呼出元の画面／activity検証、その後VM／認証とキャンセルを再確認し、awaitを挟まず確定する。失敗時は明示的に作業ファイルを破棄し、後始末失敗も返す。保存済みファイルは後から破棄しない。エラー本文を画面へ転送しない。

実一時ファイルで成功、非200、401時のKeychain異常、再ログイン後の古い200／401、転送後ログアウト、キャンセル、画面検証中の状態変化、VM寿命無効化、二重確定、停止中の実クライアントを試験する。ソフトウェア所有権の検証であり、実VM停止競合とブラウザ／原文／画面の受入試験は未完。
