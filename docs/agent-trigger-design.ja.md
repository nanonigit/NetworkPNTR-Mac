# エージェントのトリガー

## 要件

固定ブラウザ版と同じカスタムエージェント用のルールと実行方針を扱う。定期実行、
脆弱性の発見、目標達成、タスクのタイムアウト、ツール呼び出し、タスク作成を
組み合わせられる。条件ごとのメッセージ、ツールの絞り込み、有効状態を保持する。

## 設計

既存の認証付き一覧・追加・更新・削除APIを使う。IDで更新・削除する前に、
選択したエージェントの最新一覧で所有を確認する。応答と再取得の両方で結果を確認し、
更新を自動再送しない。IDはInt64で保持し、旧データのnullツール一覧は空として扱う。
実行方針の更新は該当する3項目だけを送信し、読み戻す。画面操作とスケジュール実行は
ネイティブ画面の段階で受け入れを確認する。

## 試験

全条件の送信形式、別エージェントのID、不整合な応答、削除済みの行、他の設定の保持を
確認する。固定ブラウザ版のAPIと管理VMで、無効なルールを追加・編集・削除する。
無効なルールを使い、エージェントの起動を伴わずに保存を検証する。

固定版のAPIと署名済みVMで、全6条件を持つ無効なルールを追加・編集・削除できた。
VMでは再起動後に編集済みルールと実行方針を読み戻し、検証ルールを削除して
元の方針に戻した。2回の起動とも仮想NIC・ホスト共有なしで正常停止した。
Swiftテストは1,096件が合格し、既存の1件がスキップされた。
