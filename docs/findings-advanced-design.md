# F5 advanced Findings delivery

Frozen e75ae371ad777ffd1eecdd28d2781a6519b05591 remains authoritative. Requirements: complete traffic binding/inspection/download/edit/order/delete with optimistic evidence versions and inherited context restrictions; lineage; historical/active retests and deliberate start; deepen; rich reports; selected/filtered/all CSV/JSON/Markdown/ZIP exports. Preserve native isolation, en/ja owned presentation, exact user bytes and conservative uncertain writes. No feature is accepted from DTO tests alone. Actual guest/reference/state durability and unlocked native/browser/keyboard/VoiceOver comparisons remain required.

F5a adds read-only traffic contracts first: summary GET /findings/{id}/traffic, detail GET /traffic/{binding}, body GET /traffic/{binding}/body?side=request|response&offset=byteOffset, optional context_task on all three. Source: server/finding_traffic.go, db/finding_traffic.go, web/src/lib/api.ts/types.ts. Authenticated injected JSON transport, exactly200,4MiB limit, pre/post-await cancellation, no retries. Canonical positive Int64 finding/binding/context IDs; no caller credentials or arbitrary URL. Preserve unknown role strings, Unicode notes/headers/URL/method/type and opaque source IDs, never execute/open them. Versions/lengths/positions nonnegative; binding/snapshot/finding identities must agree and binding IDs unique. Required arrays may be null but may not be missing. Preview offsets are bytes, not Swift character counts:0<=offset<=next<=total, span<=8192, truncated iff next<total, and truncated pages advance. Do not equate content UTF8 bytes with consumed bytes: binary placeholders and replacement characters intentionally differ. Detail must start both previews at0 with totals matching captured lengths. Response must match the requested owner/binding/offset.

F5a tests first: frozen-source checksum fixture, large exact IDs, unknown roles and raw FEFF/NFD/CJK, empty/null/missing arrays, identity/negative/overflow/truncated failures, binary/invalid-UTF8 display vs byte offsets, query/context identity, zero-dispatch invalid input, status/size/malformed response, cancellation without retry. Then implementation, independent review, focused/full tests and coverage, signed build and exact-head CI. This is backend-only; Lazyweb out of scope. No VM fixture change or live traffic/agent/cloud operation.

F5b adds evidence mutations and state ownership/uncertainty; F5c typed lineage/retest/deepen/report operations; F5d bounded real byte export/download capability and explicit user-selected save destinations, with no arbitrary guest host-write channel. Subsequent native controls use Lazyweb plus fixed browser evidence; actual offline guest/reference fixtures must include nonempty traffic and body preservation across restart, conflict/missing/error cases and cleanup. Agent-creating operations require a separate controlled guest test, never host shell execution. Full F5 acceptance includes all of these and actual UI; F5a cannot close it.

F5b write capability takes a captured mutable FindingRecord and matching FindingTraffic snapshot, plus optional owning task context. Fixed POST bind sends traffic_refs with typed four-role choices, raw notes and opaque source IDs; Go trims source IDs and keeps the first duplicate. Do not trim notes or reject duplicate refs that the browser/backend accept. PATCH edit sends version/role/note; DELETE sends version; PUT order sends version and the full unique permutation of captured binding IDs, including an empty permutation for an empty snapshot. Inherited/no-handle/foreign-context targets and nonmember bindings fail before dispatch. JSON body is bounded to the server1MiB limit. Successful response must be exactly200, valid<=4MiB and match finding owner; edit/delete/order evidence_version must advance beyond captured version. It need not advance by exactly1 because the handler reads its summary after committing and concurrent changes can intervene. Bind may leave version unchanged for existing snapshots; its response is not proof of newly inserted evidence. Preserve post-dispatch errors as typed failures, never replay.409 is reported distinctly by HTTP status, not by matching Chinese/Korean error text. Neither a failure nor a later read proves whether the command committed. State ownership, stop/reset, captured acknowledgement, conflict refresh and uncertainty write blocking are required before UI integration; writer tests alone do not provide that state guarantee.
