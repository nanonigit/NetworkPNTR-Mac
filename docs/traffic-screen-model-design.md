# Traffic presentation and read scheduling (TR3)

Continue all original TR3–TR5 requirements. This state/scheduling checkpoint does not add screen layout; Lazyweb remains required before the actual UI. Compose TrafficFilterDrafts and TrafficStore without changing their API or backend behavior.

One root/window-owned model retains the store and its volatile unknown-write gate across feature visits. Each presentation gets a UUID lease. Begin retires prior tasks/raw drafts, stops/resumes the store and requests the initial page/hosts/settings. Old binding setters, timer callbacks and disappear callbacks require the captured lease. Stop scrubs drafts and store reads/selections/query; auth reset additionally calls resetSession. No durable or cross-window uncertainty journal is introduced.

Each text field owns a300ms task and immutable filter ticket. Sibling tasks survive query-owner rotation. A callback merges into the current query, configures the store synchronously and adopts its copied draft state only if the presentation is still owned after Observation publication. New edits/begin are refused during publication; stop/reset are queued, reset has priority and teardown observers cannot recursively restart/reset. Duplicate raw text is a no-op. Applied no-ops preserve history and do not refetch. Immediate controls use applied text only; advanced reset cancels only its four timers. Pagination is adjacent and requires the store's fresh navigation gate.

Initial/manual/query reads are owned tasks. Avoid replacing an already active same-owner read; query changes invalidate the old core read generation, cancel the old owned task and start a new one without waiting for a transport that ignores cancellation. The5s presentation loop only requests reads when page0 and the core read gate permit; it never acknowledges uncertainty or starts mutations. Timer/sleep is injectable on MainActor for deterministic tests. Production uses Task.sleep300ms/5s; deterministic fixtures prove scheduling/control flow, not real elapsed-time accuracy or UI interaction.

Tests first: independent held timers across owner changes, stale/retyped/old-presentation callbacks, stop/reset reentry and publication, rejected over-limit query non-adoption, immediate controls and advanced reset, fresh adjacent pagination, page0 polling/manual history refresh, modal suppression, held old reads and unknown-write retention without auto-retry/ack. Then read-only review, full tests/coverage and local signed build. RootView and actual native controls are a following checkpoint; feature-map stays pending and TR3 remains open.
