# T17 アーカイブ実行設計

固定e75ae371のcreateTaskは常にlaunchTaskを呼ぶため通常作成APIは使わない。信頼済みSQLでdone・未キュー・モデルNULL・時間制限0のタスクだけを投入し、意図・活動・会話・LLM使用履歴を作らない。起動/復元では終端状態はエンジン/期限開始の対象外であることをソース確認した。created/runningは投入しない。元のブラウザ環境と既定VM成果物を維持する。インフラとフィクスチャのみでLazywebは対象外。

T17aはscript/task_archive_seed_guest.pyを実装する。Linux/aarch64/UID1000、ARTEX_ARCHIVE_FIXTURE=1、ループバックのPostgreSQL artexロール/DB/5432/64桁16進パスワード/sslmode=disableを必須とする。ホストや他接続先は子プロセス前に拒否。固定psqlを-X/パスワード非対話/ON_ERROR_STOP・最小のPG環境で実行し、シェル・引数の資格情報・生stderrは使わない。トランザクションで関連ユーザーテーブルとプロフィールが空かをロック下で再確認し、固定の終了済みタスク/探索2件とカテゴリ1件を投入する。初回は独立タスクとし継承関係を作らない。正規の/state/app/data/tasksに固定ファイルだけを排他的作成し、既存内容やシンボリックリンクは拒否する。FEFF/NFD/中国語/韓国語のバイトを維持する。証拠は固定IDと相対パス/サイズ/ハッシュだけ。SQLまたはファイル失敗時は成功を返さず私的証拠を残し、自動再送・上書きせず新規ディスクが必要。SQLとファイルの原子性は主張しない。

VMProbeの既存認証付き/api/tools/custom/test診断へコミット済み固定ソースと明示フラグだけを送る。本番UI・一般的なゲストからホストへのRPC・ホスト共有を増やさない。参照版は別名の使い捨てDB/コンテナに同じSQLとバイトを投入する。releaseアプリは開発ソースを読まない。最初の境界試験段階では実VM/実DBへ投入せず、実行時比較成功とは扱わない。

後続T17bではキャンセルと段階別期限を持つ有限Core操作と202/終端待ちを実装する。1新規起動/認証/投入後に協調停止、2同じディスクで再起動/ログインしライブ行を確認、両方を保管してデータ件数・ライブ行/ファイル消失を確認、片方を復元して文字列/ファイル一致、再保管ともう片方の削除でready1件を残す、3再起動で保管残存を確認し復元とバイト一致を確認する。done・プロフィールNULL・使用0と全ログ監査でAI実行なしを確認する。不安定な起動を避けるため単一起動へ縮めない。各起動に上限を設け失敗段階を保持し、停止・候補/既定ハッシュも検証する。境界/操作/プローブの試験とレビュー前に実機へ進めず、失敗を成功や昇格としない。

独立した参照版は新規リソース、固定イメージ改訂、利用者ボリュームなし・内部ネットワークを使い、同じ投入と操作を比較する。ID/時刻/圧縮の非決定部分は正規化しつつバイトハッシュと必須確認を残す。所有する参照ID/ボリューム/ネットワークだけを削除し、元のブラウザ4コンテナを維持する。解除後の実UI比較、全21機能、通信、既知カーネル不安定性、配布は未完了。
