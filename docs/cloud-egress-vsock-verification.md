# Dedicated cloud egress listener verification

The host now has a single-request virtio socket listener on port 8790. A ready VM can opt in through the controller. Admission closes before stop, including while force-stop awaits Virtualization. A replacement boot waits until cooperative and force-stop calls return. The process admits at most four exchanges and retains each slot until its worker, peer observer and Virtualization connection have closed. Stop callbacks identify their VM so stale callbacks cannot tear down a later generation. [Virtualization socket listener](https://developer.apple.com/documentation/virtualization/vzvirtiosocketlistenerdelegate)

The protocol tests use real UNIX stream sockets and a controlled upstream. They check exact Gemini request routing and exact response frames, rejection before upstream admission for malformed requests, EOF without a success terminal on upstream failure, cancellation on stop and peer disconnect or extra input, and interruption of a backpressured writer. The VM controller rejects enabling the listener without a ready machine. These tests exercise the host worker and its cancellation path. They do not exercise actual guest virtio delivery.

The signed DEBUG cloud-history regression booted and cooperatively stopped the known candidate twice on Apple Virtualization. It preserved the same synthetic conversation on a fresh state disk across reboot and verified the isolation markers. This exercises actual start and stop with the new controller guards. The regression runs with cloud egress disabled and supplies no evidence for delivery on port 8790.

Reproduce the local tests with `swift test --filter CloudEgressSocketTests`. See the [verification receipt](../evidence/llm/cloud-egress-vsock-verification.json). A signed VM probe must verify virtio delivery, VM-stop behavior and the zero-NIC and no-share invariants. The Linux client, activation, live APIs and browser comparison are pending. Hosted CI remains unverified.
