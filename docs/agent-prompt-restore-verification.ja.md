# 組み込みプロンプト復元の検証

エージェントのプロンプト編集画面で、組み込みエージェントに復元操作を表示します。確認画面には新しい版として保存することと、未保存の下書きがある場合に置き換わることを表示します。認証済みの `POST /api/agents/{key}/prompt/reset` に空の JSON オブジェクトを送り、ゲストから返った版番号を表示します。履歴にその版が現れたら、現在の保存済み本文をエディターに反映します。応答が不明な場合や履歴が古い場合は下書きを保持し、次の書き込み前に履歴の再読み込みを求めます。

ブラウザ版を `e75ae371ad777ffd1eecdd28d2781a6519b05591` に固定した使い捨て参照環境で、Worker の編集を v2 として保存し、復元で初期本文と一致する v3 が追加されることを確認しました。v1 と v2 は履歴に残りました。Reporter は HTTP 400 を返し、履歴はそのままでした。復元ボタンの文言は固定ブラウザ版に合わせ、確認画面の配置は Lazyweb の Productboard の例を参考にしました。

署名済み Mac 版を使い捨て Linux VM に接続して確認しました。Reporter には復元ボタンが表示されませんでした。Worker の編集を v2 として保存後、復元をキャンセルすると未保存の下書きと保存済みの2版が残りました。復元を確定すると初期本文と同じ書き出しが表示され、v3 が現在の版になりました。履歴には v3、v2、v1 が並びました。検証後は VM を停止し、検証用キーチェーン項目と VM 状態を削除しました。

`swift test --filter AgentPromptEditorTests` でリクエスト、履歴保持、古い履歴からの復旧、拒否時の処理を検証します。Markdown 表示、エージェントの設定と権限、認証後のブラウザ実画面比較は残っています。

Swift 1,072件とゲスト関連195件が成功し、既存の1件がスキップされました。リリースビルドと更新したプレビューの署名検証も成功しました。GitHub Actions は利用枠ポリシーに従いスキップしました。
