# F3 Findings画面

最終目標は固定ブラウザ版の全Findings機能です。F3.1ではネイティブ画面の前に、ウィンドウが保持する画面状態を実装します。状態試験だけで画面・VM・ブラウザ・キーボード・アクセシビリティを受入済みにはしません。

## 要件と設計

- 認証済みウィンドウごとにFindingStoreを保持します。言語・サイドバー切替ではフィルター、選択、下書きを保持します。停止では読み取りとダイアログの所有権を無効化し、ログアウトでは非永続状態を消去します。送信済み変更の排他は完了まで保持します。
- 確認を開いた時点のレコード・表示所有権・セッション・結果不明の世代を保存します。その確認を一度だけ送信します。確認済み結果で閉じ、送信後失敗は結果不明として再送しません。明示的な確認解除にも保存した世代を使います。
- ブラウザ相当の表示方式・重大度・状態・脆弱性分類・タスク・並べ替えだけを、上限付きの版管理JSONへ保存します。検索、ページ、資産範囲、選択、レポート本文、下書きは保存しません。不正・未対応設定では通信せず既定値に戻します。利用者入力のUnicodeを保持します。
- F3.2でネイティブ一覧・詳細・資産ナビゲーション、フィルター、独立ページ、6集計、継承元の読み取り専用表示を接続します。古い確認が新しい所有権で実行されないよう、先に状態境界を試験します。同じ検索の資産ツリー取得中に範囲・ページ変更で取得を取り消さない読み取り設計が必要です。

## 設計根拠

固定ソースはe75ae371ad777ffd1eecdd28d2781a6519b05591のfindings/page.tsxとfindings-table.tsxです。Lazywebのdesktop検索 `vulnerability findings table filters` は隣接する表・絞り込みのメタデータのみ（最大類似度0.442）で、外部画面画像は確認していません。視覚比較の証拠には使いません。取得した[data-table-filtersの設計資料](https://raw.githubusercontent.com/openstatusHQ/data-table-filters/main/skills/data-table-filters/SKILL.md)から、明示的なフィルター、安定した行識別、詳細パネル、未実装機能を有効にしない方針を参照します。React依存やインストール手順は導入しません。macOS SwiftUI Patternsのsplit/inspector資料から、明示的な選択と標準サーフェスを参照します。

## 検証順序

F3.1は未実装APIでREDを実行し、設定の上限・復元、編集・削除・結果不明確認、停止・リセットの所有権を実装します。古い確認、保留中変更、再送防止、Unicodeを制御試験し、レビュー、全回帰、署名ビルド、同一HEADのCIを確認します。その後F3.2の画面・表示・英日リソース・オフスクリーン試験へ進みます。実画面・キー操作・VoiceOverはMacの手動解除後に比較します。F4の使い捨てVMと固定版の変更比較、F5の出力・通信・レポート・系譜・再試験・深掘りも必須です。


F3.2は3表示、一覧・詳細の分割、明示的なフィルター、独立ページ、生UTF8を識別子とする反復処理の資産行、保存済み権限を使う確認操作を実装します。RootViewが認証ID別に画面状態を保持します。読み取りを排他に合わせて集約し、資産ツリー取得中の範囲・ページ変更でも取得を維持します。検索変更の無効化はF2に従い、集計は独立して更新します。Lazywebのissue-list検索9599af57-1296-4997-8ef8-aca8713d1a4aはaboard/linearの関連メタデータのみ（最大0.511）で、画像は確認していません。古い操作接続、Unicodeツリー、最大カウンター・ページ、取得中の変更、リセット、英日オフスクリーンを試験します。手動解除前に実画面・キー・AXを受入済みにはしません。
