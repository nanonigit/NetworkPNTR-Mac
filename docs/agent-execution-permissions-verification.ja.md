# エージェントごとの Web 検索と対話型シェルの検証

固定ブラウザ版と同じ対象のエージェントに両方のスイッチを表示します。Web 検索には保存済みの値を表示し、ゲスト全体の設定がオフか取得できない場合は操作できません。シェルには個別の保存値を使います。認証済みのエージェント設定 API に、表示されている変更項目だけを送ります。Web 検索の保存前に全体設定を読み直し、無効になっていた場合は検索の下書きだけを保存済みの値に戻します。

`e75ae371ad777ffd1eecdd28d2781a6519b05591` の使い捨て Docker 参照環境で、Web 検索を保存して対話型シェルをオフにしました。全体設定をオフにしてもエージェントの保存済み Web 検索の値は保持され、モデルの指定と実行上限にも影響しませんでした。検証は設定操作に限りました。表示条件は固定版を基準とし、全体設定の状態をスイッチの近くに表示する際には Lazyweb の Square と Workflowy の例も参考にしました。

署名済み Mac 版を、全体の Web 検索がオフの使い捨て VM に接続しました。Goals では両方の設定が非表示でした。Worker の Web 検索は操作できず、対話型シェルはオフにして保存できました。開き直すとシェルはオフで、モデルと実行上限は前の値と一致しました。Web 検索を有効にする保存は固定版 API と Swift の通信テストで確認しました。Mac のシステム設定画面は未移植です。

`swift test --filter AgentExecutionPermissionsTests` で送信項目、編集中の全体設定変更、設定取得の失敗、非表示項目を試験します。ツール紐付け、トリガー、認証後のブラウザ実画面比較は残っています。
