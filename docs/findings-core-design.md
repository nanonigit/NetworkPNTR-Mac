# F1 Findings finite contracts

Infrastructure/model/service only; Lazyweb is out of scope. Source references: server/dto.go FindingDTO/findingFromDB/findingDTOsForOwner; server/server.go findings/getFinding/patchFinding/deleteFinding; server/findings_groups.go shared filters/groups/tree; db/findings.go and finding_assets.go; web/src/lib/api.ts/types.ts plus findings page and detail. Fixed baseline e75ae371ad777ffd1eecdd28d2781a6519b05591.

FindingRecord preserves every scalar/list field needed by ordinary finding detail including standalone handle, task/node/provenance, optional report/evidence versions and assets. Raw severity/status/kind/string content remain forward-readable/literal; write enums are four severities and nine statuses. IDs are positive canonical Int64 decimal strings, not Double. Numeric task IDs in aggregate DTOs accept either exact integer JSON or decimal string. A per-task row can have a node id different from finding_id, inherited provenance or no mutation handle. Detail/global page responses must identify the requested standalone handle; context_task must not silently return an unrelated source.

FindingQuery shares filters for flat/grouped/tree reads. Serialize task filter as task_id; task selects an entirely different per-task bare-array endpoint and must never leak into global filters. All/no-filter sentinels are omitted, __unassigned__ is preserved. Only search q uses ECMAScript trim, matching the browser; class/asset labels remain literal input. Encode query metacharacters/plus once. Flat limit1...200, grouped1...100, positive page with safe offset; validate response page/page_size and no duplicate identities. Tree query has no asset_scope (navigation tree must not collapse when a subtree is selected). Scope applies to the right-hand flat list. Explicit null arrays normalize only with their required key present. The source tree3000 target is best effort: only endpoint/service levels are dropped, so valid other levels can exceed3000. Keep the4MiB transport bound, iterative linear forest validation, rawUTF8 unique keys, complete parents/no cycles and nonnegative counts; do not impose a false hard3000 cap.

FindingService accepts an injected authenticated transport, all finite successful statuses exactly200, bounded4MiB response/64KiB mutation body, pre/post-await cancellation, sanitized typed failures and no automatic retries. Detail supports optional context_task; global page and mutation responses use finding_id == id. Update takes a captured FindingRecord plus optional name/class/severity/status, refuses inherited/no-handle records, omits absent fields and permits explicit empty name/class. Browser-trim name/class before sending; verify returned fields against the server's subsequent Go TrimSpace semantics, with FEFF/NFD/NEL cases. Delete requires deleted:true and exact numeric id. Service errors are not definitive mutation outcomes: source patch applies fields sequentially, so state/controller later must distinguish unconfirmed writes and never auto replay after transport/5xx/malformed success. Known 4xx classification must consider this source non-atomicity rather than reuse the generic task rollback assumption.

F1 is Core only, remains pending in feature-map. Tests precede implementation with committed executed RED/GREEN, source checksum fixture and independent browser filter projection, exact literal/large-ID/missing-null/limits/ownership/provenance/unknown read/known write/cancellation/error cases. Reviewer and full regressions/build/signature/exact-head CI follow. No host command, VM policy, browser deployment, credentials or existing model state changes. Follow-up F2 state owns racing requests, per-group cursors/selection/uncertainty; F3 native en/ja UI uses Lazyweb then fixed browser controls; F4 actual fresh VM/independent reference and restart; F5 export/traffic/report/lineage/retest/deepen and actual UI/AX/keyboard after unlock. These phases do not narrow final parity.
