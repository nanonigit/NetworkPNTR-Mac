# 実モデル一覧 API の検証

署名済みプローブで、検証済みゲストと本番中継を使う DesktopRuntime を起動した。
4社のモデル一覧に固定の無効値を送信し、アプリがエラーとして扱うことを確認した。
プロファイルと会話が作成されず、VM と中継が停止することも確認した。
実キーや生成リクエストは使っていない。

初回に確認できたのは Groq の HTTP 401 のみで、再試験では4社とも応答未確定で
タイムアウトした。ホスト単体では OpenAI と Anthropic の 401、Gemini の 400 と
本文が届いたが、Gemini の終端は確定しなかった。その後の署名済み VM の追加計測では
OpenAI・Anthropic・Groq の 401 を確認し、Gemini は TLS 接続後に読み取りが中断された。

中継は使い捨ての接続で、HTTP の応答境界が確定した時点で完了するよう変更した。
Swift では固定長・チャンク終端・本文なしの応答と、末尾不足、同じ受信バッファの
余分なデータ、終了通知なしの切断を検証した。ローカルの TLS 試験ではサーバーが
接続を開いたままでも、クライアントが応答を完了して閉じることを確認した。
修正直後の署名済み VM 試験で、4社の応答ステータスがアプリ側に届いた。
[RFC 9112 の TLS 終了仕様](https://www.rfc-editor.org/rfc/rfc9112.html#section-9.8)

今回確認したのは外部 API の拒否応答。実キーでの一覧取得、生成、ゲスト内ツール操作は
各社で別途確認が必要。実画面と固定ブラウザ版の比較も継続する。
一般 Web アクセスはこの中継の対象外。

最終再試験では4社とも外部の応答ステータスが確定しなかった。4社から応答を得た
試験で疎通を確認できたが、実接続の安定性は未確認。Gemini は VM で HTTP 400 を
確認し、別のホスト試験では API キーに関する引数エラーを確認した。
最終 VM 試験では同じエラー分類を独立に確認できなかった。

## 署名済み配布プレビューのモデル一覧操作

使い捨ての検証用ディスクで署名済み配布アプリを Launch Services から起動した。
利用者の許可を得て利用条件に同意し、通常の画面からログインした。
「新規」から4社のプリセットを開き、意図的に無効な値でモデル一覧を取得すると、
4社とも日本語のエラーが表示された。各クリックから8秒以内に配布アプリ本体のTCP
ソケットを1件観測し、各ソケットに初回判定あり・ドロップフラグなしのサンプルがあった。
ここで確認したのはソケットの状態で、配布アプリの画面からは外部のHTTPステータスを取得できない。

固定ブラウザ版のソースでは、一覧取得の失敗をトーストで表示する。Mac版は日本語の
エラーを設定シート内に表示する。今回はブラウザの実画面比較が残っている。
すべての入力シートを閉じた後、プロファイル一覧は空だった。ログアウトで検証用の
キーチェーンセッションを消去し、仮想NICと共有が0の状態でVMを正常停止した。
実キーでの一覧取得と生成は別途確認する。
