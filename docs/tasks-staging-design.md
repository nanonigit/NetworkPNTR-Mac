# T5 — task draft upload transport

As a task author I can upload explicitly selected files before a task exists, then reference their guest paths in the task description. Pinned tasks/page.tsx uses one draft UUID and POST /api/chat/upload?scope=staging&id=<draft>, repeated multipart field file. Server chatupload.go limits the whole request to128MiB, returns name/path/size/abs, renames collisions and saves drafts/<id>/uploads. Native guest data root is fixed /state/app/data. Creation is disabled while uploading in the reference. A failure may leave partial files; never retry automatically or claim rollback.

This phase provides the real finite transport prerequisite, preserving existing session upload behavior. Add a separate staging multipart capability accepting UUID (no arbitrary scope/path/query), shared private upload worker and shared AuthenticationSession revision/progress lifecycle. Keep typed feature protocol free of bearer injection. Keep whole-request multipart bound, file stamps, cancellation, full-duplex socket ownership and timeout untouched. No general host access/RPC, guest NIC, agent command, new HTTP server, download or guest-folder mount.

Decode directly from bounded raw200JSON with an explicit draft context. Each attachment must use the existing safe name/size validation, exact UTF8 uploads/name and exact /state/app/data/drafts/<lowercase UUID>/uploads/name. Require a nonempty complete result matching selected file count; reject duplicate byte paths, missing/foreign abs, malformed/oversized responses and all non200 statuses. Do not normalize Unicode or treat Linux paths as host file URLs. Preserve collision-adjusted server names; client cannot require selected names equal saved names. Return metadata only after auth revision/cancellation validation. Uncertain errors remain errors; no retry/cleanup implied.

TDD covers route/auth framing, UTF8/BOM/NFC/NFD, wrong-context/traversal/line-control paths, empty/partial/duplicate/status/size bounds, unauthorized/stale replies/cancellation/progress. Use simulated transport and temporary regular files, no actual guest request for these tests. Shared auth and multipart regression must remain green. Review, full tests, signed build and bilingual evidence follow. Creation model stable draft ownership, UI picker/progress/busy controls, manifest localization and actual browser/native/VM upload comparison remain required next phases. Do not mark Tasks or staging workflow accepted from this transport alone. Infrastructure has no UI change; Lazyweb out of scope.
