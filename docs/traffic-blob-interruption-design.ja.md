# 元データの転送途中キャンセル検証

要件: ゲストからの元データ転送中に本文の一部が実際に保存され、所有する開いたソケットを中断し、保存先を公開せず、非公開ステージングを清掃することを証明する。全21機能・ブラウザ比較・VM隔離・provider／harness／kernel／releaseの目標を維持する。完成レシートや認証失効だけでは転送中断の証拠にしない。

固定262401バイトはポーリング前に転送完了し得るため、DEBUG限定で正確なmanifest・operationに結び付いた診断用停止を最初のステージング追記直後に設ける。detached転送タスク内で選択したblob検証だけに明示的なTaskLocalを適用し、Finding保存やReleaseに適用しない。条件変数で読み取りを最大10秒停止する。キャンセルで実ソケットを先にshutdownし、開いていたかを記録して読み取りを再開する。成功には単一の一致する操作、0<保存済みbytes<期待長、開いたソケットの中断成功を要求する。重複、ID生バイト／side／hash／長さ不一致、本文前のキャンセル、タイムアウト、完了済みソケットは無効。証人には資格情報や本文を出さない。これは制御した転送途中キャンセルであり、自然発生の通信障害やタイミング依存キャンセルの証拠ではない。

CLIで認証付き元データ保存を開始し、部分保存を非同期で待つ。元の認証リビジョンと呼出元タスクを確認し、子タスクをキャンセルする。CancellationError・正確な証人・保存先とステージングの不在を要求し、その後通常保存を実施してVM／バックエンドの利用継続を確認する。従来の停止・再起動検証と固定参照結果を維持する。使い捨て候補だけを使用し通常プロファイルは変更しない。保存UIは未完。内部処理／CLIのためLazyweb対象外。

TDD: 証人と実ソケット寿命、ID生バイト／side／hash／長さ不一致、重複、本文前キャンセル、停止・再開と期限、完了ソケットの拒否、スコープ分離。CLI前に契約試験を追加する。対象・全SwiftとPython、実VZの2回起動、アプリ厳密署名、Release全シンボル／文字列除外を確認し、ハッシュと日英RCA／検証記録を残す。既存wire／file／authの試験を維持し、依存は増やさない。

レビュー条件: 単調時刻の停止期限を条件ロック下で保持し、キャンセル記録側でも検査する。待機側が期限切れから復帰する検査だけに依存しない。メタデータ待機後にMainActorで検証設定の空きを一度に取得し、その直前にVMの稼働を再検査する。既存の検証設定を上書きしないことを純粋な取得処理の試験に残す。
