エージェント応答はキー・日英の表示名・有効状態だけを返す。タスク応答は文字列ID、状態、一時停止・待機状態、Int64の入出力トークン数を返す。プロトコル変換でJavaScriptの数値へ変換して精度を失わせない。プロンプト、コマンド出力、認証情報、プロバイダー設定は応答に含めない。トークン数は既存タスクの使用量であり、新規モデル呼び出しではない。

権限はアプリ内でクライアントの許可後に発行する。アプリ再起動で消えるメモリ内の権限とし、ログイン世代とVM世代の両方に結び付ける。発行前と応答後に確認し、失効した応答を返さない。アカウント認証情報は既存の認証付きクライアント内に保持する。IPC接続を認証してから内部の権限へ対応付け、権限発行をMCPツールとして公開しない。初期上限は128権限、各権限で許可するタスクは1,000件。IPCはフレーム上限、相手UIDと接続権限の確認、切断時キャンセル、ソケット解放前の処理終了を実装した。ヘルパーは入力行64KiB、待機メッセージ32件・未応答ID8件に制限し、部分出力に失敗した通信は終了する。アプリ内のクライアント識別・許可画面と製品起動連携は後続ゲート。

タスク作成・開始・再開・停止、スキル、検出結果、隔離ツール実行はMCPでは未実装。既存の作成・再開APIは内部エージェントの推論を起動し得るため、外部AIモードの実行所有者をバックエンド全体へ実装してから公開する。NetworkPNTRエージェントへの委任は別名のツールでモデル設定を明示し、使用量も分ける。破壊的操作、秘密・個人情報の記録、mockやセッション置換、ドメイン拡張にはAPI Reconの個別許可条件を保つ。一般の接続許可をそれらの許可とは扱わない。

プロトコル変換には[公式Swift SDK](https://github.com/modelcontextprotocol/swift-sdk/tree/0.12.1)を利用し、依存関係を確認・固定してから導入する。ローカル接続は[公式トランスポート仕様](https://modelcontextprotocol.io/specification/latest/basic/transports)のstdio方式とする。

開発用確認は `swift test --disable-automatic-resolution --filter 'MCPIPC|BoundedStdio'`。合成サービスを用いた実Unixソケット・ヘルパープロセス試験で、2^53より大きいタスクIDとトークン数の保持も確認する。ヘルパーのコマンドは `NetworkPNTRMCP --connection-file PRIVATE_CONNECTION_FILE`。接続ファイルはAI接続画面で利用者が明示的に許可した後に発行する。エージェント参照・取り消しの実機確認は成功し、残りの受入条件は後述する。ヘルパーは単一JSON-RPCメッセージを扱い、明示的null・不正ID・バッチを拒否し、SDKの処理開始前に未応答ID数を制限する。アプリ側の有限ディスパッチャーが公式SDKのメッセージ型を利用し、初期化前の要求をエラーで拒否して枠を解放する。SDKのサーバー受信ループは、キャンセル応答を省略した後の完了通知APIがないため利用しない。呼び出し元が切断すると参照処理をキャンセルし、終了後に次の接続を処理する。

要求の寿命は13回の連続キャンセル、要求直後のキャンセル、8件実行中の9件目の拒否、その後のキャンセルと通常参照への復帰を試験する。過負荷の要求を制御通知の前で待機させない。応答を省略するキャンセルでも、処理終了後に要求ごとのUUIDで枠を解放し、古い後処理で新しい要求を失効させない。IPCと標準入力の待機はSwiftの実行スレッドを占有しない。要求IDは[基本仕様](https://modelcontextprotocol.io/specification/2025-06-18/basic)に従い、同一セッションで再利用しない。

ソケットの接続待ち枠が埋まった場合は、要求を送る前の接続確立だけを、同じ期限内で新しい記述子を使って再試行する。送信済みの参照は再実行しない。試験では200件の未完了接続を閉じ、その後の許可済みタスク参照を確認する。一時的な接続中断で待ち受けを終了しない。既存Ollama試験では、実際の非同期停止コールバックを待ってから停止の観測を判定する。

## MCPの二方向

ユーザー確認済みの目標にはサーバー・クライアントの両方を含む。サーバーは「外部AI→同梱ヘルパー→アプリの許可管理→専用VM」。クライアントは「アプリ・ゲスト側エージェント→許可された外部MCPサーバー」。`MCPClientStore`は前者の接続元を管理する名称であり、後者のネイティブ機能の完成を意味しない。

固定バックエンドの外部サーバー情報とエージェント割り当てを読むコードは存在するが、外部接続・ツール実行の証拠とは区別する。`feature-map.json`の`/system/mcp`のMac画面は未完。接続登録・編集・削除、方式別設定、ツール一覧・更新、エラー、エージェント割り当てを移植する。stdioコマンドはmacOSで実行せず専用VM内で動かし、リモート通信は専用の制限付き・許可済み経路で扱う。独立した使い捨てMCPサーバーで実接続・一覧・呼び出し・切断、タイムアウト・キャンセル、不正応答、失効、再起動保存を検証し、固定ブラウザと比較する。情報参照のみの試験でクライアントの完成やサーバー側のタスク書き込みの完了とは扱わない。
