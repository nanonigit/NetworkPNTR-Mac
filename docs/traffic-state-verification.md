# Traffic window state checkpoint

TR2 state is implemented; no Traffic screen, real deletion, polling task or agent action is exposed. The full standalone workflow remains in traffic-workflow-design.md. TrafficService internally separates validation/preparation from execution so each confirmation owns immutable method/path/body bytes; public apply remains compatible and its prior finite tests still pass.

TrafficStore owns applied query, last-good page/hosts/settings/detail, byte-distinct ordered selections, selection revisions, preview and confirmation UUIDs. Filters/pages preserve cross-page selections/preview, unchanged applied queries do not rotate owner, changed queries invalidate old generations, and stale/failed snapshots cannot enable new row selections. Batch select/deselect preserves off-page IDs and NFC/NFD identities. Pending confirmations prevent replacement/draft mutation/new reads; substring scope contains only the host filter, exact scope captures selected host bytes, and a consumed ID cannot replay. Poll eligibility is page0-only; this phase starts no polling.

Post-dispatch errors/departure retain uncertainty without retry. A complete fresh available page+hosts+settings read under the current owner/unknown revision is required before explicit acknowledgment; partial failures, unavailable index, stale owner or wrong revision cannot unlock writes. Reads never acknowledge implicitly. Reset/stop clear raw applied filters, selections, preview and reads; reset also removes the public unknown scope while preserving a generic marker and any unsettled write until completion. Validated in-flight request bytes remain private until settlement. This marker is scoped to the store, not a durable process-restart or cross-window journal.

Synchronous Observation stop/reset is queued and pre-dispatch tickets revoked. Reset wins teardown, repeat stop is idempotent, scoped old-owner teardown cannot stop a new owner, and resume during publication cannot resurrect data. Late page/detail results cannot replace newer data. A stopped/reset held write cannot publish an old receipt. Success/error paths release the busy gate and then check lifecycle/owner/cancellation before returning; departure during release returns discarded. Once a verified receipt is committed and the write is released, departure does not invent an unknown server outcome. Physical socket-loss, VM effects and whole-app multiwindow recovery remain separate gates.
