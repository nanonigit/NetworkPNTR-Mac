## Requirements

C1. Preserve new-conversation draft, agent/profile selection, agent filter, pinned conversations, collapsible agent groups, live indicators, inline rename, single/batch delete confirmations and partial batch failures. Browser list pages show 100 conversations at a time; the server list itself is not paginated. Preserve selected transcript across transient list errors.
C2. Render all Activity kinds: user/text/thinking/result, paired tool input/output, errors, usage, intent/round, LLM switches/failovers and intercept approval requests. Load full details on demand, preserve markdown/code/attachments, todo state, token/duration summaries and source/focus links. An unknown event must remain visible as an unsupported event rather than vanish.
C3. History loads 200 events per page; live updates merge by seq, incoming events replace prior same-seq records, sorted ascending. Main conversation uses nonoverlapping 1-second delta polling while running and a nonoverlapping 2-second list poll. Observe a final delta before considering a turn finished. Selection changes/logout/VM stop cancel obsolete work; stale callbacks cannot overwrite the newly selected conversation.
C4. Preserve send-mode preference (Enter or Ctrl/Cmd+Enter), Shift+Enter newline, IME composition, draft/attachment restoration after failed send, disabled duplicate-send/stop actions, sticky-bottom only while the user is already at the bottom, and scroll-to-older-history position. Draft attachment selection creates a real conversation before upload; retain the typed draft through that handoff.
C5. File selection uploads only explicit user-selected bytes into the private guest. No host directory shares, shell calls, host paths in model content or arbitrary host RPC. Upstream caps each multipart upload request at 128 MiB. Current 4 MiB JSON transport cannot establish upload parity; add a separate bounded streaming multipart path, cancellation, truncation/size checks and cleanup, retaining ordinary JSON bounds. Attachment guest paths are display/data, never host execution targets.
C6. Preserve @ record citations, /btw side questions (history, idempotent client request IDs, cancellation, retry/draft restoration, clear), snapshot/model/context state, and inline approval/current-status/history/execution navigation. Main messages poll, but side questions use SSE plus 2-second history reconciliation; existing finite JSON transport is insufficient for that stream. Do not silently substitute an inert button.
C7. Credentials stay private to guest/Keychain and never enter logs. Initial VM remains zero-NIC/zero-share. An actual cloud turn requires separately reviewed outbound policy/transport. Local fixture providers, if used, run only inside the private guest, without external targets. Fixture success is not cloud-provider acceptance.

## Native structure and data flow

Keep existing global Features/System navigation. Inside Chat, use a resizable conversation rail and transcript/composer column, preserving browser grouping/order and a stable bottom composer. Use existing native typography, colors, controls and accessible names; avoid introducing a second global navigation or decorative chat dashboard. At minimum window width, both conversation selection and composer remain usable; resizing/scrolling must not obscure actions.

Typed ChatConversation/ChatActivity/ChatAttachment/ChatHistoryPage/ChatDelta/ChatBatchResult values map exact wire keys and nullable fields. ChatService uses the existing authenticated BackendJSONClient for finite routes. A main-actor ChatStore owns selection/drafts/list/history, request epochs and cancellation. Pure functions handle merge/grouping/pinning/paging; presentation never fabricates running state. Add separate bounded upload/SSE transport interfaces before advanced controls depend on them. Rendering untrusted markdown cannot execute HTML/scripts or commands; external navigation follows explicit user action.

Routes: GET/POST /api/conversations; PATCH/DELETE /api/conversations/{id}; POST /api/conversations/delete/batch; PATCH /api/conversations/{id}/profile; GET/POST /api/conversations/{id}/messages; GET /api/conversations/{id}/messages/{seq}; POST /api/conversations/{id}/stop. History uses before/limit; delta uses since. Support /api/chat/upload?scope=session&id=conv-ID, /api/chat/mentions, conversation side-questions and /api/side-questions/{id}/events and /cancel. Review exact side/approval/mention schemas before implementing those stages.

## Build order and phase gates

1. C0 baseline: capture read-only empty browser state (done); construct deterministic populated fixtures and a control/event matrix (pending). Keep feature-map status pending.
2. C1 service/model tests first: nullable profile/pin fields, all event kinds, unknown events, query/body encoding, auth errors without raw response disclosure, merge duplicates/out-of-order/cursor boundaries, batch partial failure and nonoverlapping/stale-response cancellation. Then implement finite services/store.
3. C2 actual guest/reference: create/rename/pin/profile/change/delete, 201+ event history, overlapping deltas, running-to-final transition and malformed/missing records on identical disposable data. Use the signed app against the selected source kernel. No user browser mutation.
4. C3 native core UI: implement rail/transcript/composer and externally compare the same fixtures with browser success/empty/loading/error/validation/persistence/restart/keyboard states. Draft creation/send failures and cancel/stop races are mandatory. No feature acceptance from API tests alone.
5. C4 advanced parity: bounded uploads at/over limits and interrupted transfer; citations; SSE UTF-8/chunk boundaries/reconnect/cancel/logout; side-question idempotent retry, clear/history; approval decisions/status/error/source focus; markdown/code/tool details, todo/tokens. Review transport/security before real cloud calls.
6. C5 controlled cloud and product gates: actual chosen cloud provider, egress rejection, no host execution, long history/large attachments, Japanese IME, VoiceOver/focus, light/dark, resize, stop/quit/relaunch. Match browser controls and preserve documented failure behavior. All unmet cases remain explicit release blockers.

This plan does not remove the pending runtime reliability, distribution/license/signing or remaining product-feature gates.
