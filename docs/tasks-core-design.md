# Native tasks — T1 finite API design

Reference: ARTEX `e75ae371ad777ffd1eecdd28d2781a6519b05591`; server/dto.go, server.go list/create/get/control, task_metadata.go, task_control.go, server_mgmt.go, web/src/lib/api.ts and function/tasks/page.tsx.

Goal remains full task-list/detail parity. T1 implements finite list/detail/create/metadata/pause-resume/batch-control/delete contracts through the existing authenticated transport. It does not pass Tasks UI, runtime or whole-feature acceptance. Categories/templates/archives/attachments/LLM chains/graphs/goals/constraints/main-agent chat/SSE/detail tabs must follow, with native/browser comparison before acceptance. Creation/resume/active-task APIs can start agents; tests must not invoke them against user state or run agents on macOS. Do not call active-task selection as a read.

TaskRecord preserves the complete TaskDTO, nullable/omitted optional fields, exact string task IDs, Int64 IDs/counters, unknown status/custom text, ordered source/profile IDs. Canonical positive decimal path IDs prevent query/path injection; duplicate list IDs, mismatched mutation owners, malformed envelopes/counters are rejected. UI-local validation is typed and bilingual, with no arbitrary server error body in errors.

Create draft covers every current frontend body field: name/category, description/goal, ordered profile/source/company IDs, timeout/heartbeat seconds, seed-first-intent, coverage, and interception rules. Browser ECMAScript trim and required description/goal are retained; source limit8, unique positive profiles, unique canonical sources, company positive IDs with first-seen dedup/max32. Empty rule patterns are filtered as in the browser; nonempty rule syntax remains the backend's validation responsibility. No silent option drop. Default heartbeat600matches the creation form; explicit0 remains a supported backend default sentinel. No implicit active selection or auto-retry after mutation.

Metadata requires at least name or pinned; name uses scalar/rune1...200limit after browser trimming. Controls use closed pause/resume enum. Batch canonicalizes/deduplicates first-seen IDs,1...100; validate result owner count/order and success status. Per-item failures remain false without retaining arbitrary error strings. Delete options default allfalse and encode all5flags; result preserves all6cleanup measures and a warning-presence flag. HTTP200with cleanup warning is confirmed deletion, not retryable failure. Raw cleanup-warning text is not retained/displayed. Response identity/count violations are errors; UI/state layer must not retry unconfirmed mutations automatically.

Tests: pinned-shape populated list/detail, nullable collections, large IDs, every create option/tri-state omission, metadata rune boundaries, canonical/injection IDs and no-request invalid inputs, partial batch ownership, delete counts/post-commit warnings, unexpected HTTP/malformed/duplicate/mismatched responses, unknown content preserved and error-body sanitization. Unit transport is scripted (not browser/VM parity). Follow TDD RED/GREEN, full regression, focused coverage, review and signed build. Real disposable reference+VM fixture comparison and UI/state/cancel/persistence tests remain separate gates. No Lazyweb for this backend-only stage.
