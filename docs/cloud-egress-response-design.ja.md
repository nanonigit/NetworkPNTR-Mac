# クラウド中継のHTTP応答

1件のプロバイダー応答を、応答情報、復号した本文、完了のイベントに変換する。フレーミングの検査と正常なTLS終了を確認してから完了を送る。本文の一部は先に届くため、ゲスト側は完了イベントがなければ読み取りエラーとして扱う。

Content-Length、HTTP/1.1のチャンク、TLSの正常終了で区切る本文を扱う。途中の情報応答は件数を制限して読み飛ばす。リダイレクト、プロトコル切替、曖昧な本文長、未対応の圧縮、途中切断、応答後の余分なデータを拒否する。ゲストに渡す応答情報はステータスと正規化したJSONまたはイベントストリーム種別に限り、任意のヘッダーやトレーラーは破棄する。ヘッダー部32 KiB、トレーラー8 KiB、チャンク行1 KiB、復号した本文16 MiBを上限とする。既存のTLS通信は受信バイト全体を別途16 MiBに制限する。本文は蓄積せずバイト単位で転送する。

合成チャンク応答の全分割点、途中切断、不正なメタデータ、上限、転送先の失敗を試験する。TLSワーカーと同じ入口を使う。イベントのvsock転送とVM起動停止との連動は次段階で行う。[HTTP/1.1のフレーミング仕様](https://www.rfc-editor.org/rfc/rfc9112.html)
