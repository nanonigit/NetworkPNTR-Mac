# 管理対象クラウドのリダイレクト境界

CP3ではVMの外向き通信と、キーを付けるHTTPクライアントの両方で接続先を制御する。外向き通信を有効にする前に、モデル一覧とモデル実行が、リダイレクト後も元のHTTPオリジンに留まるようにする。スキーム、ホスト名、実効ポートで比較し、変更やURLのユーザー情報を拒否する。同じオリジンでのリダイレクトと従来の10要求上限は維持する。拒否した場合は元のHTTPステータスを返す。3xx応答の本文は診断用の記録層に届く前に破棄し、拒否された接続先と不正なLocationを取り除く。通常のエラー本文と正常なストリームは維持する。

実Goクライアントを2台のループバックHTTPサーバーで試験する。同一ホストでも別ポートへの307では、モデル一覧と実行の両方で転送先要求が0件であることを要求する。同じオリジンの相対リダイレクトは認証付きで成功させる。ホスト名、HTTPSダウングレード、既定ポート、URLユーザー情報も検査する。パッチは管理用ソースの展開先へ適用する。ここで確認するのはキー付きリダイレクトの境界で、VM全体の送信先制御と実サービス確認は別の条件とする。
