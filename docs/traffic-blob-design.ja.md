# 元blobの構造化保存拡張

通信画面／21機能／VM／ブラウザ／4社／ハーネス／リリースの目標を維持。blob原本保存は固定ブラウザ画面にない追加機能。HTTP本文に同じ文字列を含められるため、表示中の `@blob` を正規の保存情報と扱わず、生の通信本文は変更しない。今回はbackend／CLIなのでLazyweb範囲外。保存UIを作る前にはLazywebを使う。

正確なe75ae371を基に独立管理するbackend拡張とし、比較用checkoutを保持。新しい認証付きGET /api/traffic/blob-metadata?id=OPAQUE&side=request|responseで、SQLite上のその通信・その側に対応するblobだけid／side／小文字64桁hash／Int64 sizeを返す。exchange_bodiesとexchangesの構造化情報を読み、側、hash、非負長、実ファイル長を確認。構造化blob情報のないinline／旧記録、行／ファイル不在、長さ不一致は利用不可。HTTPヘッダーや本文の文字列、ゲストファイル名、任意URLから生成しない。データは既存の固定GET /api/traffic/blobから流し、ホストの非公開一時保存で長さ／SHA256と現在の認証／VM／画面所有権を確認してから原子的に公開する。

まず固定Goコンパイラーとgo.mod／go.sum検証で、再現可能なソースoverlayのメタデータ処理をテスト・実装。Goのコンパイル／テストはコンテナー内だけで、macOSでGo／エージェントコマンドを動かさない。overlay／経路追加／builder／ソース・イメージ・手順ハッシュをブラウザ基準と別管理。その後handler／認証、ネイティブ解析、既存の検証済み保存基盤再利用、英日保存操作、実バイナリー出力比較へ進む。対応ゲストができるまで画面に未動作の操作を出さない。架空の検出結果や隠れた紐付け変更で保存情報を作らない。

TDDは要求／応答の独立blob、正しいhash／長さ／側／ID、Unicode ID、inlineの偽marker無視、不正側／ID、削除済みblob、不整合長／関連、閉じたDB。HTTP境界では汎用エラーにする。hashは内容の完全性とblob識別であり、リモート由来の真正性ではない。元通信の削除後は未紐付けblobが使えないことがあり、既存の紐付け済みsnapshot保存は独立して維持する。

構造化handler、ソース／イメージの来歴、VM転送、認証／中断／保存制限、実出力バイト、現画面の保存操作と実UI比較まで完了扱いにしない。昇格条件が通るまで通常ゲストとインストール済みアプリを保持し、Actions枠未確認の間はskip ciを維持。
