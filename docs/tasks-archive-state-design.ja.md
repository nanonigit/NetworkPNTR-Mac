# T14 アーカイブ状態設計

固定e75ae371のTaskArchivesPanelを参照する。初期20件、検索・状態変更で1ページへ戻る。選択はページ内、処理中の行は選択不可。2秒ごとの取得と、受付済み復元IDの詳細404によるライブ一覧更新を再現する。件数と一覧は別スナップショット。検索文字列はUnicode正規化せず保持し、空白のトリムは後続UIの明示的送信方針で決める。操作と画面は引き続き実装が必要。

TaskArchiveStoreで一覧・詳細のTaskReadState、フィルタ、表示・セッション・読み取り・更新ループの所有権を管理する。フィルタ変更で古いページ・選択・詳細を破棄し、進行中の読み取りを無効化する。同条件の失敗は古い値と選択を保持するが選択を再照合しない。成功時のみ現在ページの処理中以外のIDへ選択を絞る。不明状態は表示・選択可能だが操作可否は型付きの判定に従う。

一覧→選択詳細→復元待機ID詳細を直列取得した後に2秒待機する。重複周期を作らず各中断点で所有権とキャンセルを確認する。停止は値・フィルタ・復元受付を保持し古い読み取りとループを無効化する。認証リセットはセッションも切り替え全消去する。状態実装のみで画面変更はないためLazywebは実装範囲外。画面準備の参照検索ではMonodesk完了タスク表、Dockタスク表、Height一覧のメタデータを取得した。実画面の受け入れやレポート生成の完了とは扱わない。導入済みLazywebは0.15.14。

observeAcceptedRestoreはrestore_queuedの型付き応答と捕捉済みセッション所有者を受け、アーカイブID・タスクID・固有受付トークンを保持する。書き込みを実行せず202を完了としない。一致する待機IDの詳細404だけで受付を外し、再照合リビジョンを変更する。後続のライブ一覧更新用通知であり、永続的な復元成功の証明にはVM・ブラウザ比較が必要。無関係な404では変更しない。200のタスクID不一致は失敗とし401/403はその周期の照合を止める。エラーは安全な型だけ保持する。同じIDの新受付を古い404で消してはならない。ホストパス・コマンド・通信・VM既定値は変更しない。

試験は既定値・検索境界・ページ内選択、古い一覧と詳細、失敗時の値保持、受付の所有者・状態・ID、フィルタから消える場合と404の区別、非404・認証失敗、受付差し替え、停止・再開・リセット、2秒周期と重複防止、各中断点のキャンセル。レビュー後に署名ビルドと全回帰を行う。実変更・APIキー・スクリーンショットは不要。ネイティブ画面・一括操作・共通ゲート・実ジョブ・言語・AX・キーボード・ブラウザ比較は未完了。
