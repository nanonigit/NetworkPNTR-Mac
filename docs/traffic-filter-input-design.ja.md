# 通信履歴フィルター入力契約（TR3準備）

画面実装前の入力処理を追加する。TR3–TR5の全操作、証跡への紐付け、原本保存、定期更新、実ブラウザ／ネイティブ比較は維持する。この段階では画面・通信を追加しない。入力処理だけなのでLazywebは対象外。画面設計時には引き続き使用する。

固定版e75ae371の6つのテキスト欄は独立した300msタイマー、ECMAScript trim、即時反映のmethod/status/size/sortを使い、適用条件が変わったときだけ先頭ページへ戻る。各欄のチケットは表示スコープ、更新番号、UTF8原文を保持する。他欄の編集では無効化せず、表示し直しや同じ文字への再入力では古いチケットを拒否する。NFC/NFDはバイトで区別し、検索下書きを設定に保存しない。

処理はコピーした下書きとクエリーを提案し、元の状態を変更しない。呼出側は同じ表示所有権の下でTrafficStoreの検証／configureを同期実行し、成功した場合だけ提案を採用する。拒否された検索を適用済みにしない。クエリー長・エンコード後の長さの検証はTrafficStoreが担う。タイマー実行、キャンセル、Observation再入、確認画面／所有権のガード、定期更新は今後の画面モデルの責務であり、この段階の成果には含めない。

応答サイズは正規化した入力文字列を適用済みの識別に使う。1→01では数値が同じでも先頭ページへ戻る。数値化は固定Linux64版のGo Atoiと>=0の条件に合わせ、Int64内のASCII符号付き10進整数のみ採用し、それ以外は範囲指定なしとする。逆転した非負範囲は保持する。検索の意味を維持するが、無視される数値文字列のHTTP表現まで同一にはしない。詳細検索リセットは4欄とstatusを即時解除し、host/query/method/size/sortを保持する。解除前の詳細欄チケットは拒否する。同じソート列を押すと昇降順を切り替え、新しい列は降順から始める。ページサイズは25/50/100/200。

先に独立／古い／再入力／表示更新チケット、trimとUnicode原文、無変更時の履歴ページ、数値境界／無視、提案の不採用、詳細検索解除、即時操作とソートを試験する。その後レビューと限定／全体試験を行う。実画面と残りの操作が揃うまでTR3は未完了のままにする。
