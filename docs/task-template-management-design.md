# T8 — native task templates

Fixed task-template-controls.tsx owns a manager with list/new and five saved fields: name/description/goal/category_id/intercept_rules. Save-as takes description/goal/category/rules from creation, starts with blank name and no selected template, and does not create a task. CreatePOST201, complete editPATCH200 (explicit null category and empty rules clear them), deleteDELETE200 with exact deleted ID. Browser callbacks update the picker catalog but never silently reapply changed content to the task draft. Deleting the selected template clears picker selection only. Confirmed applying a template resets the task upload count (the source onApply explicitly does so); cancel keeps it. Preserve staged files/draft UUID and ordinary task fields.

Core service uses finite numeric IDs, the existing direct-byte option decoder,4MiB response bound and exact success statuses/owners. Input is the same five fields: JS trim outer strings/patterns, omit empty patterns, preserve rule order/flags/notes and raw Unicode internally. Validate positive category, name120Unicode scalars/text16000 according to server normalized whitespace,512KiB encoded request. Do not normalize NFC/NFD or drop BOM inside content. Server is authoritative for case/whitespace uniqueness;409 gets a safe localized conflict. Invalid/partial/mismatched replies cannot confirm mutation. No task/agent/selection side effects, auto retries, host execution, network policy or guest artifact changes.

Window-owned manager retains immutable context/editor/decision IDs. Fields and callbacks capture both context and editor generation; switching items/new cannot accept queued edits for the old editor. Confirm switching/new when unsaved edits exist; delete uses immutable selected template snapshot/decision ID. One mutation gate spans reset and releases only on completion; old-session results are discarded. Known validation/4xx rejection preserves editable draft; transport/cancellation/unexpected success/5xx leaves result uncertain, blocks repeat and retains draft across reopen. Explicit local-discard/reconcile copy says server effects may already exist; never infer rollback. Confirmed receipts update the local list/creation picker even if refresh fails, without overwriting an unrelated current draft. Read replies use context/tickets and cannot erase later work. Ordinary close preserves local edits; reset discards session state. Parent disappearance closes manager context and cancels stale reads without releasing an in-flight mutation gate.

Production injects template service into the retained creation owner. Manager opens as a child sheet from Manage/Save as controls; disable opening/creation/template apply while an editor/modal/picker/upload/mutation conflict exists. Closing/reopen keeps state as documented; save-as is an explicit fresh seed and uses dirty-discard confirmation when needed. Edit fields: name/description/goal/category and stable UUID rule rows, all7kinds/actions. Reuse existing task rule label catalog; do not tie view identity to locale. Native list/search plus editor use browser hierarchy, with explicit create/save/delete/close and unsaved-change/delete confirmation. No unnecessary per-keystroke requests. Existing templates may contain user Chinese/Korean text and must remain literal.
