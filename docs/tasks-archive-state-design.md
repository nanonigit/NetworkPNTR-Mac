# T14 archive state design

Pinned source e75ae371, TaskArchivesPanel: page20, query/state reset page1, page-local selection, processing rows not selectable, every2sec reload, accepted restore IDs queried independently until detail404 triggers onChanged. Counts/list are separate snapshots. Preserve literal query bytes rather than Unicode normalization; whitespace-only trimming is deferred to explicit UI submission policy. Native writes and UI remain required next phases.

TaskArchiveStore owns list/detail TaskReadState, filter and view/session/read/poll tickets. A filter change drops the previous page and selection immediately, invalidates in-flight list and detail results, and resets detail. Same-filter refresh failures keep stale values and selection but cannot reconcile it. Successful refresh intersects selection with current nonprocessing IDs. Unknown states remain readable/selectable as browser, but action eligibility remains typed.

Sequential read cycles avoid overlap, await list, selected detail, and pending receipt details, then sleep two seconds. All continuations check operation ticket and cancellation. stop invalidates reads and polling while retaining filter, stale values and pending restore receipts; reset additionally rotates session and clears all state. Manual refresh and duplicate run do not create concurrent cycles. This state-only phase has no UI layout changes; Lazyweb is out of scope for implementation. Preparatory Lazyweb reference search desktop archived tasks table returned Monodesk completed-task table (search/filter/pagination), Dock task table, Height task list; these are research metadata only, no native visual acceptance or hosted report claimed. observeAcceptedRestore takes a typed restore_queued receipt and captured session owner, retains archiveID/taskID plus unique receipt token. Never creates a write or claims a202 is completion. A matching pending detail404 removes that receipt and changes a reconciliation revision, prompting future live-task reload. Treat as archive removed after accepted restore, not proof of durable task restoration: actual VM/browser durability remains required. Other404s do nothing;200 for a different task identity fails closed;401/403 stops reconciliation for this cycle. Distinct list/detail/reconciliation errors retain safe typed identity only. A replaced receipt cannot be consumed by an older404. No host paths/commands/network/VM defaults change.
