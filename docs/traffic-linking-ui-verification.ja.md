# 通信紐付けUI統合の検証

通信画面に、バイト識別によるページ横断選択、250ms／1ページ目／20件の検出結果検索、Rootに保持する紐付け状態、英日ネイティブダイアログ、結果不明時の明示確認を接続した。Rootは同じ認証クライアントから各サービスを作る。候補／検索／ダイアログ／クエリー／選択版／要求の各識別で操作を保護し、coreの実行中通知後にも送信前に親の有効性を確認する。確認済み成功時のみ元と一致する選択を解除し、変更された新しい選択は完了通知とともに保持する。紐付け中／結果不明時は削除と新規紐付けを禁止。閉じる／リセットで生の編集情報を消し、既存の非公開・メモリー限定の復旧ハンドルを保持する。

固定ブラウザLinkTrafficDialogを参照：検索変更で1ページ目、20件、250ms、検索／ページ変更でも選択先保持、継承／変更先IDなし行は選択不可、正規の検出結果IDへ送信、見出しは `#finding_id · (name || vulnclass)`。既存FindingService.listの厳格さを維持し、専用bindingCandidatesで読み取り専用候補を許容し、ページ／件数、生文字列／エンコード後の上限を検証。既知の重要度だけ英日変換し、独自値、名前、要約、FEFF／NFD／中国語／韓国語の生データは保持。ネイティブ側では新鮮な証跡と完全な成功応答を必要とする。ブラウザにも同じ復旧UIがあるとは主張しない。
