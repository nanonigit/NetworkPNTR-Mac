# Indexed tool execution and Linux process restart verification

The managed cloud2 backend uses the existing tool-history patch followed by a checked indexed-execution patch on norma v0.4.3. The patch fixes the real ChatAgent streaming path. Signature metadata can arrive before arguments, and tool arguments can interleave by index. The executor waits for completed indexed streams, validates the raw arguments and IDs, and executes the same blocks that go into history. Early fragments attach to their matching starts. Unmatched fragments, malformed arguments, duplicate or missing IDs and incomplete streams fail before indexed enqueue. The scheduler keeps the original turn context through queue processing, semaphore waits and tool calls. The existing unindexed scheduling path remains available for normal turns. See cloud-indexed-execution-design and bugs/cloud-indexed-execution for the contract and reproduction.

The actual HTTP provider and ChatAgent passed both process-restart modes. Each scenario runs two separate Linux subprocesses with the same file-backed transcript. The first executes one fixed Read and sends the matching signed history and result. The parent removes the witness file after that process exits. The second reads the transcript, replays the same call ID, signature, arguments and saved result, emits zero new tool uses, and appends a reply to the existing history. The loopback fixture receives exactly three requests in each scenario. Its child checks the exact local authority and path. The protocol witness includes the real tool output, not a precomputed response.
