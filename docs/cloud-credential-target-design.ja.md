# 保存済みAPIキーと送信先の照合

保存済みAPIキーを再利用するには、通信形式、ベースURL、設定されたプロキシの一致が必要。カスタムゲートウェイでは同じオリジンに複数のテナントが存在し得るため、ベースパスまで照合する。前後の空白とベースURL末尾のスラッシュだけを正規化する。URLが空の場合は、保存した通信形式の既定接続先に限る。明示的に入力したキーは、編集後の接続先に使う。

モデル一覧と接続テストは、保存済みプロファイルを1回読み取り、要求を送る前に照合する。保存済みキーでモデル一覧を取得するときは、チャットと同じ通信形式に従ってベースパスと環境変数の既定値を解決する。親パスへの旧フォールバックは、キーを明示した要求で利用できる。プロファイルIDが指定され、保存キーがないか接続先が一致しない場合は、グローバルキーへ切り替えない。旧形式の接続テストと設定APIは、接続先が一致するときに限りメモリ内のグローバルキーを再利用できる。拒否した接続テストは既存のキー未入力結果を返し、プロファイル編集には固定エラーを返す。

キー未入力の編集ではPostgreSQLの対象行をロックし、保存された接続先とキーの有無を確認してから同じトランザクションで更新する。キーがない設定は接続先を変更できる。保存済みキーがある場合は、接続先の変更時にキーを明示的に入力する。隔離したネットワーク名前空間のPostgreSQLとループバックの模擬APIで、保存行と実HTTPハンドラーを検証し、拒否された試行の送信件数が0であることを確認する。
