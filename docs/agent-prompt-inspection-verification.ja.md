# プロンプトのプレビューと版の差分の検証

Mac のエディターから別シートで結果を確認できます。プレビューは認証済みの `POST /api/agents/{key}/prompt/preview` に下書き原文を送り、ゲストが変数をサンプル値に置き換えます。下書きが空の場合は固定版 API と同様に現在の保存済み本文を使います。展開結果とゲストの構文エラーは選択できる原文で表示します。固定ブラウザ版の成功結果は Markdown 表示です。

過去の版と最新の保存済み版を比較できます。Swift の行比較では UTF-8 の一致を使い、LF での分割と同じ長さの候補がある場合の選択順を固定ブラウザ版に合わせています。追加と削除には記号と色が付き、行数または計算量の上限を超えた場合は両方の版の原文を表示します。どちらの確認操作も下書きや保存済みの版を変更しません。

`e75ae371ad777ffd1eecdd28d2781a6519b05591` に固定した使い捨て Docker 参照環境で、正確なサンプル値への展開、未定義変数に対する HTTP 200 内のエラー、空の下書きでの保存済み本文の使用、本文と履歴が変更されないことを確認しました。行が重複する場合と CRLF・Unicode の場合は、固定ブラウザ版の差分関数を実行し、Swift テストの期待値と照合しました。編集と確認の画面を分ける際には Lazyweb の v0 の例も参考にしました。

署名済み Mac 版を使い捨て VM に接続して確認しました。参照版と同じサンプル値に展開され、未定義変数のエラーが表示されても下書きと v1 は残りました。v2 を保存して差分を開き、削除行と2つの追加行を確認しました。初回の VM は操作待ちで時間切れになり、新規 VM で検証と停止を完了しました。ゲスト検証は Swift ビルドと並行した初回に2件が時間切れになり、単独での再実行で195件すべて成功しました。Swift は1,069件成功し、既存の1件がスキップされました。リリースビルドとプレビューの署名検証も成功しました。GitHub Actions は利用枠ポリシーに従いスキップしました。

`swift test --filter AgentPromptInspectionTests` でリクエスト、比較順、改行と文字の扱い、計算量の上限を試験できます。Markdown 表示、既定値へのリセット、エージェントの設定と権限、認証後のブラウザ実画面比較は残っています。
