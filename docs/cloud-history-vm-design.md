# Signed history replay across a VM reboot

Use the managed cloud2 binary in a disposable CPU1 Linux VM with zero NICs and host shares. Build a read-only system disk with a loopback-only fixture provider started by the candidate init. The fixture accepts one fixed model, endpoint and synthetic bearer. The first boot makes one guest-only Read of a fixed volatile file. The provider checks the signed assistant tool call and actual result, then saves a digest of that result on the private state disk. The restarted fixture requires the same signed call and result digest. It returns a completion marker after validating both prior and new turns. The volatile file exists only on the first boot.

The signed DEBUG VMProbe uses the production Swift authentication, LLMService and ChatService. It creates a pinned profile and conversation through the normal API, waits for the first completed turn, stops cooperatively, and boots the same state disk. It verifies the original profile, conversation and activity IDs, sends the continuation and checks the new completion and the original single Read/result. Stopped serial logs supply per-boot fixture, credential and isolation witnesses. The built candidate manifest digest binds both boots. Test malformed histories, wrong signatures, reordered events and changed results. Browser comparison and cloud egress are separate gates. This VM and CLI phase places Lazyweb outside scope.
