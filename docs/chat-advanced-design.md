2. Attachments: server/chatupload.go caps the complete multipart request at128MiB; existing native JSON requests/responses are4MiB and use fixed application/json. Do not raise every JSON limit or declare small-upload parity. Add a separate streaming multipart request path with bounded files/request accounting, explicit file selection, no host paths in request metadata, short-read/changed-file detection, cancellation/VM-stop and ownership. Browser creates a conversation on draft file selection and uploads to scope=session,id=conv-ID, carries draft/attachments to selection, permits attachment-only send and restores both after failure. Removed cards do not imply deletion of guest files. Verify repeated names, empty file, at/over limit, interrupted transfer and failed handoff with the pinned browser.

Implement a bounded UTF-8/incremental SSE parser/transport with reconnect/reconciliation and cancellation before exposing controls.
