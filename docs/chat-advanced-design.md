## Attachment transport implementation boundary

Inspection of the pinned server/chatupload.go confirms that128MiB bounds the multipart body, including boundaries/part headers, rather than each file. ParseMultipartForm uses32MiB memory before spilling; duplicate names receive suffixes instead of overwriting. Session upload uses id=conv-<positive conversation ID>. The server response contains guest abs paths; native presentation must not confuse those with Mac paths or offer a host-open action.

Keep BackendJSONTransport/BackendHTTPRequest and their4MiB request/response checks unchanged. Add a separate authenticated multipart capability through AuthenticationSession so401 still clears the session and Keychain. Do not expose bearer values to ChatWorkspace or the file picker. The new runtime API owns one VZ connection and a duplicated descriptor per transfer. A cancellation handler must actively interrupt the duplicate and terminate the worker, including while polling or stalled in a write; cancelling a detached Task alone is insufficient. VM stop invalidates transfer identities. Responses remain finite/bounded JSON and are parsed with existing status/framing validation. The guest relay already uses64KiB buffers and a fixed loopback endpoint; no host shares, NIC or general file RPC is required.

Represent multipart framing and checked total length before connecting. Read selected regular files in bounded chunks, never concatenate128MiB into Data or increase the generic JSON cap. Explicitly selected files are scoped to the transfer and released on success/error/cancellation. Validate selected-file identity/size and observed metadata before/after reading, reject short/extra reads and changed observations, and document that this is not a filesystem snapshot guarantee against concurrent same-metadata mutation. If stable retries need a snapshot, use an app-private bounded staging copy, not a shared directory. Only basename and content travel; no Mac absolute paths, bookmarks or security-scope tokens enter request metadata. Filename escaping and empty/duplicate/Unicode file behavior require actual pinned-browser multipart comparison, not an assumed browser implementation.

Implement in ordered gates: A1 pure multipart framing/length/file-read regression tests, including exact body limit and over-limit rejection before any socket; A2 real socketpair backpressure/partial-write/cancel/early-response/timeout tests and authenticated session handling; A3 signed app/VM uploads with content hashes, zero-length/repeated names and128MiB-body boundaries compared with the disposable reference; A4 keyed draft attachment ownership, create-on-selection handoff, attachment-only send, failed-send restoration, removal without deleting guest data, conversation switch and VM-stop tests; A5 native picker/cards/progress/error controls and external browser/native keyboard/accessibility/visual pairs. ## A3 bounded full-content verification

Use a single GET of the pinned workspace/download handler (server/workspace.go calls http.ServeFile), not multiple Range requests that might mix file versions. Consume at most64KiB per feed and hash incrementally with CryptoKit SHA256. Success requires HTTP200, one decimal Content-Length equal to the expected attachment metadata, no Transfer-Encoding or nonidentity Content-Encoding, and at most128MiB. Header storage is64KiB; no full success body is retained. Finite error responses are at most4MiB and report status through the authenticated revision guard, never body text or tokens. Reject malformed/duplicate framing, unexpected status206, missing success length, truncation and extra bytes. A single response is not a guest filesystem snapshot; don't claim detection of same-size concurrent mutation. Expected synthetic SHA independently proves the controlled fixture's bytes.

First implement/tests the incremental digest state machine (split headers, every binary byte, empty/exact/over bounds, malformed framing and terminal failures). Then implement a dedicated nonblocking socket exchange with owned cancellation/finite deadline and backpressure/short-read tests. Integrate a typed authenticated attachment-only capability (positive conversation ID, single safe basename, expected size) and runtime post-await lease checks before diagnostics. Extend independent disposable reference hashing and compare actual large-file hashes. Existing upload/JSON paths remain bounded. No NIC, host share, host command endpoint or UI change is introduced; Lazyweb is outside this backend work.
