# クラウド中継のHTTP応答フレーミング検証

TLSワーカーが受信したプロバイダー応答を、試験と同じ処理で検査する。ステータスと種別、本文の断片、完了を順に送る。完了には、HTTP応答の区切りが正しいこととTLS通信が正常終了することの両方が必要。転送先の失敗、通信エラー、キャンセルは応答の失敗として扱う。

途中の情報応答、引用符付き拡張、トレーラーを含むチャンク応答について、全分割点と1バイトずつの受信を試験した。全途中切断パターン、曖昧なフレーミング、リダイレクト、HTTP本文を受信し終えた後のTLS失敗、本文なし応答、エラー応答、累積上限、転送失敗も検証した。レビューで、Unicodeの小文字化で不正な符号化が受理される例と、不正なチャンク拡張が通る例を発見した。符号化の指定をASCIIに限定し、拡張名と値をHTTPの構文で検査するようにした。[HTTP/1.1のフレーミング仕様](https://www.rfc-editor.org/rfc/rfc9112.html)

`swift test --filter CloudEgressResponseTests` で再現できる。入力と試験結果は[検証記録](../evidence/llm/cloud-egress-response-verification.json)を参照。専用vsockプロトコル、VMの起動停止との連動、署名済みVMでのストリーミング、実APIとブラウザ版との操作比較は後続の受入条件。画面変更を伴わないためLazywebは対象外。ホストCIは未検証。
