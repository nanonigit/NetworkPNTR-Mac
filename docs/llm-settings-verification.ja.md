# LLM設定：比較検証の中間記録

実装済み・ネイティブ受け入れは一部確認済みです。機能全体や配布の合格ではなく、21機能すべてをアプリにする目標は維持します。

## 証拠

- Swift 30件が成功しました。全送信項目、空キー編集、形式ごとの出力上限、リトライ範囲、秘密非表示、異常応答、認証付き通信、部分設定更新、取得失敗時の保持を含みます。保存成功後の再取得だけが失敗した場合は作成を失敗扱いにせず、重複作成の再試行を防ぎます。Python 14件も成功しています。カバレッジ率の測定結果ではありません。
- 署名済み.appは1 vCPUの直接ルート診断VM、本物のARTEX/DB・vsock・Keychainを使います。evidence/llm/native-service-results.jsonに、3形式のCRUD・空欄でのキー保持・有効設定削除拒否・ローテーションと除外/復旧・リトライ・再起動後の保持を記録しました。内部診断のUIクリックfalseは診断方式の範囲を示し、別のCUA実操作まで失敗扱いにする値ではありません。
- 11群の契約結果が使い捨ての固定ブラウザ版バックエンドと一致しました。比較コンテナは外向き通信・公開ポート・ホスト共有なしで、既存DBや本物のキー・有料APIを使いません。`compare_backend.py <vm-contract> <output> --kind llm`で同じ専用操作を比較できます。
- 外部CUAでLLM画面を開き、フォーム全項目、無効な数値の拒否と修正、API形式に応じたフィールド有効化、キーなしのモデル取得エラー、作成、名前・回数・ストリーミング編集、Return保存、有効化と削除禁止、元の有効設定への復帰を確認しました。範囲はexternal-ui-results.jsonに明記しています。
- native-profile-cards.pngとbrowser-profile-cards.pngは独立したCUA撮影です。ナビゲーション、カードと操作の配置を比較しますが、データと表示寸法・ピクセル倍率は異なります。同一データの画面同等性やピクセル一致の合格には数えません。元のブラウザタブはダッシュボードへ戻し、後から作った比較タブも閉じました。

## 差分と未完了条件

SwiftUIの分割ナビゲーション・システムフォーム・秘密入力・タブ・編集シートを使います。ブラウザ版のパラメーターを維持し、通信中・失敗を表示します。プロキシの資格情報を一覧に出さず「設定あり」と表示し、接続テストの生エラーもキーが反射されない一般的な文面にしています。数値の誤入力を明示し、空欄はブラウザ版と同じ0/既定値として扱います。

全体リトライに切り替える際にCUAの接続が切れました。プロセスが動作中であることを確認し、状態再取得と新しいCUA接続でも失敗したため、この操作は合格に数えません。ローテーション/全体リトライの実操作、削除の最終確認、サイズ変更・明暗・アクセシビリティ、モデル一覧の成功・実応答、通信先制限、通信中断、完全な画面比較は残ります。内部画像やAPI成功では代用しません。

1 vCPUのLinuxKitカーネルはローカル診断材料です。再現可能ビルドとライセンス、長期安定性、ログ上限、配布準備は別の未完了条件です。2 vCPUの間欠的なゲスト異常を解決扱いにはしていません。

## 実アプリ診断の再現

開発用ビルダーで固定バックエンドを用意します。診断用の起動構成は配布物ではなく、調査記録に従って別途準備してください。`ARTEX_MAC_GUEST_BUILD_DIR=/path/to/verified/profile script/build_and_run.sh --build-only`で構築し、実行ファイルに`--native-diagnostics /private/fresh/fixture-directory`を渡します。専用ディスク・一時Keychain項目を作り、終了時に項目を削除してVMを正常停止します。`--native-review`は認証済みのテスト環境を最大15分保持します。専用フォルダー内に固定名native-review-finishを作ると片付けを再開します。任意のコマンドやゲスト入力は受け取らず、DEBUGビルドに限る仕組みです。実ユーザーの保存先をテストに流用しないでください。
