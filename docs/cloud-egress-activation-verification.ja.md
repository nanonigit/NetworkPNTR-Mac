# クラウド中継プレビューの起動検証

署名済み VMProbe で、Mac アプリと共通の DesktopRuntime の起動・停止処理を使った。
改変したマニフェストを VM 生成前に拒否し、検証済み候補では有効・無効の両方を起動した。
どちらも初回認証の準備が完了し、明示的に有効にした起動だけで本番中継が開いた。
無効時に直接中継を開こうとする操作も拒否した。停止後は VM と中継の解除、
ネットワーク機器なし・共有マウントなしを確認した。その後、別ディスクで
4社の模擬通信の回帰試験を行った。

固定したゲストを同梱した ARM64 Release のプレビューはアドホック署名済み。
`open -n "/path/to/ARTEX Mac Cloud Preview.app" --args --cloud-egress` で起動する。
プレビュー専用の状態と Keychain アカウントを使う。引数を省いた場合は通常の起動方針が
適用される。起動検証ではプロバイダーに要求を送っていない。GUI の実起動、実 API、
プロバイダー選択画面、固定ブラウザ版との比較は今後の検証項目。

## 実行環境画面の表示回帰

署名済みの配布用アプリを Launch Services から `--cloud-egress` 付きで起動し、
仮想NICとホスト共有なしで実行環境が準備完了になった。実行環境画面には
クラウド通信がオフという固定文言が残っていた。アカウント画面は初回設定まで到達した。
この起動では管理者パスワードの設定とモデル一覧の取得は未実施。

固定の説明文で隔離とプロバイダーへの通信をまとめており、リスナーのプロパティは
監視対象外だった。修正後は隔離とリスナーの状態を分けて表示する。この表示で確認できるのは
ローカルの中継の稼働状態。各社への疎通はモデルAPIで別に確認する。
固定ブラウザ版には専用VMの状態画面がないため、実機のVMの起動・停止と照合する。

Swiftの回帰テストは1,084件が合格し、既存のアクセシビリティテスト1件がスキップされた。
署名済みVM検証では、有効と無効の各モードを新規ディスクで確認し、改変されたマニフェストは
VM起動前に拒否された。

更新後の署名済み配布用アプリを実機で確認した。アクセシビリティツリーでは、起動中は
中継が停止中、起動完了後は対応プロバイダー向けに稼働中、正常停止後は再び停止中だった。
起動完了画面にはホスト共有と仮想NICがないことが表示され、ゲストログでも両方が0だった。
プレビュー専用の検証状態は通常の保存先から退避し、プレビューのキーチェーンセッションが
ないことを確認した。同梱ゲストのマニフェストのSHA-256は
`5bc88b952a14bfe695d091e384e666a2fa24a68a4eb97cea40e77dac18b6b290` だった。
