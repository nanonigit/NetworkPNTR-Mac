# 元データの制御した転送中断: 検証の回帰防止

## 再現と時系列

6f7e15eでDEBUG証人の未実装をコンパイルREDとして定義し、d0f4659で状態試験6件が成功。b124110では実socketpairから4096バイトを非公開ファイルに書いたが、診断スコープで観測できず3つのアサーションが失敗した。fb6a13cでステージングを接続して時刻を注入すると、ステージングは通過した一方、期限後の記録に関する2つの失敗を再現した。3b465e8で同じロック下で期限を保持・検査し8件が成功。953b9efで未実装の実VM経路を定義した後、bb9658bで接続した。

別レビューではメタデータのawaitを挟んで検証設定の空き検査と代入が分かれており、別所有者を上書きできる点も発見した。f3f4267で一度に取得する契約をコンパイルREDとして追加。4a9f3eeで関連19件が通過し、修正ではMainActorで中断なく空きを取得し、その直前に実VMの稼働を再検査する。既存の検証設定を維持する。両方ともDEBUG検証の正しさの問題であり、通常アプリのプロファイルを昇格せず、外部対象にも接続していない。

## 5 Whys

1. 期限後キャンセルを成功と誤認する理由: 記録側が停止状態だけを見ていた。
2. 期限後も停止状態が残る理由: 待機側が期限検査へまだ復帰していなかった。
3. 待機側だけでは不足する理由: キャンセルとタイムアウトは並行する状態遷移である。
4. 別の所有者を上書きする理由: 空き検査がawait前だった。
5. 遷移をまとめる理由: 時刻の有効性と所有権の空きは、待機前ではなくロック／actor隔離下の実際の遷移で検査する必要がある。

## Fishbone・修正

時刻: 単調期限を保持し、条件ロック下で記録側も検査する。所有権: メタデータ後にMainActorで空きを取得し、清掃も自分の設定だけに行う。識別: ID生バイト・side・長さ・hash・操作UUIDを一致させ、重複は証拠を無効にする。転送: 最初の追記成功後にDEBUG限定で期限付き停止し、実ソケットを先にshutdownしてから記録する。ファイル／認証: 保存先とステージング不在、元認証リビジョンの有効性、親タスクの非キャンセルを要求する。範囲: detached転送内に明示的TaskLocalを置き、Finding診断と分けReleaseに含めない。清掃: 失敗時も子タスクを終了まで待ち、返ったレシートは破棄する。

## 再発防止

ID生バイト／side／hash／長さ、重複、本文前キャンセル、完了ソケット、期限、期限後記録の決定的再現、実部分ステージング、TaskLocal分離の試験を残す。実VMの前提と空き取得も回帰テストに残す。実ゲスト中断・その後の通常バイト照合・再起動が通るまで、この条件を完了と数えない。制御した読み取り停止を記録し、自然なタイミングのキャンセルや自然発生のネットワーク障害を証明したとはしない。UI／保存パネル／全21比較／kernel／provider／harness／releaseは別条件のまま維持する。
