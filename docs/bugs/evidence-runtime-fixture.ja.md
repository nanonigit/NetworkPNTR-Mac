# 実VM診断の所有権・結果判定の不具合

## 1. 再現

試験データは当初8件、準備／DB／活動監査を加えて11件成功。レビューから、作成ファイルの置換、削除失敗、書込側のないFIFOを追加。cf31f29で14件中3件失敗し、置換ファイルの削除対象化、後始末失敗の隠蔽、FIFO待機を再現した。FIFOは時間制限付き子プロセスで安全に終了させた。

native診断にも最終書込み／後始末の正確な契約が必要だった。dd82b15は非公開／不足APIへのコンパイルREDであり、最終書込み失敗を当時の経路で実行再現したと主張しない。be693f7で関連9件成功。最初の署名実VM2起動は終了コード0、4本文を各起動で保存し、ログアウト／停止／再起動後の結果を拒否。ただし通信中キャンセルは未観測だった。

途中ファイルの観測だけでは、既に完了したworkerの受取りを止めただけでも成功扱いにし得る。c05edb0で、閉じたソケットへの後続キャンセルを拒否する操作別証拠の不足契約をRED化。9b41048で関連12件成功。新規ディスクの署名実VM2起動も終了コード0となり、通信中の呼出元キャンセルとVM停止を観測できた。

## 2. 証拠

後始末は名前だけを保存しunlink失敗を無視、FIFOは型確認前のO_RDONLYで待機していた。初期診断は最終書込み前に成功を立て、失敗時の作業ディレクトリも未確認。最初の通信中判定案も、過去の途中サイズだけで開いた接続の中断を確認していなかった。いずれも製品完了の証拠には採用していない。

## 3. 原因分析

5 Whys：置換を削除できたのは所有権をパス名で判断したため。後始末失敗が成功に見えたのは例外を捨てたため。削除の試行と完了を同一視し、名前空間変更／特殊ファイル試験が不足していた。根因はinode／型と明示的な後始末結果の契約不足。

結果判定は、計算上の成功、報告書の永続化、実際のプロセス終了を混同していた。通信中キャンセルは、過去の途中サイズとMainActor未完了だけを信頼し、独立workerが先に終わる可能性を見落とした。操作別の中断応答が不足していた。

Fishbone：ファイル所有権／型、削除例外の隠蔽、報告書I/O順序、workerと受取りの非同期差、異常系不足。時系列：21550ff不足RED→ef1c42d／84ed150成功→cf31f29所有権／FIFO RED→aec5b46成功→5a7e774クライアントRED／a4dc815成功→4813259／dd82b15ファイル／結果契約RED→be693f7成功→886d500途中観測RED／d8252f9成功→c05edb0操作別証拠RED／9b41048成功→実VM通信中受入。

## 4. 修正

作成時device／inodeを保持し、置換を削除せず、全対象の後始末を試みて未完を返す。監査はO_NONBLOCK／O_NOFOLLOWで開いて通常ファイルを確認する。結果公開は起動／保存／所有権の事実で制限し、失敗時は必ず成功を消す。出力／ダウンロード先の残存も確認する。報告書だけでなく観測済み終了コード0を必須にする。ディスク障害時は古い報告書を書換えられない可能性があるため。

DEBUG／package専用の観測は、対象UUIDと全マニフェストを保持し、キャンセルハンドラー内のatomicなsocket.cancel()結果を記録。完了済み・重複・別対象を拒否。VM停止は別に登録済み接続1件の中断を必須にし、処理を待ってから後始末を確認する。リリース版にはこの観測フックを含めない。
