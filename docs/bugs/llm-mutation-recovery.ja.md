# LLM書込の復旧：5段階記録

## 1. 再現

最初はstop/resume・不明世代・再開APIの欠落でコンパイルRED（db2de38）。実装c16fd45で元の所有権6件を含むLLM関連28件成功。拡張試験6b3a35cでは確認済み状態が残るアサーション2箇所の失敗と、読取開始通知からの同期離脱でsignal11クラッシュを検出した。日英4キー不足で行列試験1箇所が失敗（3c84608）。修正89f6728で36件成功。レビューが復帰側の同様の再入を発見し、上限付きRED3e903fbで2件・3箇所失敗。修正2088822で関連38件成功。実キー・クラウド要求・ゲスト書込は使用していない。

## 2. 証拠と時系列

6系統の書込、送信前入力不正、送信後取消・遅延成功、離脱復帰中のゲート保持、古い全取得、プール取得だけでは確認済みにしないこと、次の取得失敗、古い再開世代、確認済み保存後の取得失敗・離脱、同期通知の再入を扱う。その後RootViewから画面ローカルなストア再生成を発見し、所有者管理の試験とウィンドウでの保持を別途追加する。実画面移動の受入は未完了。

## 3. 根本原因

5 Whys：再操作を許したのは書込エラーを表示するだけだったため。送信前失敗と送信後不明を区別する印がなく、離脱・再入を止める保持チケットもなかった。全取得後の明示的再開世代を要求せず、試験が即時の成功・失敗に偏っていた。Fishbone：状態＝busy真偽値、寿命＝移動先ビューが所有、通信＝取消後の遅延応答、通知＝代入前に実行、検証＝敵対的ライフサイクル試験不足。時系列：送信→離脱／取消→サーバーでは成立し得る→応答を受け入れられない→一般エラーだけでは重複再操作を許す。プロバイダ障害の証拠ではない。

## 4. 修正

内部送信コールバック、所有権付き読取・書込チケット、獲得時とライフサイクルの再入防止、不明世代と全取得の確認世代を導入。明示的再開までストアですべての書込を禁止する。同じ認証中はウィンドウ側でストアを保持し、認証所有者変更時に停止・解放する。3画面共通の日英パネルを無効フォームの外に置き、読取専用の概要と独立した再読込・再開操作を提供。自動再送・秘密保存・再開時の書込は追加しない。

## 5. 検証・再発防止

回帰試験と112項目の日英行列を維持する。回数上限付きの復帰再入と読取離脱の再帰試験を削除しない。独立レビューが復帰側の修正を再確認した。接続試験・編集タスクの所有権、アプリ終了をまたぐ不明状態の永続化、実ブラウザ／ネイティブ操作、シートの収まり、アクセシビリティは未検証。ソフトウェア試験ではこれらを完了扱いにしない。
