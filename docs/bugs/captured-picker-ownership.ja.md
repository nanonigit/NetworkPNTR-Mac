# 通信候補の所有権：5段階回帰記録

## 1. 再現

状態欠落RED e1ba09aで候補選択の契約を定義。初期実装b1f4d5fは14件・7箇所失敗。読取中の表示更新が同期的な失効処理を上書きし、失効済みの処理を呼び、処理中ゲートが残る問題を再現した。修正fe8d687で14件成功。拡張RED ca191b7は21件・8箇所失敗。選択／プレビューIDの復元、再帰・離脱要求の消失、終了処理中の古い成功通知を再現。修正ed3f6b7で21件、関連全50件が成功。

## 2. 証拠・時系列

合成通信で一覧・プレビューを逆順に返し、追加は送信後に待機させた。ページ横断選択、既存IDの除外、NFC/NFDのバイト識別を確認。親・子の処理中通知で閉じた場合はPOSTも結果不明も発生しない。送信後の離脱復帰はゲートを保持し、親の確認済み結果を保ちながら子の成功表示を破棄する。送信後の取消は親の不明状態を保持する。成功後の終了処理の試験は送信後に通知を監視し、同値代入の事前通知に依存しない。

## 3. 根本原因

5 Whys：古い選択が残ったのはstop後も別の集合への代入が続いたため。消去が元のsetter完了前に行われ、ライフサイクルの再入を防いでいなかった。結果の後処理後にも所有権を確認せず、同期通知を使う結合試験が不足していた。共通読取も、処理中を公開したことで自分の世代が無効になっていないか確認していなかった。Fishbone：状態＝別々の選択集合、寿命＝復帰・再入、通信＝許可後の送信直前、識別＝親・検索・表示対象、検証＝通知段階と逆順応答。時系列：獲得→同期終了→元のsetter継続→残存データ・古い成功通知。バックエンド障害の証拠ではなくローカル状態の不具合。

## 4. 修正

獲得・離脱復帰のガード、復帰中の終了要求の保持、復帰時の選択消去、状態公開後の所有権再確認を追加。親ownerを捕捉し、親サービスの送信直前に子を再確認する。親の世代・不明ゲートを維持する。共通FindingReadStateは処理中公開後・最初のawait前に世代を再確認し、処理を呼ぶ前にも取消を確認。後続読取は失効した処理中状態に妨げられない。再試行・自動追加・不明解除・ホスト能力・実ゲスト書込は追加しない。

## 5. 検証・再発防止

ページ横断・既存・バイトID、古い／逆順読取、読取専用対象、追加成功・競合、送信前後の離脱／取消、同期通知の回帰を保持する。独立レビューが選択復元を指摘し、修正を確認。共通読取・ライフサイクルの修正もレビュー済み。ネイティブ操作、親／詳細への接続、原文全体の保存、実ゲスト／ブラウザの非空・永続化、キー操作・VoiceOver・画像受入は未完了。CIアカウントの支払い／利用上限も別の未完了条件。
