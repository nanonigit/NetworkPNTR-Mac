# 空の名前に対する参照検証の修正

MUSUBIの流れで、隔離実行の失敗と保存済みDB・ログを確認し、省略された名前の応答で再現、参照検証だけを修正、RED/GREENと新しい使い捨て環境で確認し、失敗と回帰試験を保持する。

schema2のネイティブ3起動は成功したが、最初の独立参照実行は空の名前でraw textエラーとなった。保存した合成9101行は名前が空、分類は正規化済み、重大度mediumで、長い分類名への変更前だった。固定版server/dto.go:315のFindingDTO.nameはomitemptyで空文字を省略する。ネイティブ側は省略を空文字として既に扱うが、参照側は必須としていた。

5 Whys: 省略をNoneとして失敗→DTOは空文字を省略→単体試験は名前を必ず含めた→SQL形状を応答にも流用→省略専用の回帰試験が不足。特性要因はDTO直列化・試験形状・検証前提。時系列は実VM成功→独立参照失敗→単体2件RED→省略だけを空文字として扱う修正→重点9件GREEN。nullや空でないはずの名前の欠落は引き続き拒否する。固定版・シード・監査・通信制限は変更せず、失敗環境内で更新を再試行しない。

失敗時のDB258823バイト、ログ4197バイト、実行行記録2525バイトを非公開で保存した。所有するコンテナ・タグ・別名だけを削除し、元の入力とコンテナを保持した。修正後の実測結果は別の境界検証記録に残す。生データ・認証情報・ログはGitに含めない。
