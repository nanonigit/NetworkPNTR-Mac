# 通信履歴の表示境界の調査

## 再現と証拠
b4d931fはモデル未実装による意図したコンパイルREDで、実行時不具合ではない。3d89699で制御した時計の12件が成功。その後ada08e1の15件で6つの失敗／エラーが発生し、確認画面中に満了した入力の消失、stop中のreset要求で結果不明の操作範囲が残る問題、beginの旧表示破棄中のreset後に新表示が開く問題を再現した。モデル／コアの決定的な試験であり、インストール済み画面やVMの観測ではない。

## 根本原因
5 Whys：タイマー満了後にapplyがfalseならタスクを破棄していた。falseで不正／古い入力と一時的な確認／書込みゲートを区別していなかった。満了済みチケットの保持場所がなかった。そのためゲート解除後に未適用検索だけを反映する経路がなかった。欄ごとの満了チケットを保持し、ゲート解除を観測して解決する。サーバー変更操作の再送ではない。

resetの消失は、tearingDownならすべてのライフサイクル要求を無視したため。通常stopとreset自身の後処理を区別しておらず、再帰通知の防止が認証上の消去優先度を上書きした。通常の破棄中はresetを待機させ、実際のreset中の再帰要求だけを抑止し、reset待機時にはbeginの再開を防ぐ。

Fishbone：時間—300msチケットと一時ゲート、識別—欄／表示とquery所有権、寿命—stopと認証reset、並行—willSet通知と通知世代、通信—キャンセル無視読取と新条件の世代、受入—制御した時計／APIと実時間／画面／VMの区別。

## 修正・検証の順序
b4d931f未実装RED→3d89699の12件GREEN→ada08e1実際の境界RED→e5fc56fの15件GREEN→追加18件。満了した入力を確認／書込み中も保持し、解除後に現在のクエリーへ統合する。変更操作の再送や結果不明の暗黙承認はしない。詳細解除／新規編集／表示破棄で該当チケットと観測を無効化する。stop／beginよりresetを優先して原文下書きを消去し、後処理通知による再開を防ぐ。修正の読取専用レビューでも新たな阻害要因はなかった。

## 再発予防・範囲
再現ケースと保留書込み503／回復の試験を保持する。今後のroot／画面はウィンドウ／セッションごとにモデルを保持し、不変leaseをBinding／タスク／破棄へ渡し、認証離脱時にresetする。時計は注入しているため実経過300ms／5sの精度、実画面、ブラウザ同等性、実backend変更を証明しない。TR3–TR5／kernel／4社／harness／releaseは未完了。最終の限定証跡はtraffic-screen-model-verification英日版を参照する。
