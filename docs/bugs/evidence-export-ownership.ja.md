# 証跡保存結果の所有権不具合

## 1. 再現

初期の認証保存9件はcad90bcで成功。保存前の検証コールバックから同じ結果のdiscard()を呼ぶ試験と、VM寿命検証がキャンセルを返す401結果を追加。232b57fで11件中5アサーション失敗。前者は破棄したはずのファイルが保存され、後者は古いVM結果によって現在のログインと保存トークンが失効した。

## 2. 証拠

確定処理がファイルをローカル変数へ移した後に外部検証を呼ぶ。discardはそのファイルに届かず、検証一覧だけを消していた。認証側はVM寿命確認より先に401を処理していた。実一時ファイルと認証状態への影響を確認し、実VM／プロバイダー接続や実資格情報は使用していない。

## 3. 原因分析

5 Whys：破棄後に保存できたのはローカルのファイル参照が生きていたため。所有権確認を通ったのは検証一覧が消えたため。消去で回避できたのは「消費済み」が再実行だけを止め、進行中の確定を失効させなかったため。独立した失効状態がなかったのは同期再入を未試験だったため。根因は後始末と公開権限を同じ状態として扱ったモデル不足。

401側は現在の認証revisionだけを信頼し、独立したVM寿命を先に確認しなかったことが根因。

Fishbone：消費／失効の状態設計、コールバックからの破棄、VM確認と401の順序、古い認証と古いVMの試験差。時系列：234418c API不足RED → cad90bc初期GREEN → 232b57f再入／VM401 RED → 1e7e64f修正 → 関連27件成功 → 129MiB+17バイト保存を含む36件成功。

## 4. 修正

破棄時に確定処理中でも独立したrevokedを立て、所有権コールバックの前後で確認する。401を処理する前にVM寿命を確認し、認証revisionの古さも失効操作より先に確認する。保存前の失敗では作業ファイルを破棄し、保存済みファイルは削除しない。画面側のactivity検証後、awaitを挟まずVM／認証を再検証する。

## 5. 検証・再発防止

上記2件、再ログイン後の古い200／401、Keychain異常を伴う現在の401、キャンセル無視の応答、転送後／画面検証中ログアウト、二重確定、画面／VM失効、停止中の実クライアント、実ファイル比較を保持する。実VM停止／再起動と画面所有権の受入試験が済むまで機能全体を完了扱いにしない。全体試験／ビルド／CIはevidence-export-connection-verification.ja.mdへ記録する。
