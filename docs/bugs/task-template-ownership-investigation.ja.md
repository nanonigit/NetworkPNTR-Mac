# T8 テンプレート所有権の調査

収集・再現: 制御可能な通信で、削除前 GET による再表示、ブラウザ版と異なる適用後の添付件数、古い子画面の終了通知による新画面の閉鎖、終了拒否後の親ドラフト消去、リセット直後の古い削除送信を確認。利用者データ・VM は使用しない。実際の失敗は RED コミットに保持し、画面終了と親破棄にも所有権の回帰試験を追加。

5 Whys: 非同期処理の所有権を一方の境界だけで確認し、読み取りと変更のゲートが分離、終了時に現在の所有者を参照、破棄側は終了成功を仮定、待機中処理は送信後だけ寿命を確認していた。初期試験は遅延応答に比べて同期的なスケジューリング間隙が不足。Fishbone はデータ（表示件数と実ファイル）、ライフサイクル（リセットと画面）、通信（読み書き競合）、実行順序（Task の待機）、検証（送信前と応答後）に分類。

時系列: 設計→API/モデル RED/GREEN→UI 連携の実行 RED→レビューで所有権修正→33ff113 の待機中削除 RED→修正・全体回帰。画面・編集・確認 UUID を固定し、親破棄を保護、変更時に読み取りを無効化、適用確定時のみ表示件数を消去、削除送信前にも寿命を照合する。古い処理でも defer でゲートを解放。同一セッションの確定応答は画面終了後も反映し、旧セッションの応答は破棄。結果不明の自動再送は禁止。

再発防止: 遅延 GET、古い Binding、破棄キャンセル、親本文と UUID 保持、送信直前リセットの送信ゼロ、送信後リセットの通知ゼロを通常試験に含める。実 OS 操作と保存永続化のブラウザ比較はロック解除後の受入条件として残す。
