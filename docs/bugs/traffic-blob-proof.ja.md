# 元データ検証の因果関係に関する回帰

## 再現と時系列

追加中のDEBUG captured-blob経路では、管理版の検査前に旧バックエンドのSHA条件を適用しており、新しい候補を起動できなかった。別レビューでは停止後のCancellationErrorを一律に成功として数えると、認証失効をVM所有権失効と誤認することも判明した。公開レシートには認証とVMの両方の検査があるため、原因を区別する必要がある。

2f919e8でモード別事前検査の未実装をコンパイルREDとして記録。855f131で分岐を実装した後、6件を実行し、VMが有効なままログアウト／再ログインした場合に4つのアサーション失敗を再現した。a42c40aで修正し、セッション保持と呼出元タスクのキャンセルも含め7件が通過した。追加テスト案のthrowing Task.valueにtry awaitが必要だった点は、GREEN前のテスト準備の修正であり、製品の不具合ではない。

## 5 Whys

1. 管理版を起動できない理由: 旧バックエンドのハッシュを無条件に検査していた。
2. 認証キャンセルを停止と誤認する理由: 原因の異なるキャンセルを一律に受け入れていた。
3. キャンセルが曖昧な理由: 公開時に複数の独立した所有権境界を検査する。
4. 認証phaseだけでは不足する理由: 再ログイン後も認証済みになるがリビジョンは変わる。
5. 別の証人が必要な理由: 元の認証リビジョンとタスク状態を独立して保持・検査し、VM所有権による拒否を特定するため。

## Fishbone・修正

成果物: CPUとリスナーの共通検査後、旧版と管理版を明示分岐する。寿命: 停止後の検査まで元セッションを強く保持する。認証: DEBUG限定packageメソッドで正確なリビジョンを捕捉し、トークンを公開せず拒否の前後で検査する。呼出元: キャンセルを受け入れるcatchの内外でタスクを検査する。VM: 呼出元で実コントローラーが停止しマシンがないことを要求する。清掃: 因果関係の検査に通ったときだけ停止済みとし、失敗時も外側で保留ファイルを破棄する。

## 検証と再発防止

対象7件が通過。使い捨てLinux VMでも2回起動・2回の協調停止・2回の監査が通過し、262401バイトの元レスポンスを保存して全バイトとハッシュを再照合、停止後の公開を拒否、再起動後も照合できた。固定ブラウザ参照結果も一致。認証失効・再ログイン・寿命・タスクキャンセルと事前検査の組合せを回帰テストに残す。停止後の公開拒否は転送途中のキャンセルを証明しない。ネイティブUI／保存パネル／キーボード／VoiceOver、通常プロファイルとカーネルの昇格、全体受け入れは未完。
