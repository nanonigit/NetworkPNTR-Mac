# Prepared traffic writes are not dispatched writes

MUSUBI: inspect state/service boundaries; reproduce synchronous cancellation and stop at the observed busy transition; repair explicit handoff tracking; verify held-response lifecycle and regression tests; retain bilingual records. The under-development store initially passed nine controlled tests, but independent review identified that service.execute can reject cancellation before calling transport while the store still records unknown.

5 Whys: zero-dispatch cancellation became unknown because every execute error was classified after handoff; the ticket existed before service cancellation checking; busy preparation was treated as dispatch; only already-cancelled and post-reply cancellation were tested; synchronous Observation callbacks exposed the gap. Fishbone: phase boundaries, observable reentrancy and test timing. Timeline: missing-store REDdedfcb2 -> initial seven/nine GREEN -> review -> RED21439be with eleven tests/five failed assertions -> explicit handoff and ticket-derived busy ->21focused GREEN -> independent repair re-review without blocker.

The service now invokes an internal callback after its cancellation check immediately before transport.send. The store revalidates session/activity/owner/ticket/active there, then marks the ticket handedOff. Earlier cancellation or synchronous stop returns notStarted without uncertainty or another request. Stop only marks handed-off tickets unknown; post-handoff cancellation/errors remain uncertain. Busy derives from the observable current ticket, so stale cleanup cannot desynchronize a separate flag. The callback is not a public arbitrary-operation capability; fixed routes, bounds and authenticated transport remain unchanged. This repair does not prove socket bytes were sent: transport handoff is the conservative uncertainty boundary.

Recurrence tests use withObservationTracking to cancel or stop synchronously as busy changes. Other tests retain stop/resume pending busy, reset plus newer write cleanup, exact-revision acknowledgement, read-not-ack, raw byte totals and foreign snapshot/selection rejection. Similar prepare-versus-handoff boundaries in other features remain a separate follow-up audit; this record does not claim they were repaired.
