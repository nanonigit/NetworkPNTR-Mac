# 管理対象ツール履歴の消失と署名の文脈

## 再現と経過

CP1bはモデル一覧・テキストを確認したがツール履歴は未検証だった。新試験は実際のプロバイダー実装とHTTPで、合成ツール2件、非ストリームまたは7バイトずつflushするSSE、JSON履歴保存・復元、事前に作った無害な結果を含む次の要求を検証する。aa2a6bfで署名消失と交互に届く引数の混入を実行時REDとして記録。3fe4c64で型付き署名と番号を保持し、既存の上流試験準備不備を修正したうえでGREEN。独立レビューが別接続先への再送を発見し、a7383eeでOpenAI／Groq／独自URLへの誤送信をREDとして再現。cb77140で受信時に接続先／モデルの識別子を付け、送信コピーで検証し、Anthropic分離も含めてGREEN。ツールは実行せず、実キーやクラウド接続先は使っていない。

上流のTestDoStreamHonorsConfiguredRetriesはHTTPクライアント未設定のまま内部関数を直接呼び、未修正モジュールでもpanicした。試験だけにsrv.Client()を渡し、本体の再試行処理は変更していない。署名問題のREDには数えず、スキップで隠していない。

## 5 Whys

1. 次のツール往復で状態が失われる理由：復号でGoogle署名を捨て、ストリーム引数を最後のツールへ集約していた。
2. 署名・対応関係が失われる理由：正規化ブロックに署名項目がなく、イベントにもツール番号がなかった。
3. JSON復元で直らない理由：正規化履歴へ入る前に情報が消えていた。
4. 最初の修正が別プロバイダーへ署名を送る理由：署名の受信元を記録していなかった。
5. CP1bで見つからなかった理由：一覧とテキスト、要求形式の確認範囲であり、ツール履歴・接続先変更は後続条件だった。

## Fishbone

形式：既知の署名だけを保持し、回避値や任意ベンダー項目を再送しない。状態：番号別の引数・署名と早いメタデータ。履歴：型付きJSONで復元。接続先：実行時URL／モデルとの結合とコピー上での不一致・不明署名除去。分離：再帰的にAnthropic向け専用項目を除去し、元履歴とAnthropic思考署名を維持。試験：ネットワーク無効のLinux内で固定本体＋HTTPと全関連試験、合成結果はツールを動かさない。供給元：固定依存を検証してコピーへパッチを適用し、コンテナ内だけで置換、固定ブラウザ／既定ゲストを維持。

## 再発防止と残条件

署名有無、ストリーム有無、交互引数、早い／遅い署名、JSON、同文脈成功、別URL／パス／モデル拒否、内部識別子を送らないこと、元履歴不変、Anthropic分離を維持する。試験・カバレッジ・ビルド記録はcloud-tool-history-verificationを参照。識別子は認証権限ではない。同一接続先でのキー更新、実タスクDB履歴、圧縮・再起動、外向き通信とリダイレクト、使用量／エラー／キャンセル、実4社接続とUI・ブラウザ比較は別途必要。フィクスチャ成功だけで実験バックエンドを昇格しない。
