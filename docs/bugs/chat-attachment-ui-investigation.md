## Cause analysis and prevention

5 Whys, ownership: a callback could affect the wrong work because selection/task scheduling and operation replacement are asynchronous; the visible owner alone was used; action identity was not carried through the UI boundary; core ownership tests did not exercise that UI callback; initial controls tests covered availability rather than stale event identity. Fix: immutable selection closure plus scheduling-time recheck, owner-bound removal, UUID-bound Cancel, invalidated panel completion tokens, controlled regressions.

5 Whys, error text: size validation appeared as a connection error because the workspace recognized only BackendAPIError; upload-body errors use another closed enum; a generic safe fallback masked actionable errors; backend error safety was reused without an allowlist for local validation; there was no cross-layer presentation test. Fix: allowlist the static body-error enum; keep arbitrary error descriptions out of the UI. Fishbone: async event ownership, panel lifecycle, error type boundaries, missing integration fixtures. Timeline: plan -> capability RED/GREEN -> owner RED/GREEN -> review stale Cancel -> UUID RED/GREEN -> native/browser actions -> oversize UI RED -> five-case RED/GREEN -> fresh signed native UI retest -> full suites and bounded coverage.
