# LLM編集シート：5段階回帰記録

## 1. 発見・再現

従来のビューは取得・試験・保存タスクを保持せず、離脱では入力欄だけを消していた。所有者欠落RED1700475で6件を定義し、GREEN85bc270で成功。拡張RED19dd23bは15件・6箇所失敗：開始待ち中の親離脱、親の離脱復帰前後の要求・遅延応答、同期終了後の入力代入によるキー復元を再現した。確認済みキー消去中のプロキシ復元の対照試験も保持する。ビューの機械的置換による引数ラベルのコンパイル誤りは挙動RED前に修正し、挙動証拠には数えない。

## 2. 証拠・時系列

合成通信で明示的な要求を待機させ、閉じる・編集・親世代変更の後に妥当／エラー応答を返す。開始前の終了では送信0件。送信後の終了は終了待ちゲートを保持し、応答を破棄する。保存取消は既存ストアを通し、結果不明時の復旧制御を維持する。修正3110030でLLM関連57件、入力所有者・画面外構築の整理333302bで59件（Core38／Mac21）成功。実キー・実プロバイダ通信・ゲスト書込・エージェントコマンドは使用しない。

## 3. 根本原因

5 Whys：遅延処理が反映されたのはビューを捕捉するTaskを取消用に保持しなかったため。応答に活動・入力の所有権がなく、親の状態も世代に結びついていなかった。入力欄の消去だけでは捕捉済みの処理は失効せず、試験がサービス契約に偏っていた。Fishbone：所有＝非構造化タスク、識別＝入力・親の世代なし、通知＝代入前のコールバックで終了し得る、秘密＝消去後に元のsetterがキーを戻す、検証＝敵対的なシート離脱試験不足。時系列：処理中を公開→離脱／編集→要求・応答継続→古い表示・終了。または入力代入前通知→終了で消去→元の代入がキーを戻す。

## 4. 修正

LLMEditorModelが入力・検証状態・単一チケットと取消可能なタスクを所有する。編集活動・入力・親の読取専用activityIDを捕捉し、送信と応答に一致を要求する。入力変更で同期的に失効・取消し、非表示後のsetterも代入後にキーを消す。closeは表示状態の更新前に寿命を失効させ、古い処理のゲートは終了まで保持する。確認済み保存後のキー消去は自分の保存通知を消さず、終了・編集後の通知は反映しない。ビューはモデルとマスク済みヒントだけを保持する。終了ボタンは閉じる前に取消し、離脱でも取消す。保存中の対話的終了は禁止し、自動再試行・要求は追加しない。

## 5. 検証・再発防止

開始前・送信後・親離脱復帰・FEFF/NFD/CJK入力・保存通知／キー消去・処理中／結果／入力通知からの同期終了・取消済み呼出し・検証不正の試験を保持する。独立レビューがキー復元を指摘し、再現と修正を確認した。画面外構築は形式・新規／編集・言語・明暗・候補・接続結果・エラーで暗黙の通信がないことを確認する。実際の収まり、候補ポップオーバー、キーボード／VoiceOver、ブラウザ／ゲスト／プロバイダの受入、プロセス再起動後の不明状態は別条件。
