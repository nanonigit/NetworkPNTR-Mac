# Findings画面のライフサイクル回帰

## 1. 観測・再現

F3.2のソース点検で、資産表示の単発取得後に一覧へ戻ってもポーリングが再開しないことを発見しました。RED9d8ad0fで切替を実行し、更新中の観測が失敗します。独立レビューでは、古い詳細終了操作が新しい選択を閉じる、ページ・表示切替で検索タイマーの入力が失われる、古い確認のgetterが新しい下書きを参照する問題を発見しました。RED73091e3の共通操作を使う3試験で5つのassertionが失敗しました。実ウィンドウやゲストでの観測ではなく、制御されたネイティブ部品の回帰です。

## 2. 調査

5 Whys: 画面タスクが完了して更新が終了→表示方式の変更で新しいタスクが始まらない→単発と反復を同じ寿命で扱った→詳細・検索・確認にも表示所有権を流用→異なる意図が重なる試験が不足。Fishbone: ライフサイクル（単発・反復）、所有権（表示・詳細・セッション・確認）、実行順（300ms・取消）、試験（ABA・入力の重なり）、UI（保持されるクロージャ）。Timeline: 未実装RED→初期5件成功→ポーリングRED→管理タスクで修正→レビュー指摘→確認操作3件RED→識別と検索を修正→データ入り表示・保留変更・深いツリー試験→再レビュー。

## 3. 修正

表示ポーリングを明示管理し、旧ループの完了処理を待ってから次の所有権を取得します。停止では読み取りと更新を取り消し、再表示では終了中の旧ループを待ちます。同じ検索での範囲・ページ変更は資産ツリーを保持します。操作による読み取りは取得・変更の排他後に集約し、全体集計は独立させます。明示更新には集計も含めます。

詳細選択ごとに専用世代を更新し、同一項目への戻り（ABA）も区別します。inspectorと閉じる操作は表示所有権と詳細世代を検証します。検索の意図はセッション・生の入力バイト・操作可能状態で識別し、待機後の現在のフィルターへ適用します。ページ・表示切替で失わず、確認画面を閉じた後も再開します。新しい入力・ログアウトで古い意図を無効化します。古い名前・重大度のgetterは空またはkeepを返し、新しい入力を変更しません。

## 4. 検証

古いinspector・終了・ABA、検索待機中のページ・表示・入力変更・ログアウト・確認画面、古い下書き・重大度の接続、資産取得中のページ・範囲変更、変更保留中の停止・再表示・集計、データ入り3表示、4確認画面、継承・旧項目の詳細、古い値・失敗表示、英日・明暗・幅900/1440、4096段のツリーを試験します。オフスクリーン表示はウィンドウを持たず、描画自体は通信しません。件数・カバレッジ・ソース識別はfindings-ui-verification.ja.mdに記録します。静的再レビューで追加の阻害要因はありません。実画面・キー・VoiceOver・VM・固定版との比較は未完了です。

## 5. 再発防止

保持される操作は実際の意図の寿命で検証します。表示所有権だけでは詳細や検索を識別できません。単発・反復の切替では更新中の証拠を確認します。オフスクリーンを実画面・AX・ブラウザ同等性の証拠に使いません。従来のカーネル・実行障害を保持し、未実装の発展機能を完了扱いにしません。
