# T13 集計キーの文字列同一性調査

収集・再現: 正常JSONにNFCのé、NFDのe\u0301、FEFF付きキーと通常キーを同時に含めると、当初の[String:Int64]は4件を3件にしNFD検索もNFC値を返し、一方の負/正衝突を受け入れた。da81515で3件の実行失敗。利用者データ/VM/実変更なし。別のキーコンテナも統合し、JSONSerialization可変コンテナはNFC/NFDを保つが先頭FEFFを失うため修正に使えない。

5 Whys: Swift辞書は正規等価でキーを比較→Go/JSの同一性と差→動的集計も通常デコードを再利用→NFD単独試験は同時共存を検証しない→負例に衝突の順序が不足。Fishboneは言語の同一性、JSON、動的キー、上書き後検証、試験多様性。

修正: 対象の集計だけ生JSONを走査し、順序付き項目・DataのバイトID・検索として保持。JSONDecoderで文字列を検証し、保存前にInt64/非負/同一バイト重複を検査。4MiB/深さ128に制限して文法と曖昧な既知別名を確認。ArchiveRecord/PageだけBackendJSONCodingから専用経路へ渡し他モデルは不変。無関係の入れ子は無視。これらに独自のキー付きデコードやJSONSerializationを使わない。

再発防止: b5e2647 GREEN9から10件に拡張し、ページ分離・4名/ID・両負数順・null/空・不正文法/桁/小数/エスケープ/深さ/サイズ/経路を確認。全Swift437件（成功436・既存AX1件スキップ）、Python62件、レビュー/署名同梱。件数のInt64と名前原文を保持する。実ジョブ・状態/画面・永続化は別の受入条件。
