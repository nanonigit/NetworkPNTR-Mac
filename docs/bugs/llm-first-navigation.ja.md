# 初回の LLM 設定が読み込み表示のままになる

署名済み Mac アプリを使い捨ての認証済み Linux VM で起動すると、最初に
LLM 設定を開いたときに読み込み表示が残った。アカウント画面を開いて
LLM に戻ると、空の一覧が表示された。Gemini のフォームでは接続先と
空のキー欄を確認できた。

読み込み画面はワークスペースの所有者判定を使う。初回は所有者の比較で
処理が打ち切られ、監視対象のストアを読まない。そこで、初回のストア作成を
SwiftUI が検知できなかった。ストアを読んでから所有者を比較し、初回の
作成を画面に伝える。同じ所有者での再表示、所有者変更、ログアウトの扱いは維持する。

回帰試験では空のワークスペースで同じ判定を監視し、最初の作成時に変更通知を
受け取ることを確認する。実機では新しく起動した署名済みアプリで LLM を
1回だけ開き、画面を移動せずに「新規」が表示されることを確認する。

変更通知の回帰試験は修正前に失敗し、修正後に通った。署名済みアプリで、
日本語と英語のどちらでも初回に「新規」が表示された。日本語で5つの選択肢を
開き、通信形式、接続先、空のキー欄と無効な保存ボタンを確認した。下矢印と
Return で先頭を選び、Escape でフォームを閉じられた。

英語を選んだときも作成とローテーションのシートが日本語になる問題を
併せて確認した。両方のシートに親画面の表示言語を渡すよう変更した。
再度署名して起動し、英語の Groq フォームとローテーション、日本語に
戻した後のカスタム設定を確認した。一覧は空のままだった。固定ブラウザ版は
ログイン画面に戻ったため、比較には固定ソース、保存済みの操作項目と画像を使った。
現在の認証済みブラウザ画面での操作と VoiceOver は未検証。
