# 通信履歴の入力処理の回帰予防

## 証拠・再現
固定ブラウザ版は6つの独立したタイマーを持ち、数値化した値だけではなく適用済みテキストを比較する。最初のRED5e5b39dは処理型が未実装のため意図したコンパイル失敗であり、実行時不具合の再現ではない。実装17d094bで14件、追加b0a593cで17件が成功した。追加試験は実際のTrafficStore.configureの受理／拒否を含み、通信は行わない。コンパイル失敗から製品不具合を主張しない。

## 分析
予防的5 Whys：履歴ページが意図せず戻る原因候補は未反映入力と適用済み入力の混同。その混同は即時操作で全欄を反映する設計に繋がる。単一の更新番号では別欄の入力待ちも取り消す。Stringの等価比較ではNFC/NFDの違いを見失う。数値だけの比較では1→01の適用変更を見失う。したがって原文／適用済みの識別を分離し、欄ごとの更新番号を保持する。これは画面接続前に試験した回帰候補であり、インストール済みアプリで発生した障害ではない。

Fishbone：時間—独立チケットと実タイマーの区別、識別—UTF8と正規等価の区別、検索—文字列と数値条件の区別、所有権—表示と提案採用、受入—純粋処理／ストア設定と実VM／画面の区別。

Timeline：固定ソース契約・英日設計→未実装型RED5e5b39d→14GREEN17d094b→ストア結合17件b0a593c→全試験／カバレッジ・読取専用レビュー。コピーによる提案で、設定拒否後も適用済み状態を維持する。詳細検索解除では古い詳細欄チケットを無効化し、hostのタイマーは保持する。

## 再発予防・限界
古い／再入力／表示更新チケット、Unicode trim、無効／オーバーフロー／逆転範囲、正規化後の無変更、ストア拒否の試験を保持する。画面モデルは現在のクエリーへ一欄ずつ反映し、表示／確認操作の所有権を検証し、受理後だけ同期的に提案を採用する。ストア所有権の更新で他欄のタイマーを取り消さない。実際の300ms、キャンセル、画面描画、定期読取、実サーバー削除、ブラウザ同等性、製品全体の完成はこの記録では証明しない。
