# Findings画面の下書き寿命

## 1. 観測・再現

F3.1の読み取り専用レビューで、`stop -> clearDialog` が未送信の名前・分類・重大度を消すことを確認しました。サイドバー移動時の下書き保持要件に反します。編集を開始し、Unicodeを含む値へ変更し、停止して同じ項目を開き直すと再現します。実画面・ゲスト変更は実行していません。

## 2. 調査

5 Whys: 停止がフィールドを消す→入力がダイアログ後処理に属する→確認と下書きの寿命が同一→初期設計が一つのダイアログ寿命だけをモデル化→停止試験が検索文の保持しか観測しなかった。Fishbone: 状態所有権（確認と入力の結合）、ライフサイクル（停止とログアウト）、試験（検索のみ）、UX要件（保持）、通信（無関係）。Timeline: 未実装APIのRED→11件成功→レビュー指摘→編集値の回帰RED→独立した下書き保持でGREEN。

## 3. 修正

未送信かつ結果不明でない編集だけを、認証セッションと独立Finding IDに結び付けてウィンドウのメモリに保持します。停止では確認権限を無効化します。明示的に開き直した時だけ新しい確認を作り、一致する下書きを復元します。キャンセル・ログアウトで破棄し、送信済み・結果不明の編集は再送可能な下書きに戻しません。永続化や自動送信はしません。

## 4. 検証

対象回帰でFEFF/NFD/CJKの入力・重大度、古い確認IDの拒否、新しい表示所有権、明示キャンセル、認証リセットを確認します。別IDへの混入と送信済み変更の除外も追加します。全回帰と再レビューの実行結果はfindings-screen-verification.mdへ記録します。

## 5. 再発防止

入力と実行権限の寿命を分けます。サイドバー・言語切替では編集値、古い確認拒否、IDとセッションの境界、保留中変更の排他を試験します。実画面・ブラウザ・キー操作・AXは手動ロック解除後の必須試験です。
