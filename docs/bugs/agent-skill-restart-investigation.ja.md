# 再起動で復活する既定スキルの調査

固定版 `e75ae371ad777ffd1eecdd28d2781a6519b05591` で Worker から `api-recon` を解除し、解除を読み直した後、同じ PostgreSQL DB でバックエンドを再起動します。再び読むと紐付けが復活します。運用者が外したスキルがエージェントの候補に戻る問題です。

解除 API は行を削除します。起動時の処理は毎回既定の行を追加しようとします。衝突を避ける条件が守るのは存在する行だけです。既定スキルの初期化完了を記録していなかったため、削除された行と初回の未設定を区別できませんでした。従来の検証では同じ起動中に読み直していたため、再起動を挟んだ変化を見逃していました。

専用ゲストは、既定の行と初期化完了マーカーを同じトランザクションで書き込みます。固定版はスキル設定の後、リクエストを受け付ける前にインターセプトの初期化を行います。その完了マーカーがある DB は、紐付けがない状態も含めて現在の値を移行します。旧版の再起動ですでに復活した紐付けについては、過去の解除を推定できません。

再発確認には同じ DB での再起動を使います。新規の専用ゲストと、固定版で解除してから移行する場合を両方試し、別のエージェントの既定紐付けも確認します。固定チェックアウトと再現結果を比較用に保持します。今回はゲストの DB 修正なので Lazyweb は対象外です。

専用 Linux arm64 バックエンドで Go テスト383件が成功し、251件のスキップを記録しました。PostgreSQL の使い捨て環境では、新規の専用 DB と、固定版で解除してから移行した DB の両方で解除が保持され、Auto の既定紐付けも確認できました。署名済み Mac 診断版は Apple Virtualization 上で解除し、同じディスクで再起動しても外れたままになることを確認しました。クラウド通信の合成試験では4プロバイダーのモデル取得とチャット、およびキャンセルが通り、ネットワークアダプターと共有フォルダはどちらも0でした。検証用 VM を停止し、一時状態を削除しました。[検証データ](../../evidence/agents/seeded-skill-restart.json)

署名済みローカルプレビューに検証済みの cloud6 ゲストを組み込みました。Mac バイナリがゲストのマニフェストを照合し、リリース署名も検証できました。マニフェストの固定値を変更する前の Swift 全体試験は1,084件成功し、既存の1件がスキップされました。最終版の固定値と診断の対象試験は23件成功し、ゲスト関連195件も成功しました。GitHub Actions は利用枠ポリシーに従いスキップしました。固定ブラウザ版は修正前の比較基準として使います。
