# MCPのタスク使用量がゼロになる参照経路の修正

状態：参照ブローカーで再現・修正し、単体・通信試験と固定DB・APIの比較が成功。署名済みMac画面で選択したタスクのMCP参照、描画したブラウザとの比較は未完。

固定バックエンドは、単体詳細ではトークン集計を設定せず、一覧で実集計値を設定する。ブローカーが詳細を使っていたため、使用量のあるタスクでもゼロを返した。両APIの異なる応答を与える回帰試験で、入力4294967294・出力13がともにゼロになることを先に確認した。

原因の連鎖：詳細DTOに集計がない→ブローカーが詳細を使用→一覧と詳細の値が同じだと仮定→合成試験が詳細にも集計を与えた→初期の実機試験がエージェント一覧と未許可タスクだけで、許可済みの使用量があるタスクを通していなかった。今後は空・拒否ケースに加え、許可済みの実データも比較する。

修正後は事前のタスク許可、一覧GET後のキャンセル・アカウント・VM世代確認を保ち、許可IDに完全一致する1件だけを既存6項目へ射影する。他タスクを返却・保存・ログ出力せず、不在は404とする。ゼロへのフォールバックはしない。選択・非選択、不在、処理中の失効・キャンセル、stdio・ソケットを試験する。モデル設定や推論経路は呼ばない。

診断用データは、新規VMのLLM設定・使用履歴が空のDBへ、終了済みタスクだけを投入する。活動ごとのint4カウンター2件を実APIでInt64として集計する。明示IDとトランザクション対応の採番変更を使い、実固定DBで強制ロールバック時の行と変更対象3採番、再投入拒否、マネージャー再起動後のAPIを確認する。2^53超の通信試験は合成環境のみと区別する。

比較手順で見つかった長すぎる一時パスワード、タスク再読込、snake_case、採番監査の不足は非公開の失敗記録に残す。比較用DockerはローカルDesktop・取得済み固定イメージだけに制限し、ホストポートを公開しない。失敗時も所有ラベルを確認して各資源の削除を試みる。Dockerは固定ブラウザの比較専用であり、Macアプリの実行要件にはしない。

[比較記録](../../evidence/mcp/task-read-metrics.json)。タスク書き込み、外部AI実行、外向きMCP、起動の信頼性、新規Mac登録、画面対応比較は、この修正で完了とはしない。

試験の実行順：Python211件のうち2件が、並行ReleaseビルドのSwiftPMロック待ちでタイムアウトした。Swiftビルド終了後にCLI試験を逐次実行し、初回の失敗を残して該当2件だけ再確認する。タイムアウトを延ばしたり、稼働中のビルドを再起動して合格へ寄せたりしない。

初回の署名済み選択タスク試験は、同じディレクトリの作成前後でURL表現が異なるため、投入前の確認で停止した。ファイルパスの正規化比較へ修正し、該当ケースと拒否ケースの2件を追加した。この試行にカーネル停止はなく、失敗した診断試行として保持する。選択タスクMCPの合格とは扱わない。
