# ネイティブLLM設定：要件・設計・作業計画

## 対象と比較基準

全機能をアプリにする目標を維持します。固定コミットe75ae371ad777ffd1eecdd28d2781a6519b05591のLLM画面を対象にします。一部だけを完成扱いにはしません。出所はpage.tsx、retry.tsx、api.ts、types.ts、server/dto.go、db/llmretry.goです。実ブラウザでも2つの設定カード、新規・ローテーション、モデル設定・再試行タブ、新規フォームの全項目を確認しました。既存の設定やキーは変更していません。

Lazywebで`desktop API key model settings`を検索し、V7 Labs 251005、Knock 252246、Aider 218608の説明情報を参照しました。設定一覧から編集への導線、入力ラベル、有効・健全性の表示、詳細設定のグループ化に反映します。画像を直接確認したとは主張せず、ARTEXの項目と挙動を第一の基準にします。

## 必要な項目と動作

- 一覧：名前、形式、モデル、キーのヒント、制限、プロキシ、思考強度、有効状態、健全性・待機時間、ローテーション時の優先順位・除外。作成・編集・保存・有効化・非有効設定の削除。新規作成だけでは有効化しません。編集でキーを空欄にすると既存キーを保持し、値そのものは取得・表示・ブラウザから移入しません。
- 編集：名前とモデル必須、3つのAPI形式、URL・プロキシ・セッションヘッダー・秘密入力のキー、秒/分の制限、コンテキスト、優先順位・除外、ストリーミング、出力上限とOpenAI専用フィールド名、思考スイッチと強度、設定ごとの3層リトライ。
- モデル取得と接続テスト：本物のAPIを使い、編集時は設定IDを渡して保存済みキーを利用します。通信中と結果を表示し、架空のモデルや応答を作りません。外向き通信は別の未合格条件です。テストは外部課金せず専用データで行います。
- ローテーション：有効・個別設定の代替許可、実際の順序と健全性、単独/全体復旧。画面が開き、有効で異常メンバーがある時だけ10秒ごとに更新します。部分的な設定保存で他の設定を上書きしません。
- 全体リトライ：接続・空応答・ストリーム・遮断・意図再実行の5層。0は既定値、-1は無効。回数[-1,20]、間隔[0,3600000ms]の正規化を合わせます。未保存編集を背景更新で消しません。
- ネイティブのエラー・通信中表示とキーボード操作を用意します。一時障害では既存データを保持して古い表示であることを示し、取得失敗を空データと誤表示しません。生のエラー本文やキー・プロキシ資格情報はログに出しません。

## 設計

ArtexCoreに型付き応答、全項目を送信する検証付き編集データ、認証付きJSONアダプター、サービスと状態管理を置きます。応答の文字列IDと更新時の数値ID、snake_caseを明示的に扱います。応答モデルにはキーのヒントだけを持たせます。入力したキーは画面の一時状態と認証付きvsock通信に限定し、ホストの平文ファイルに保存しません。SwiftUIに一覧・編集・ローテーション・リトライ画面を分け、ログイン後に接続します。比較表は実操作・画面と一連のテストが通るまで未完了のままです。

## 作業順とテスト

1. 型・編集データ：全フィールド、既定値、3形式、空キーでの保持、ID、入力正規化、数値、OpenAI専用上限、ヘッダー改行拒否、リトライ制限、キー非表示。
2. サービス：認証付きの一覧・保存・有効化・削除。有効設定の削除拒否、401/503/不正JSON、失敗時の一覧と編集保持、モデル取得/テストのIDとパラメーター、部分設定保存、全体リトライの読み書き。
3. 画面：取得中・空・エラー・設定ありと全編集項目、ローテーション、全体リトライ。ブラウザ版と項目を照合し、プレースホルダーや操作不能状態を合格にしません。
4. 実アプリ・VM：同じデータでCRUD・有効化・キー保持・リトライ・ローテーションと再起動後の保存を確認し、別の使い捨てブラウザ環境とAPI結果を比較します。キーなしの失敗も外部通信せず検証します。
5. 実クリック・キーボード・画面対比較、サイズ変更、明暗、アクセシビリティ、未保存編集、キャンセルと通信中断。ネイティブ操作ツールの障害中は内部診断でこの条件を代用しません。
