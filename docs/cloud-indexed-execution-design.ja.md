# 番号付きツール実行とプロセス再起動

固定ChatAgentは、モデル文脈をnormaの履歴ファイルへ、表示用活動をPostgreSQLへ保存する。実際のエージェントとHTTPプロバイダーを別々のLinuxプロセスで起動し、同じ履歴ディレクトリを使う。模擬プロバイダーは一時ファイルの固定Readを1回要求し、呼び出しID・引数・署名と結果を照合する。初回プロセス終了後に一時ファイルを消し、次のプロセスに同じ履歴の再送を要求する。ストリーム有無の両方で完了し、復元側ではツール実行0件と履歴追記を確認する。通信は外部接続なしのビルド内ループバックに限定し、子プロセスでも固定形式のURLを検証する。

署名イベントで実行側の不具合が表面化した。実行側には履歴とは別の逐次バッファがあり、引数以外のイベントで即座に確定する。引数より先に署名が届くと、履歴には正しい引数が残ってもReadは空の引数で実行される。交互に届く番号付き引数にも同じ乖離がある。番号付き呼び出しは、応答終了イベントとツール使用／通常終了の理由を受けてから、既存集約器が組み立てた同じブロックを開始順に実行する。番号なしの実行時期とテキストの逐次表示は従来どおりとする。ストリームエラーや未完了の呼び出しでは保留中のツールを実行しない。権限判定と並行実行ポリシーは既存実行器に委ねる。

固定norma v0.4.3へ独立した管理パッチを適用する。実ChatAgentのプロセス試験、交互引数・中断の回帰試験、関連パッケージ全件を外部通信なしで実行し、新しい版のLinux本体をビルドする。このプロセス試験で履歴復元と再送を確認し、次の受け入れ条件は専用VMと通常チャットAPIを使った状態ディスクの再起動試験とする。

レビュー後の条件として、通知前に番号付き引数の生JSONとIDを全件検証する。早い引数は対応する開始に結合し、未対応の断片があれば拒否する。すべての通知が受理された後にまとめてキューへ入れる。キュー処理とセマフォ待ちはそのターンの実行文脈を使い、権限フックの後にも再確認する。中断結果が発行済みなら、後から完了してもその結果を維持する。
