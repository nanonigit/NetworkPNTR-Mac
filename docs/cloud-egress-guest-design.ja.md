# クラウド中継用vsockのLinuxクライアント

管理対象バックエンドは `ARTEX_MAC_CLOUD_EGRESS=vsock-v1` の指定時に中継を使う。未指定の場合は既存の通信方式を使う。不明な指定、カスタムプロキシ、カスタムセッションヘッダーは中継で拒否する。モデル一覧とプロバイダー実行の両方で同じ切り替えを使う。この段階ではクライアントをビルドし、ゲスト起動時の有効化は署名済みVMの検証で行う。

HTTPSのホスト、ポート、メソッド、パスを照合して操作を選ぶ。URLのユーザー情報、エスケープしたパス、クエリ、フラグメント、Hostの上書きを拒否する。所定のキー、ストリーム指定、上限付き本文だけをホストCID 2のポート8790へ送る。ファイル記述子はノンブロッキング、close-on-exec、期限付きとする。キャンセルで接続を閉じ、IP通信への切り替えは行わない。

応答は逐次読み取る。完了フレームだけを正常なEOFとして扱う。JSON本文やOpenAIのSSE完了マーカーを受け取ったあとでも、中継の完了前に切断した場合は失敗とする。管理対象SDKはSSE完了マーカーのあとも中継の終端を確認し、モデル一覧は読み取りエラーを検査する。中継の制御情報をプロバイダーのHTTPヘッダーとして扱わない。

要求の一部でも中継へ届いた可能性がある場合、フレーミングや通信の失敗を結果不明としてGoのエラーに保持する。SDK、タスクのルーティング、ワーカーの再試行判定では同じ要求を再送しない。ステータスに基づく再試行は、非200応答や割当量の記録経路でも、中継の完了フレームを受け取った場合に限る。
