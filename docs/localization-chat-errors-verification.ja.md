# Chatエラー言語対応 — L4b

## 再現と証拠収集

L4aで明示言語の表示処理を作りましたが、Chatのstoreはまだ表示済み日本語を保持しており、表示中エラーは言語選択に追従できませんでした。ソースから表示境界の不足を確認した段階で、このチェックポイントで実画面の再現をしたとは主張しません。

`96eae3e`は型付きstore値の未実装を確認した意図したコンパイルRED。既存pickFiles APIとuploads/パス契約にfixtureを直してから正式REDを実行しており、最初の試験設定ミスは製品の不具合として数えません。`0796897`で同じ3試験成功。スクリプト応答のtransportを通した実ChatServiceで、送信失敗時の混在本文／添付復元、日英文言取得による通信再実行・会話選択変更なしを確認。一覧／履歴／workspace／添付の言語取得、未知の引用検索失敗からの秘密除去、本文取得失敗時の元summary保持も確認しました。

## 分析

5 Whys：エラーが切り替わらない→storeが表示済み文字列を保持→catch時に表示処理→そこにはlocaleがない→理由の識別を保持していなかった。Fishbone：値の識別・observable所有者・会話別辞書・世代／キャンセル判定・localeに応じるview表示・任意backendデータの安全性。Timeline：現状調査→Lazyweb隣接証拠→要件／設計／計画→fixture訂正→意図したRED→安全な型付き保持とview表示→GREEN→レビュー／全試験／coverage→署名ビルド。実画面比較は延期。

## 修正

AppErrorMessageは閉じたBackendAPIError／ChatUploadBodyErrorまたはカタログキーだけを保持。未知のエラーは直ちに安全なfallbackへ変え、詳細やパスを保持しません。Chat一覧／履歴／変更操作／workspace／添付／引用／本文はこの値を保持し、詳細シートも含めviewの現在localeで表示します。診断／旧利用箇所には従来の日本語String計算プロパティを残しました。言語に基づくviewの再作成や新規taskは追加せず、世代・lifetime・キャンセル・所有者判定と会話別エラー辞書を維持。静的fallback4文言を日英カタログへ追加。レイアウト／再試行動作は固定ブラウザを基準とし、Lazyweb検索`chat error retry message`は隣接DoorDashメタデータのみ（類似度.385）。視覚比較の証拠にはしません。

## 検証と再発防止

Swift全246件（成功245・既存AX1件スキップ）、Python52件成功。AppErrorMessage行13/13・領域11/11。最終署名アプリのビルドと厳格署名検証成功、各言語33項目のerror同梱文言は元カタログと一致。読み取り専用レビューで所有者保持／localeによる表示のみの変更を確認。回帰試験と互換カタログの差分検査で境界を守ります。

ネイティブ操作ツールが「Macロック中、自動解除不可」と返し、ユーザーは後で解除すると回答しました。新規VM／ブラウザfixtureは開始せず、新規ネイティブ画像も取得していません。native／browserの失敗送信中の言語切替は未検証です。解除後に実画面でエラーの切替と本文／添付／カーソル／選択保持を確認する必要があります。以前のL3画像は当時のエラーなし切替だけの証拠です。認証／LLM／ダッシュボード／runtimeエラー、backend言語同期、初期会話名の出所、IME／VoiceOver、未実装画面と全21機能の受け入れは引き続き未完了です。
