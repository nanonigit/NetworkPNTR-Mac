# T15 アーカイブ操作状態

固定e75ae371のアーカイブ・復元・削除・再試行とT13通信契約を参照する。画面レイアウトは扱わずLazywebは範囲外。操作時点のタスク・アーカイブIDと利用者の文字列を捕捉する。単体ライブ操作は継承ブロックを確認する。一括は停止・完了・失敗・タイムアウトかつ未キューを抽出し、依存順はサーバーに任せ100件上限。復元・削除は対応する状態だけを抽出し入力100件上限、対象1件なら単体、それ以外は一括。再試行は失敗行1件に限定し元の操作を選ぶ。通信やホスト権限は拡大しない。

TaskStoreに専用外部チケットを追加しカテゴリ・一括・通常操作と排他する。異なる終了処理で解除できずリセット後も完了まで保持する。TaskArchiveStoreも変更チケットで古い取得を無効化し、設定・選択・更新を止める。送信前に両方を確保し、リセットによる結果破棄を含め終端で解除する。202で行を消さず状態を先取りせず、終了時に再取得が必要とする。

TaskArchiveWorkspaceは不変コンテキスト、単一ワーカー、送信済みフラグ、受付・拒否・不明・未開始の各結果、不明タスク/アーカイブIDと捕捉した明示確認を保持する。停止ではキャンセルと閉じる処理を行うが不明結果を保持する。リセットは世代を替え古い結果を捨てるが、旧処理が終わるまで次を開始しない。送信前キャンセルは未開始、送信可能性があれば不明。型付き入力と400/401/403/404/409/413/422は拒否、壊れた2xx・通信・その他状態は不明。自動再送せず明示確認で捕捉IDだけを解除する。送信は一度のみ。

単体の復元・削除応答はアーカイブIDだけでなく捕捉タスクIDも照合する。一括は通信層で集合と並び替えを検証し応答順を保持、成功した復元だけを捕捉IDに紐付けて追跡する。復元再試行も追跡し、それ以外は追跡しない。202でライブ行を削除しない。有効なライブ一括応答は部分成功・成功0件でもブラウザ方針どおりチェック選択を消す。現世代にだけ通知する。書き込み中はアーカイブ選択を止め、有効応答後に選択解除する。復元後の消失通知は別の詳細404が必要で、実ジョブの成功・永続性は未確認。

ゲート排他・リセット・取得所有権をRED/GREENで開始し、保留送信の捕捉・重複禁止・並び替え部分成功・各再試行・状態と上限・ID不一致・不明確認・前後キャンセル・停止とリセット・画面モデル排他を試験する。MUSUBIの回帰予防はソース証拠→不正順序→ガード→レビューと全検証→保持テスト。確認画面・タブ・操作部・一括結果UI、VMとブラウザの実ジョブ・永続性・英日UI受け入れは未完了。
