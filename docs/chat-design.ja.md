# ネイティブチャット：要件・設計・受け入れ計画

状態：C1の有限APIと状態管理を実装し、C2の基本CRUDを比較済みです。チャットUIと全機能の同等性は未完了です。ブラウザ基準はe75ae371ad777ffd1eecdd28d2781a6519b05591に固定します。

## 設計前の根拠

ブラウザのchat/page.tsx、API・型・履歴統合・送信キー・横質問・Transcriptと、サーバーのconversations.go・chatupload.goを確認しました。実ブラウザの/chatでは会話一覧、新規会話、エージェント絞り込み、Autoの説明、添付、入力欄、DefaultのLLM選択を確認しています。基準画像はevidence/chat/browser-empty.pngです。エージェント選択を開閉しただけで、設定変更・会話作成・送信はしていません。利用者の既存タブとデータは保持しています。データ入りの比較は使い捨ての環境で別途行います。

UI設計前にLazywebを利用し、Jasperのチャット例を実画像で確認しました。継続表示するナビゲーションと添付・入力のまとまりは、ARTEXにもある構成を補足する参考です。挙動の仕様はARTEXを優先し、Jasperの現在の機能を保証するものではありません。参考：https://www.lazyweb.com/agentic-search/c0217a77-d95c-4e68-b7e9-6b818ca2ea7b。Growth Reportは依頼・生成していません。

## 必須要件

C1. 新規会話の下書き、エージェント・LLM選択、絞り込み、ピン、エージェント別の折りたたみ、実行中表示、名前変更、単体・一括削除の確認と部分失敗を維持します。ブラウザは一覧を100件単位で表示しますが、APIの一覧自体はページ分割しません。一時的な取得エラーで選択中の履歴を消しません。
C2. ユーザー・本文・思考・結果、対応するツール入力と出力、エラー、利用量、intent/round、LLM切替・フェイルオーバー、承認要求を扱います。詳細の遅延取得、Markdown・コード・添付・Todo・トークンと所要時間・出典への移動を維持します。未知のイベントを黙って隠しません。
C3. 履歴は200件単位です。seqで重複を除き、新しい同一seqで置換し、昇順に並べます。実行中の差分は1秒、一覧は2秒の重ならないポーリングです。最後の差分を取得する前に完了扱いにしません。選択変更・ログアウト・VM停止で古い要求を取り消し、遅れた応答が別の会話を書き換えないようにします。
C4. EnterまたはCtrl/Cmd+Enterの送信設定、Shift+Enter改行、日本語IME変換中の誤送信防止、失敗時の下書き・添付の復元、二重送信・停止の抑止、最下部にいる場合だけの追従、過去履歴取得時のスクロール位置を維持します。下書きで添付すると会話が作られるため、入力を引き継ぎます。
C5. 明示的に選んだファイルの内容だけをVMへ転送し、ホストのフォルダー共有・シェル実行・モデルへのホストパス送信を行いません。上流はmultipart要求全体で128 MiBが上限です。現行JSON通信の4 MiB上限では同等性を示せないため、別の上限付きストリーミング転送、取り消し、切断・超過検査、後始末が必要です。通常JSONの制限は維持します。
C6. @引用、/btw横質問の履歴・冪等ID・キャンセル・再試行・下書き復元・消去、スナップショットとモデル・処理段階、承認の現在状態・履歴・実行元への移動も対象です。通常会話はポーリングですが、横質問はSSEと2秒の履歴照合を使います。有限JSON通信だけでは実現できず、動かないボタンで済ませません。
C7. 認証情報はゲスト・Keychainの内部に保持し、ログに出しません。当初のNIC・共有0を維持します。実クラウド通信は別途審査した外向き通信制御が必要です。ローカルの模擬プロバイダーを使う場合も専用ゲスト内だけで動かし、模擬結果をクラウド対応の合格にはしません。

## ネイティブ構成

既存のFeatures/Systemナビゲーションの中に、幅を調整できる会話一覧と履歴・入力の2列を置きます。並び順とグループ、下部の入力欄を維持し、既存の文字・色・操作部品とアクセシブルな名前を使います。最小ウィンドウでも一覧と入力を使えるようにします。

ChatConversation/ChatActivity/ChatAttachment/ChatHistoryPage/ChatDelta/ChatBatchResultでJSONキーとnullを正しく扱い、有限APIは既存の認証済みBackendJSONClientを利用します。ChatStoreが選択・下書き・履歴・世代番号・キャンセルを管理し、履歴統合・グループ・ピン・ページは純粋関数にします。添付とSSEは上限付きの別インターフェースを先に作ります。MarkdownからHTML・スクリプト・コマンドを実行しません。

APIは一覧・作成、名前とピンのPATCH、単体・一括削除、profile変更、messagesの履歴before/limitと差分since、メッセージ詳細、送信、stopです。添付・引用・side-questions・events・cancelと承認の詳細仕様は各工程で再確認します。正確なルートとソース参照は英語版chat-design.mdにまとめています。

## 工程と合格条件

1. C0：読み取り専用の空画面の基準取得は完了。使い捨てのデータ入り基準と操作・イベント対応表は未完了。feature-mapはpendingのままです。
2. C1：先に型・サービス・履歴統合・状態管理のテストを作ります。null・未知イベント・クエリと本文・秘密を出さないエラー・重複と逆順・カーソル・一括部分失敗・要求の重複と古い応答を検証して実装します。
3. C2：実ゲストと固定ブラウザ版の同一データでCRUD・ピン・LLM変更・201件以上の履歴・重複差分・実行中から最終状態・不正データを比較します。選定したソースカーネルで署名済みアプリも使います。
4. C3：一覧・履歴・入力欄を実装し、成功・空・読込・失敗・検証・保存・再起動・キー操作を実クリックで比較します。下書き失敗・停止との競合も必須です。API比較だけでは合格にしません。
5. C4：添付の境界と切断、引用、SSEのUTF-8・チャンク分割・再接続・キャンセル、横質問の冪等再試行・履歴と消去、承認と出典、Markdown・ツール詳細・Todo等を確認します。実クラウド通信前に通信・セキュリティをレビューします。
6. C5：選んだ実クラウドAPI、許可外通信拒否、ホスト実行なし、大量履歴・添付、日本語IME、VoiceOver・フォーカス、明暗、リサイズ、終了・再起動まで確認します。ブラウザにある操作と失敗時の挙動を照合し、未実施項目を明示します。

この計画によって、VMの長期安定性、配布・ライセンス・署名、残りの製品機能の条件を外すことはありません。

## C1の通信・状態管理で守る条件

ChatServiceでは正の会話・プロファイルID、正確な変更キー、既定プロファイルへ戻す明示的なJSON nullを使います。一括削除は上流同様にIDを重複排除し、要求した全IDに対する一意な結果を確認します。結果はid/okだけを保持し、バックエンドの生エラーを表示しません。nullの配列は空に正規化しますが、必須の配列キー欠落・型不正・不正な確認応答を成功扱いにしません。履歴はブラウザと同じ200件単位、差分カーソルは後退させません。送信のaccepted、停止のidle/stoppingを区別し、停止要求だけで実行終了とは判定しません。添付・SSEは後続です。

ChatStoreは一覧と選択会話の要求世代を管理し、各世代の一覧・履歴・差分要求を重複させません。会話切り替えで古い履歴・差分を無効化し、停止・ログアウトではすべてを無効化します。失敗時は一覧・履歴・下書きを維持し、過去ページと重なる新しいイベントを保持します。running=falseの最後の差分も先に取り込みます。送信成功後は送った内容と一致する下書きだけを消し、再取得だけの失敗で二重送信を誘発しません。ポーリングは完了後に待機し、一覧2秒・実行中の差分1秒で、切り替え・キャンセル・ログアウト時に止めます。要求と待機を制御する単体テストを先に行い、実ゲストとブラウザ版で通信を比較してからUI同等性を判定します。

## C1更新とC2の現在地

有限サービスと状態管理を実装し、C2の基本CRUDを署名付きアプリのVMと固定参照サーバーで比較しました。送信などの成立後は差分の変更世代を更新します。古い差分は履歴を統合しても新しい取得要求を終了できず、完了後に同じ通信枠で再取得します。送信成立後に一覧更新をawaitした後も、生存世代とキャンセルを確認してから差分を取得します。ローカルの停止では、明示的な再開後に最終履歴を取得する要求を保持します。開発者向け--chat-diagnosticsと--kind chatの比較は基本CRUDと空の履歴に限り、201件以上の実ゲスト履歴、実行中の遷移、UIの条件は未完了です。

C2データ入りfixture：使い捨ての会話Native chat history fixtureだけが存在し、活動・タスク・検出結果・資産が空であることを条件にします。AIを動かさず205件の固定イベント（ユーザー、対応するツール入出力、未知の種類、使用量、テキスト、最終結果）を挿入します。最新200件と過去5件、詳細の遅延取得、カーソルと未知イベント保持を検証します。別の条件付きトランザクションで6件を追加し、停止後の最終差分を取得します。参照環境の専用PostgreSQLにも同じSQLを入れ、独立したHTTP検証で比較します。機密情報は参照コンテナの一時状態だけに置き、import/ホスト実行は副作用の前に拒否します。実行中停止・AI応答・UI・クラウドの合格ではありません。
