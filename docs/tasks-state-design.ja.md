# タスクT2 — 状態とライフサイクル

T1 TaskServiceを使うMainActorのObservable TaskStoreを実装します。画面変更・機能状態昇格はしません。固定ブラウザe75ae371ad777ffd1eecdd28d2781a6519b05591では10秒ごとに一覧を取得し、取得失敗時は前データを保持、変更後に再取得します。ネイティブ側は安全な翻訳エラーと古さも公開します。詳細を開くのは読み取りであり、/api/activeへPOSTしません。試験で実ユーザーのバックエンドやホスト上のAIを実行しません。状態処理のみなのでLazyweb対象外です。

一覧/詳細に値・取得中・失敗・古さを持たせます。選択IDを正規化し、選択変更時は古い詳細を即座に消し、選択世代を更新して旧応答を無視します。同じ正規IDの再選択では既知の値を保持して再取得できます。読み取りは別々のUUIDで識別し、変更操作/停止/リセットで旧応答を無効化、取得中フラグを解除します。取得失敗時は値を保持して古いと示し、キャンセルは通信エラーにしません。同じ状態の取得を重複させず、古いdeferが新しい取得中を解除しません。

ストア内で作成/名前・ピン変更/制御/一括/削除を1件ずつ実行し、処理中の読み取りに優先できます。自動再試行はしません。結果はnotStarted（処理中/開始前キャンセル）、rejected（送信前の型付き入力拒否）、confirmed（T1で検証済み）、unconfirmed（開始後のエラー/キャンセル）、discarded（認証世代リセット済み）に分けます。現在の認証世代だけが結果とエラーを保持し、確定操作と再取得失敗を分離します。再取得だけ失敗しても操作結果は確定です。不確定はUI/ユーザーが照合し、取り消された証拠とみなして再試行しません。通信エラーだけではサーバーへ届いたか判定できません。

対象ID付きの型付き確定結果、安全な操作エラー、不確定フラグを保持します。明示的な次操作がゲートを取得してから前の通知を消します。選択変更で処理対象を変えず、作成したタスクを勝手に選択しません。削除確定では該当IDだけを一覧から除き、一致するアクティブ/選択を消し、先行する旧取得で復活させません。その他の確定では新しい一覧を得るまで集計データを古いまま保持します。メタデータ/詳細応答の集計値は0なので、そのまま一覧を置き換えると集計を失うためです。一括の部分結果をUI用に保持し、失敗項目も自動再試行しません。

停止は読み取り/ポーリングを無効化しますがキャッシュを保持し、操作が終わる前に変更ゲートを解除しません。停止後の操作確定は保持しますが背景再取得を始めません。リセットではユーザーデータを消して認証世代を変更し、処理中の変更ゲートは終了まで保持、旧結果を公開せずdiscardedにします。今後の画面連携では1ウィンドウ/認証セッションがストアを所有し、サインアウト時にリセット、未完操作の終了まで保持する必要があります。複数ストア間やサーバーの冪等性保証ではありません。

ポーリング所有者は1つで、即座に読み取り後10秒待機し、一覧と選択詳細を更新、各await間で所有/キャンセル確認、自分の世代だけを終了します。試験では待機を注入し、実時間頼りの競合試験を避けます。遅延応答を制御し、順序逆転、操作と旧読み取り、停止/再開/リセット、確定後取得失敗、不確定キャンセル、重複抑止、全有限操作、アクティブ化なしを検証します。実比較、ダイアログ/下書き/絞込/並べ替え/選択UI、永続化、高度タスク機能、全21機能の受入は継続します。
