## 操作と所有権

既存詳細シートのコピー付近に、現在の要求／応答を明示した「元データを保存」を追加する。検証済みの稼働ゲストが管理版メタデータ・転送を扱えるときだけ提供する。能力は互換性の検査であり認証・安全性の例外ではない。GuestArtifactsは現状追加フィールドを無視するため、view内でJSONを読むのではなく能力契約と伝播を実装・試験する。未対応では本文表示を使える状態に保ち、動かない保存ボタンを出さない。今回通常ゲストを昇格しない。

保持するTrafficBodyExportModelでウィンドウ提示lease、TrafficStore所有者、ID生バイト、詳細revision、選択side、保存UUIDを固定する。メタデータ取得、保存先選択、ステージング、公開の前後で再検査する。TrafficServiceの構造化情報をID／sideと照合し、AuthenticationSessionの型付き転送と上書きしない整合性レシートを使う。表示本文の@blob、ゲストのファイル名、記録URLを信頼せず、元データを文字列変換しない。本文なし／未対応sideで公開しない。

取得・転送中は不定進捗の「保存中」と「保存をキャンセル」を表示する。現在の転送APIには進捗通知がなく、割合を捏造したりファイル長で推定しない。保存中のside変更・二重保存を防ぐ。パネル取消は通常の終了。明示取消、詳細を閉じる、ウィンドウ消失、画面遷移、認証リセット、VM所有権喪失で操作を失効させ、子タスクとパネルを取消し、遅れたレシートを破棄する。所有者のないバックグラウンド公開を残さない。コピー・折返し・本文表示は読み取り状態が有効なら維持する。整合性確認後の公開だけを成功とし、清掃失敗は通常取消と分けて表示する。

既存のウィンドウ付き保存先選択・レシートを再利用し、Finding保存を弱めない。清掃が終了するまで旧所有者を保持し、旧タスクが新操作を消さない。実際の送信／公開直前をMainActorで検査し、最終検査と公開の間にawaitを挟まない。観測通知からの再入も既存のqueued stop/resetと整合させる。終了した画面・セッションの生本文を残さない。

## 実装・受け入れ順序

1. 能力契約: 通常／不明／欠落／管理版、検証済みプロファイル、VM epochとリセット伝播を試験。未対応でもviewerは利用可能。
2. ModelのTDD: 遅延メタデータ、ID生バイト／side不一致、パネル取消・遅延応答、二重操作・再入、side／選択／ウィンドウ／認証／VM失効、遅延200／401／レシート、清掃失敗、成功・取消。実一時ファイルで公開を検証しFinding試験を維持。
3. root／詳細への接続: 詳細所有者ごとのmodel保持、パネルanchor、取消・状態、日英キー、生データ保持。Lazywebは状態・取消配置だけの参考。
4. 全試験・ビルド・署名と、model経由の実管理版VM保存。本文表示・コピー・折返し・Finding保存は固定ブラウザと別々に比較する。実ウィンドウ・パネル・キーボード・複数画面・VoiceOverは解除後まで未完。ロック解除を再要求せず、画面外の描画を入力受け入れにしない。
5. ゲスト昇格は別のkernel安定性・来歴・runtime・release条件通過後。Gemini／Groq CP1–CP4とharness H0–H5も継続。
