# エージェント一覧の検証

Mac 版のエージェント画面は閲覧専用で、稼働中のゲストへのサインインが必要です。`GET /api/agents` の順序を保ち、組み込み／カスタムと無効の表示、エージェントのキー、説明、MCP・スキル・ツールの件数を表示します。件数の省略は 0 として扱います。取得失敗時はエラーと再読み込み操作が表示されます。

固定ブラウザ版 `e75ae371ad777ffd1eecdd28d2781a6519b05591` の Agents 画面、エージェントの翻訳処理、一覧 DTO と照合しました。既定エージェント 7 種の名前と説明を含む共通文言は、日英それぞれ 22 件が一致します。ブラウザ版で固定の「Skill」は日本語画面で「スキル」と表示します。Lazyweb の Superhuman Agents の検索結果も、カード内の情報の配置に活用しました。カスタムの名前と説明は入力内容のまま表示します。

署名済み診断ビルドを隔離 Linux VM で起動してサインインし、既定の 8 件を表示しました。並び順と MCP・スキル・ツールの全 24 件数は、別途サインインした使い捨て Docker 参照環境と一致しました。参照環境は認証前に HTTP 401 を返しました。Mac 版で英語から日本語に切り替えて再読み込みしても 8 件が表示され、各カードがアクセシビリティツリー上で独立していました。初回の実機試験で既定のレポート作成エージェントに韓国語が残っていたため、初期値と完全一致する名前・説明だけを翻訳しました。修正版では両言語で翻訳後のカードを確認しました。固定ブラウザ版は初期データの文言をそのまま表示します。

ローカルでは Swift 1,055 件成功、既存の 1 件がスキップ、ゲスト成果物のテスト 195 件が成功しました。リリースビルドとローカルプレビューの署名検証も成功しました。検証用 VM は両方停止し、検証用のキーチェーン項目とゲスト状態、および参照用コンテナとネットワークを削除しました。

通信、表示項目、翻訳、キャンセルは `swift test --filter AgentCatalogTests` で試験できます。生成した翻訳リソースは `python3 script/export_localizations.py --check` で検証できます。

エージェントの作成・削除、詳細、プロンプト編集、設定変更は今後の段階で扱います。固定ブラウザ版と Mac 版の実画面比較、キーボードとアクセシビリティの受け入れ、ホスト版 CI の確認も残っています。
