# クラウド中継の直接接続

検査済みの数値IPに、ノンブロッキングのTCPソケットで直接接続する。TLSの前と、API要求の送信直前に実ソケットの接続先を照合する。接続は要求ごとに作る。ワーカーはホスト名の再解決、プロキシ設定の参照、リダイレクトの追跡を行わない。

Swiftの入口は、生成したCloudEgressRequestと同じホスト名について許可された接続先だけを組み合わせる。各交換のワーカーがTCPソケットとSecureTransportのコンテキストを所有し、別スレッドからキャンセルできる。TLS接続と交換全体を単調時計で制限する。待機中とTLSの入出力処理中にキャンセルを確認し、終了時にソケットを閉じる。応答は上限付きで逐次渡す。HTTP応答のフレーミングの検査、リスナーの同時処理制限、DNSを含む期限、VMの起動停止との連動はvsock層で扱う。

ループバックのTLSサーバーと試験用CAで、証明書不一致、未信頼チェーン、応答待ち、ストリーミング、上限超過、プロキシ設定時の挙動を検証する。Swiftの入口では、要求と接続先が一致しない場合にソケットを開く前に拒否する。既定ゲストのリスナー有効化は、署名済みVMの受入試験で扱う。

SecureTransportのTLS 1.2ハンドシェイクをサーバー認証で一時停止する。Securityフレームワークで固定のHTTPSホスト名と証明書チェーンを検証し、外部取得を無効にする。失効情報はローカルのキャッシュを使える。認証で一時停止しない接続は拒否する。SecureTransportは非推奨でTLS 1.2までのため、利用箇所をこの通信ターゲットに限定し、4社を受入試験に含める。[AppleのSecureTransport資料](https://developer.apple.com/documentation/security/secure-transport)・[サーバー認証での一時停止](https://developer.apple.com/documentation/security/sslsessionoption/breakonserverauth)
