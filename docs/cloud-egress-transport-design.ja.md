# クラウド中継の直接接続

検査済みの数値IPに対し、macOS付属のlibcurlを接続専用モードで使用する。プロキシとリダイレクトを無効にし、固定HTTPSホスト名とポートのDNSを検査済みIPに固定する。ソケットを開く直前にTCPの接続先を確認し、TLSとホスト名の照合後も実ソケットの接続先を照合してからAPIの要求を送る。接続は要求ごとに作る。

Swiftの入口は、生成したCloudEgressRequestと同じホスト名について許可された接続先だけを組み合わせる。各交換のワーカーがlibcurlのハンドルを所有し、別スレッドからキャンセルできる。TLS接続と交換全体を単調時計で制限し、ソケットの待機中にもキャンセルを確認して、終了時にハンドルを閉じる。応答は上限付きで逐次渡す。HTTP応答のフレーミングの検査、リスナーの同時処理制限、DNSを含む期限、VMの起動停止との連動はvsock層で扱う。

ループバックのTLSサーバーと試験用CAで、証明書不一致、未信頼チェーン、応答待ち、ストリーミング、上限超過、プロキシ設定時の挙動を検証する。Swiftの入口では、要求と接続先が一致しない場合にソケットを開く前に拒否する。既定ゲストのリスナー有効化は、署名済みVMの受入試験で扱う。

ソケットの許可リストはlibcurlによる接続を制限する。macOSの証明書検証による中間証明書の取得は別に制御する。本番リスナーを有効にする条件として、TLS実装が証明書取得を明示的に制御できることを確認する。別ホストを指す発行者URLを持つ証明書で拒否を確認し、チェーンが揃った場合の成功も対照試験に含める。
