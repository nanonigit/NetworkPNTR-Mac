# Traffic sort persistence (TR3)

Requirements: match the pinned useStoredSortPreference traffic-sort behavior for ts/status/resp_len and asc/desc, default ts/desc. Persist no query text, packets, hosts, page/size, selection, dialog or credentials. This is state/preferences work with no layout change; Lazyweb is out of scope. Keep complete Traffic binding/blob/VM/browser/UI/release/provider/harness goals.

Use a distinct native UserDefaults key traffic.sort.preference.v1 and optional injected preferences (nil disables storage for existing callers/tests). Store bounded JSON Data with only field/direction, compatible in shape with the browser hook. Validate whitelist and<=4096 bytes; malformed/missing/legacy values fall back to ts/desc. After an accepted restoration canonicalize to the two allowed keys, dropping unrelated input fields. Do not read browser storage or migrate other preferences. Root injects standard app preferences; tests use disposable suites only.

Hydrate on each new presentation, before the initial read. Stop/reset erase transient query/drafts but retain the nonprivate saved sort. If a prior dispatched write still owns the core gate after navigation, defer restoration until that write settles; do not issue a default-sort initial read or enable interactive controls before restoration. Gate release restores the captured preference, then requests the current read. Unknown-write state remains and is never retried/acknowledged automatically. Preserve current-query/lease guards, independent field timers and reset priority.

Only accepted sort controls save; method/status/size and text never persist. Stop/reset during query publication must prevent an abandoned restoration/control from overwriting saved preferences. Preference publication runs inside the existing guarded model transaction; reentrant controls are refused and reset stays prioritized. A native window samples shared preferences on begin, matching the browser hook's mount-only hydration rather than inventing cross-window live synchronization.

Tests first: all6 valid pairs, malformed/oversized/unknown fields and canonical payload, no write before begin, exact default/disabled storage, accepted sort and privacy across reopening/logout, blocked/stale callbacks, Observation stop/reset during save/restore, held-write deferred restoration with no retry/ack. Review, scoped/full tests and coverage, signed build and remote verification follow. Actual UserDefaults permission failures, root activation/visible UI/keyboard/AX and whole-product acceptance remain separate gates.
