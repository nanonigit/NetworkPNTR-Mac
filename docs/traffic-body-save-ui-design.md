## Interaction and state ownership

Add a side-specific Save original action next to copy in the existing detail sheet, with localized request/response semantics. Availability comes from a verified running guest profile supporting managed blob metadata and streaming; guest capabilities are a compatibility gate, never an authentication/security exemption. GuestArtifacts currently ignores those extra fields, so explicitly implement and test capability propagation instead of reading ad hoc JSON in a view. Unsupported profiles retain a usable packet viewer and expose no nonfunctional save action. The normal guest is not promoted by this UI work.

A retained TrafficBodyExportModel owns one immutable detail identity: parent window presentation lease, TrafficStore owner, raw traffic ID bytes, detail preview revision, selected side and export UUID. Capture and revalidate them before/after metadata, destination selection, staging and commit. Fetch structured metadata from TrafficService, verify literal ID/side, then use AuthenticationSession.authenticatedTrafficBlobExport and the existing no-clobber integrity receipt. Never derive metadata from rendered @blob markers, filenames or recorded URLs. Never convert original bytes through text. An unsupported/missing side must not publish anything.

Show an indeterminate Saving original status plus Cancel save during metadata/staging. The transport currently has no source-download byte progress contract; do not show invented percentages or estimate progress from file length. Freeze side switching and duplicate save dispatch while the operation owns the sheet. Panel cancellation is neutral. Explicit cancel, detail close, window disappearance, parent navigation/session reset and VM ownership loss revoke the operation and cancel the child/panel; any late receipt is discarded. Closing must not leave an unowned background publication. Existing copy/wrap/raw display remain available when their read state is valid. Show success only after verified publication; cleanup-required remains visible and distinct from an ordinary canceled operation.

Reuse the window-bound destination chooser and file receipt without weakening finding exports. Retain the last owner until cleanup settles; an old task cannot clear a newer operation. Revalidate owner at actual dispatch/commit under MainActor, with no await between final validity check and publication. Handle reentrant observation callbacks consistently with TrafficScreenModel's queued stop/reset pattern. Never retain stale raw packet/user data after its window/session scope retires.
