# 実モデル一覧 API の認証拒否試験

署名済み DEBUG プローブを使い、検証済みゲストと新規の専用ディスクで通常の
DesktopRuntime を起動する。本番の HTTPS 中継を有効にし、使い捨てのゲスト認証を
初期設定する。4社のプリセットそれぞれで固定の無効値を使い、通常のモデル一覧を
1回ずつ要求する。中継の固定 GET を使い、実キーや生成リクエストは扱わない。
プロファイルやチャットは保存しない。

プロバイダーの応答と VM・通信の失敗を区別する。認証済みゲスト API の応答を、
アプリが一般化したエラーに変換する手前で確認する。記録するのはプロバイダー名、
分類または HTTP ステータスのみ。プロバイダーの拒否、アプリでのエラー扱い、
正常停止は別々に確認する。外部応答が得られなければ未確認として扱う。
応答本文、要求ヘッダー、資格情報は記録しない。画面変更は対象外。

使い捨ての HTTPS 接続では、固定長・チャンク終端・本文なしの応答の境界を
確認した時点で完了できる。受信したバッファ全体を検査してから TLS 接続を閉じ、
再利用しない。切断で本文の長さが決まる応答には、有効な TLS 終了通知が必要。
HTTP 境界に達する前の切断、タイムアウト、キャンセル、不正な応答は失敗とする。
[RFC 9112 の TLS 終了仕様](https://www.rfc-editor.org/rfc/rfc9112.html#section-9.8)
