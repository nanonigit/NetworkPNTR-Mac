# エージェントの終了処理編集の検証

終了処理タブで通常終了時のプロンプトとラウンド数を編集できます。対応するエージェントには案件タイムアウト用の設定欄も出ます。空の本文とラウンド数 0 にはゲストの既定値を使います。ラウンド数は保存先の整数範囲内で入力できます。通常終了、案件タイムアウト、メインプロンプトの下書きは個別に保持します。

保存は認証済みの `PUT /api/agents/{key}/wrapup` と `PUT /api/agents/{key}/wrapup/task-timeout`、復元は各リセット API への POST を使います。ゲスト側では通常終了の本文とラウンド数が別々に書き込まれるため、両方の反映を読んでから成功を表示します。結果が不明な場合は再読み込みを求めます。復元には確認画面を設けています。

`e75ae371ad777ffd1eecdd28d2781a6519b05591` に固定した使い捨て Docker 参照環境では、通常終了の4ラウンドと案件タイムアウトの6ラウンド、およびそれぞれの本文原文を保存できました。案件タイムアウトの復元でその本文とラウンド数が空と 0 に戻り、通常終了の設定は保存済みの値を保持しました。通常終了も個別に復元できました。各欄の構成は固定ブラウザ版を基準とし、入力欄と操作をまとめる配置は Lazyweb の設定画面も参考にしました。

署名済み Mac 版を使い捨て Linux VM に接続しました。負のラウンド数では保存できず、通常終了を4、案件タイムアウトを6ラウンドで保存できました。通常終了の保存中も、案件タイムアウトの未保存の下書きは残りました。案件タイムアウトだけを復元するとその欄が空と 0 になり、通常終了は4ラウンドのままでした。通常終了も続けて復元できました。Mac の操作結果を固定版の API と照合しました。

`swift test --filter AgentWrapUpEditorTests` で送信内容、反映確認、別の欄の下書き保持、部分的な保存失敗を検証します。モデルとツールの紐付け、トリガーの設定、認証後のブラウザ実画面比較は残っています。

Swift 1,075件とゲスト関連195件が成功し、既存の1件がスキップされました。リリースビルドと更新したプレビューの署名検証も成功しました。使い捨て VM を停止し、検証用のキーチェーン項目と状態、Docker 参照環境を削除しました。GitHub Actions は利用枠ポリシーに従いスキップしました。
