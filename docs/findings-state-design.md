# F2 Findings state ownership

Infrastructure/state only; Lazyweb is out of scope. Preserve fixed browser page.tsx preference/filter effects, flat/group cursor states, query fingerprints, 5-second active view/stat refresh, nonpolling asset snapshots and cross-page selectedIds. F1 service remains the wire authority. No native UI/feature acceptance or browser/VM changes.

Compose observable finite FindingReadState<Value> (last-good value/loading/stale/safe error with private request generation) and FindingPageState<Value> (page/size/one corrective read). FindingStore owns separate flat, group headers, tree, stats, detail and each group's page state. Snapshot every query before await. Configure/stop/reset invalidate existing read generations so old responses and their deferred loading cleanup cannot overwrite a new request. View changes retain same-query cached data as stale; changed filters/asset dataset clear affected snapshots. Filters reset all cursors/expanded groups/tree/detail, keep independent stats and cross-page export selection. Selected IDs are canonical standalone ASCII IDs. Use Data UTF8 for raw asset keys and query fingerprints; Swift canonical-equivalent string equality must not merge distinct server scopes. Header ownership constrains group selection/expansion/cursors. Asset scope resets flat page and never enters tree query.

Each active-view refresh serially awaits a captured current cycle and stops launching later reads after ownership changes. Slots suppress overlapping reads independently; expanded loaded visible groups own their pages. Separate view and stats loops with 5-second sleeps are single-flight and stop-safe; asset view performs one initial view snapshot instead of repeated tree polling while stats remains independent. Explicit refresh reloads tree/list when requested. Changing view while a loop is sleeping must reevaluate whether to stop/poll without restarting an obsolete loop. Page correction uses overflow-safe (total-1)/size+1 and at most one corrective request, never recursive polling. A correction is allowed only after the same owned successful read.

A captured mutation validates owner/current visible-or-detail handle, editable provenance, patch/body constraints and pre-cancellation before a service call. Global gate remains held across stop/reset until the exact call terminates. All errors after service handoff, even HTTP4xx, are unconfirmed because pinned PATCH applies sequential fields; never claim rollback or auto replay. Confirmed update/delete changes only captured known caches and retains lastConfirmation across read failures; deletion clears its selection/detail. Unknown IDs block further writes until explicit acknowledgement by captured session owner. Stop invalidates activity, keeps old snapshots stale and uncertainty; late completion in the same session is discarded for presentation and retains unknown ID. Reset rotates session and clears presentation/selection/uncertainty but retains the old in-flight gate until terminal, after which old responses are discarded. No post-stop/reset completion may modify a newer call's gate or data.

RED/GREEN tests must control suspension and reverse response order, filters/view/UTF8 changes, page and group independence/correction, cross-page selection, tree snapshot behavior, stale/error preservation, detail/context races, stop/reset/cancel, old/new poll loop cleanup, successful mutation and failed follow-up read, malformed/4xx/5xx/transport failures, conservative uncertainty, explicit ack, source readonly rows and captured target, paused write across reset. Review/full suites/coverage/signed resources/exact-head CI precede F3 en/ja UI and F4 actual guest/reference. Advanced export/traffic/report/lineage/retest/deepen/native visual/AX/keyboard remain mandatory later gates.

Contextual detail cannot be replaced by a standalone PATCH response: keep its inherited/provenance snapshot stale until a contextual reread. Unknown acknowledgement requires sessionOwner plus a captured unknownRevision, rotated on every uncertainty episode/ack/reset; a delayed acknowledgement for finding7 episodeA cannot release episodeB.
