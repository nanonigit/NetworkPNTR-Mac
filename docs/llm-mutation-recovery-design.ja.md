# LLM書込の所有権と復旧

## 要件

6系統の書込で送信後に結果が不明になった場合、プロファイル重複作成や曖昧な再操作を防ぐ。既存の入力検証と通信契約を維持する。送信前の取消・画面離脱では送信せず、サーバー側の結果不明とも扱わない。送信後に確認できなかった場合は書込を停止する。再読み込みだけでは解除せず、対象の書込が終了してから全設定を取得し、表示中の世代に対する明示的な再開操作を要求する。離脱・復帰で未終了の書込ゲートを解放せず、古い読取応答を受け入れない。確認済み保存は後続の再取得失敗だけで失敗扱いにしない。実キー・自動再送・ホスト上のエージェント実行は使用しない。

## 設計とUI参照

6系統のサービスに内部onDispatchを追加し、既存の公開APIを維持する。書込チケットで活動世代・送信済み・確認済みを保持し、Observationの代入前コールバックによる再入を専用ガードで防ぐ。全設定取得とプール取得は共通の読取チケットで所有し、離脱で途中・遅延応答を破棄する。不明世代は同じ書込について重複発行しない。全取得は書込終了後に開始する必要があり、再開は不明世代と確認済み世代の一致を要求する。

設定画面・編集シート・ローテーションシートに共通の日英復旧パネルを置く。無効化するフォームの外側で、サーバーでは完了済みかもしれないことを説明し、「再読み込み」と別の「現在の設定を確認したので操作を再開」を提供する。再開で再送はしない。入力中の編集内容と既存の一覧・再試行設定を維持し、閲覧・編集画面への移動は可能にする。ストアでも書込を禁止する。設定画面の離脱でstop、復帰タスクでresumeと再取得。接続試験や編集ビューのタスク所有権は別途未完了。

Lazywebのdesktop検索 `settings save error recovery` と `error banner`（2026-10-28）は弱い近似メタデータのみ：DuckDuckGo11407の設定保存・読込、Ring5165のエラーバナー、VaynerX159802の明示的復旧操作。画像の実見や受入証拠ではない。インライン説明と独立した操作だけを参考にし、単なる警告消去や盲目的再試行は採用しない。主な基準は固定版e75ae371ad777ffd1eecdd28d2781a6519b05591のLLM画面と既存のネイティブ操作一覧。

## 実装と受入順序

1. 新しい所有権・復旧API、および送信前後・離脱復帰・古い読取・入力不正・再開世代のRED。
2. サービスとストアを実装し、6系統・Observation再入・終了待ちゲート・確認済み保存後の取得失敗・全取得とプール取得の違いを試験。
3. 3画面に復旧パネルを追加し、日英行列を検証。任意のCJK文字や入力値は維持。
4. 独立レビュー・全体回帰・カバレッジ・署名付きビルド・対象コミットのCI。実画面操作・キーボード・リサイズ・アクセシビリティは手動解除後の未完了条件。

## 画面移動時の所有権の補足

RootViewの条件付き画面は、従来LLMSettingsView内でストアを作り直していた。同じストアのstop/resume試験だけでは実際の画面移動を保証できない。ウィンドウ所有のLLMWorkspaceで認証セッションのオブジェクトごとに1つ保持し、同じ認証中の画面移動では同じストアと不明世代を再利用する。認証の喪失・別セッションでは停止して解放する。ビューは保持されたストアを受け取る。実装前に所有者管理の試験を追加する。アプリ終了をまたぐ永続化ではなく、クラッシュ・再起動後の結果不明の復旧は未検証。
