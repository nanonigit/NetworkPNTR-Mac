# 独立通信画面の紐付け実行検証

元の21機能／VM／ブラウザ／UI／リリース／4社／ハーネス目標を維持。TR3のソフトウェア試験だけでは実サーバー変更を証明できない。既存DEBUG限定CapturedProbeにTrafficStore、FindingService.bindingCandidates、TrafficBindingStoreを追加し、同じループバック由来の実通信29件で検証する。今回はbackend／CLI検証なのでLazywebの画面設計範囲外。画面配置、NIC／共有、ゲスト昇格、外部通信、エージェント起動、クラウド呼出しは追加しない。

既存の新規非公開永続ディスク、Linux／UID1000限定fixture、ソースハッシュ、活動監査、固定コミット、CPU1候補、2回の協調起動停止、固定ブラウザAPIの独立比較記録を再利用。通常アプリのゲストは変えず、2回目は再投入しない。同じホストの29件だけで複数ホスト削除やTR4／TR5全体を証明しない。

固定exerciseは29件／一意ordinal0〜28を確認し、TrafficStoreで25＋4件を取得して元データの識別／メタデータと照合。両ページで選択・解除後、実際の位置を調べてordinal3／4を選ぶ。最大2ページ／20件の候補から正規ID9101を探し、継承／ハンドルなしは変更しない。新鮮な証跡を読み、親クエリー／選択版の送信前判定と単回要求で紐付け、識別・supporting・空注記・順序を確認。再送を拒否し、確認成功後だけ元の選択を解除する。これはTrafficScreenModel／RootView／ネイティブ入力を実行するものではなく、それらの実受入は未完。

既存の検出結果側picker紐付けより先に実行する。その後の同じrefsは冪等になり、正規化された応答／versionが完全一致しなければ失敗させる。余分な紐付け／snapshot／version変更を正規化で隠さない。独立ブラウザ比較用exerciseを変えず、別フィールドに独立通信側proofを追加し、全体成功の必須条件とする。再起動後の元データ／最終証跡／活動監査を維持。

先に模擬通信で固定fixture条件、25＋4、候補ページ、正規ハンドル／既定refs、POST1回／再送拒否／一致選択解除、候補不在／読み取り専用／不正応答／不完全receiptの拒否を試験。RED／GREEN、読み取り専用レビュー、全体回帰、実VMの終了・起動停止・監査を記録。模擬成功だけでは実検証済みとしない。Actions枠方針を維持。
