# エージェントの MCP とスキルの表示設定の検証

Mac のエディターには MCP とスキルのタブがあります。カタログと現在の紐付けを取得し、各チェック欄の変更を項目別の API で保存します。エージェントの ID は詳細から取得し、保存後に紐付けを読み直して表示へ反映します。結果が不明な場合は再読み込みを求めます。変更後に閉じると一覧カードの件数を更新します。

固定ブラウザ版のエージェント編集画面は両方の一覧を一括で置き換えます。Mac 版は固定版のリソース設定画面が使う項目別 API を利用します。これにより別項目の紐付けを上書きすることを避けます。項目と状態を並べる配置は Lazyweb の Conduktor、Square、Hygraph の例も参考にしました。

`e75ae371ad777ffd1eecdd28d2781a6519b05591` の使い捨て Docker 参照環境で、無効な検証用 MCP の紐付けと解除、`api-recon` スキルの解除、他の紐付けの保持を確認しました。同じ DB で参照バックエンドを再起動すると、解除した `api-recon` が再び表示されました。固定版は解除時に行を削除し、起動時に行がなければ既定の紐付けを追加します。既定スキルの解除を再起動後も保持する対応は残っています。検証は設定操作に限りました。

署名済み Mac 版を使い捨て Linux VM に接続しました。Worker の無効な Browser MCP を紐付けて解除しても、ScopeSentry のチェックは外れた状態でした。api-recon を解除し、詳細を閉じると Worker のカードは MCP とスキルがともに0件へ更新されました。Mac 版は反映の読み直しと詳細を閉じる操作まで検証し、再起動後の再登録は固定版の Docker 環境で再現しました。api-recon の同梱説明は中国語で表示され、日英対応の項目として残っています。

`swift test --filter AgentVisibilityEditorTests` で送信内容、反映、エラー時の挙動を試験します。組み込みツールやトリガーの紐付け、MCP とスキルの管理画面、再起動後の保持、認証後のブラウザ実画面比較は今後の項目です。
