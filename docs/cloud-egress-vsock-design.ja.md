# 専用VMのクラウド中継ストリーム

VMのvirtioデバイスにゲスト発のvsockポート8790を割り当てる。1接続は1要求で、起動済みかつ準備完了のVMだけが明示的に有効化できる。アプリ全体で同時処理数を制限し、VMの停止時は中継を取り消してリスナーを外す。ゲストは応答終了まで送信側を開いておく。EOFや余分な要求データを検知したら上流を取り消す。中継専用のIPリスナーは設けない。

要求の先頭14バイトは、ASCIIのARXE、バージョン1、操作ID、ストリーミングを示す最下位ビット、予約の0、ビッグエンディアンの16ビットのキー長と32ビットの本文長で構成する。操作IDの1〜9はOpenAIのモデル一覧・チャット・Responses、Anthropicのモデル一覧・Messages、Geminiのモデル一覧・チャット、Groqのモデル一覧・チャット。先頭を検査してからASCIIのキーと上限付きの本文を読む。ホスト名、URL、ポート、プロキシ、任意のヘッダーは受け取らない。

応答フレームは1バイトの種別とビッグエンディアンの32ビット長で始まる。種別1は16ビットのHTTPステータスと種別1バイト（0未指定、1 JSON、2イベントストリーム）。種別2は最大16 KiBの本文。種別3は長さ0で、唯一の成功終了を示す。失敗や中断では種別3を送らず閉じる。完了はTLSとHTTPの検証で判定する。

上流を差し替え、実ローカルソケットでバイナリ形式とワーカーを試験する。既定で有効にする前に署名済みVMでリスナーを試験する。要求、DNS解決結果の使用、TLS、応答送信に共通の期限を適用する。OSのDNS解決は同期処理のため、キャンセル後も解決が返るまでアプリの処理枠を占有し得る。
