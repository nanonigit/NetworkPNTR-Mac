# Inbound MCP capability contract

Status: core read broker and local stdio/IPC helper pass synthetic integration tests. App-owned authorization/revocation, native consent and packaged real-VM agent reads are verified in a disposable fixture. Selected-task reads, active-client lifecycle, paired browser comparison and clean-Mac client registration remain open.

| Tool | Arguments | Authorization | Shared native service | Execution owner |
| --- | --- | --- | --- | --- |
| `networkpntr_agents_list` | Empty object, no additional properties | Agent discovery | `AgentCatalogService.list`, GET `/api/agents` | External AI; no internal inference |
| `networkpntr_task_status` | Required `id`, canonical positive decimal string, no additional properties | Task status plus exact task ID allowlist | `TaskService.detail`, GET `/api/tasks/{id}` | Read existing task; no inference is started |

Both tool descriptors set read-only and idempotent annotations. These annotations are hints; the app broker enforces the actual route, scope and account/runtime ownership. Account credentials stay inside `AuthenticatedBackendClient`; they are never MCP arguments or output.

Agent responses contain only key, localized name and enabled state. Task responses contain decimal-string ID, status, paused/queued flags and exact Int64 input/output token counters. The protocol adapter must preserve these integers without JavaScript-number coercion. Prompt content, command output, provider secrets and raw task content are excluded from these projections. Tokens describe existing task usage, not a new model call.

The app issues opaque in-memory grants after client authorization. Grants expire on app restart and are bound to both the authenticated account epoch and current VM epoch. A revoked or changed epoch rejects dispatch and suppresses an in-flight response. The IPC server must authenticate a per-client connection, retain its own grant mapping, and never expose `authorize` as an MCP tool. The initial broker bounds grants to 128 and explicitly allowed tasks to 1,000 per grant. The local IPC implementation now bounds frames, verifies peer UID and a per-client capability, cancels reads on disconnect, and drains before closing sockets. The helper limits incoming lines to 64 KiB, queued messages to 32 and pending request IDs to eight, and makes partial-output failure terminal. The scoped native consent/revocation flow passed; active-client logout and VM lifecycle remain acceptance gates.

Task creation, start, resume, stop, skill instructions, findings and isolated tool execution remain unimplemented in MCP. In particular, the existing task creation and resume routes can schedule internal agent inference. External-AI mode must add and verify execution ownership through the backend lifecycle before exposing these writes. NetworkPNTR-agent delegation will use separately named tools with explicit model configuration and separate usage. Destructive actions, recording sensitive values, mock/session substitution and target-domain expansion must retain the API Recon consent requirements; a generic MCP connection grant does not authorize them.

Core checks use the fixed browser task-contract fixture `e75ae371ad777ffd1eecdd28d2781a6519b05591` and existing typed native services. This is a wire-contract comparison only. The packaged real stdio/helper agent-read flow is now verified below. Paired browser/native/MCP workflows, selected-task reads, clean-Mac client registration and client lifecycle remain open.

Use the [official Swift SDK](https://github.com/modelcontextprotocol/swift-sdk/tree/0.12.1) for the protocol adapter; review and lock its dependency graph before integration. The [official transport specification](https://modelcontextprotocol.io/specification/latest/basic/transports) defines stdio as the local helper transport.

Development verification: `swift test --disable-automatic-resolution --filter 'MCPIPC|BoundedStdio'` runs real Unix-socket and helper-process checks using synthetic services, including a task ID and token count above 2^53. The helper command is `NetworkPNTRMCP --connection-file PRIVATE_CONNECTION_FILE`; that file must be app-issued after consent. The AI connections screen issues this file after explicit consent; its scoped live agent-read/revocation check passed. Remaining broader gates are listed below. The helper accepts single JSON-RPC messages, rejects explicit null/malformed IDs and batches, and bounds pending request IDs before the SDK dispatches them. The app-owned finite dispatcher uses the official SDK message codecs, returns errors for pre-initialization calls and retires their slots. The SDK server receive pump is not used because its public API lacks a completion hook for suppressed cancellation responses. A canceled caller connection retires its backend read before the app accepts the next connection.

Request lifetime checks include 13 repeated cancellations, immediate cancellation, 8 active requests followed by a ninth overload error and cancellation recovery. Overload does not wait ahead of control notifications. Slots retire after handler drain using a per-dispatch UUID, including suppressed responses; old cleanup cannot retire a newer ticket. IPC and idle stdin waits yield the cooperative executor. MCP request IDs must be unique within a session, as required by the [base protocol](https://modelcontextprotocol.io/specification/2025-06-18/basic).

Socket-backlog recovery retries only connection establishment, before any request bytes are written, with fresh descriptors and the existing overall deadline. It does not replay a dispatched read. The stress driver closes 200 unfinished connections and then verifies an authorized task read. A transient aborted peer does not end the listener. The regression suite also waits for the real asynchronous Ollama URLProtocol stop callback before asserting its cancellation witness.

## Two MCP directions

The user confirmed both directions are required. Inbound server: external AI → packaged helper → app broker → dedicated VM. Outbound client: the app/guest agent → authorized external MCP server. `MCPClientStore` tracks inbound callers; its name does not mean that the native outbound MCP client is finished.

The frozen backend exposes external-server metadata and agent assignments. `AgentCatalogService` reads these assignments; this does not prove external MCP connection or tool execution. The native `/system/mcp` replacement remains pending in `feature-map.json`. Add native server registration/edit/remove, transport-specific connection settings, tool discovery/refresh, errors and agent assignment without executing stdio commands on macOS. Guest subprocesses belong in the dedicated VM; remote transport needs its own bounded, authorized network path. Verify an independent disposable MCP fixture through real connect/list/call/disconnect, timeout/cancellation, malformed responses, revoked access and restart persistence. Compare the same supported workflows with the pinned browser. Neither outbound completion nor inbound task writes are closed by metadata-only reads.
