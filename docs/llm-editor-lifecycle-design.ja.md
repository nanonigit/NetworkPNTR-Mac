# LLM編集シートのライフサイクル

## 要件

モデル取得・接続試験・保存のタスクを編集シートで所有する。閉じる際は可能なら送信前に取り消し、APIキー・プロキシの一時入力を消し、遅延した結果・エラー・閉じる操作を破棄する。送信済みの接続試験は実行済みの可能性があり、取消は巻き戻しではない。入力変更は候補・試験結果・保存済み通知を無効にし、Unicodeのバイト差も扱う。未終了の処理は同じシートを再表示してもゲートを保持する。保存には既存LLMStoreの送信所有権・結果不明時の制御を使う。自動クラウド要求・再試行・秘密の永続化・ホストでのエージェント実行は追加しない。ブラウザの全入力項目と日英操作を維持する。

## 設計と参照

MainActorのLLMEditorModelに入力・検証状態・一時応答・タスクハンドルを集約する。単一チケットは活動世代・入力世代・操作種別を持ち、秘密の追加保存先にはしない。獲得後に再確認し、Observation通知から閉じた場合は送信しない。入力の代入で同期的に世代を進め、確認済み保存後の明示的なキー消去では保存通知を維持する。closeは表示状態の更新前に活動世代を無効にし、再入にも対応する。再表示だけでは未終了のチケットを解放しない。応答と終了処理の所有権を確認し、現在のシートの保存成功だけで閉じる。SwiftUIはモデルにバインドし、離脱で取消する。保存中は対話的なシート終了を禁止するが、強制離脱でも取消を要求し、送信後の不明状態はLLMStoreが保持する。

主な基準は固定版e75ae371ad777ffd1eecdd28d2781a6519b05591のLLM画面と既存入力一覧。Lazywebのdesktop検索 `api connection test`（2026-10-28）は弱い近似メタデータのみ：Postman Inc250775の試験一覧・検証、Postman245868の要求フロー、Uptrends233805。画像の実見や受入証拠ではない。ARTEXの明示的な取得・試験・保存、処理中の表示、入力ラベルを維持し、見た目の再設計や文言追加はしない。

## 実装と受入順序

1. 所有者欠落のRED：開始前終了、待機中の遅延応答、バイト差を含む入力変更、直列化、現在の成功・失敗、保存通知とキー消去。
2. タスクとチケットを実装し、同期通知からの離脱、閉じて再表示、古い保存、ストアの結果不明制御との連携を試験。
3. 既存操作・離脱・終了を接続し、日英の画面外構築が通信しないことを確認。CJK・FEFF・NFDの任意入力は維持する。
4. 独立レビュー、関連・全回帰、カバレッジ、署名付きビルド、対象コミットCI。実操作・キーボード・VoiceOver・ブラウザ画面比較は手動解除後。合成応答では実プロバイダ／ゲスト受入を証明しない。プロセス終了をまたぐ不明状態と製品全体の残条件は維持する。
