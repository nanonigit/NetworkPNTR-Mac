# Actions利用枠への一時対応

証拠：2026-10-28にユーザーから共有されたGitHub通知は、アカウントの無料枠2,000／2,000分使用済み、2026-11-01リセット予定と記載。前回40643534669はステップ開始前に停止し、一般的な支払い／利用上限エラーを返していた。今回の画像で無料枠消費が確認できるが、超過課金の有効／無効までは確定しない。課金設定や予算は変更していない。

ローカルの全体試験、カバレッジ、ゲスト形式チェック、署名ビルド、実機受入を継続する。push前に差分確認と必要なローカル試験を終え、HEADコミットへ[skip ci]を入れる。現ワークフローの起動条件はpush／pull_requestのみで、この方法に対応。利用可能枠の再確認までActionsの手動起動／再実行をしない。スキップや利用枠による停止を成功としない。リリース時のリモート検証は未完のまま保持し、利用可能になってから実行して結果を確認する。自動再開や予約ジョブは作成していない。他リポジトリ／他ユーザーによる消費までは制御していない。

[GitHub公式のスキップ仕様](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/skip-workflow-runs)には、対象イベントと必須チェックがpendingに残る点が記載されている。ワークフロー自体は維持し、アカウント全体のActionsを無効化していない。枠の回復だけでテスト成功とは扱わない。
