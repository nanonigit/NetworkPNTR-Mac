# 要件と完成ゴール

別の非公開リポジトリnanonigit/artex-macとして、ネイティブMacアプリを作る。このApple Silicon Macで、ブラウザ・Docker Desktop・ターミナル・手動のサーバー起動なしに利用できる。画面はSwiftUI、AIのコマンド実行とDBはアプリ管理のLinux VM内に置く。

## 完成条件

R1. ブラウザ版の主要21機能、全画面・詳細画面・操作を機能対応表へ記載し、機能を黙って省略しない。外観だけでなく一連の操作の同等性が必要。
R2. e75ae371ad777ffd1eecdd28d2781a6519b05591を比較基準に固定。同じ入力・データで、入力検証、エラー、空状態、進捗、キャンセル、更新、出力、再起動後の保存を比較する。APIテストと画面操作の証拠を分けて残す。
R3. Features/Systemの階層、項目名・順序、タスクと詳細の関係を踏襲する。Macのメニュー・キーボード・ウィンドウに合わせた変更は理由と比較テストを記録する。Lazywebは補助資料、ブラウザ版を主基準とする。
R4. AIからのホスト上のシェル実行、Dockerソケット、ホスト共有フォルダ、任意ホストRPCを禁止。初期VMはネットワークなし。後で明示的な接続先ポリシーを設計する。キーをログ・Gitに保存しない。
R5. 起動・停止・再起動、クラッシュ、容量不足、更新失敗と復旧を検証する。データは専用ゲストディスクに保存。現在のブラウザ版は別環境として保存し、移行は検証済みの明示的インポートで行う。
R6. ローカル起動できる.appを作る。配布署名・公証・初期Macでの導入・ライセンス・復元検証は最終段階の必須条件。まずApple Silicon/macOS 15以降を対象とし、Intel対応は未実装と明記する。
R7. AIの結果や進捗を捏造しない。VMの起動状態・ゲスト起動確認・API起動完了は区別する。APIが通るだけでネイティブ画面を完成扱いにしない。

最初の到達点はフェーズ0の設計文書とフェーズ1のVM技術実証。以降も全体ゴールとして残し、モック画面やWebViewだけで全体完了にしない。

A3全内容照合の追加要件: 約128MiBの実添付を認証付きvsock経由で全バイト取得し、一定量のメモリでハッシュ照合する。通常JSONの4MiB制限、認証世代、取消/VM停止時の記述子所有権、固定ブラウザを維持。期待サイズとHTTPフレーミングの完全一致を要求し、不完全・超過・圧縮・曖昧な応答を拒否する。これは受信内容の証明であり、同時書換えに対するファイルスナップショット保証ではない。添付UIとダウンロード/書出し操作全体は別の未完了ゲート。

添付の進捗/取消追加要件: 実際にソケットへ書いたmultipart本文のバイト数を単調増加で通知し、認証情報/HTTPヘッダー/ホストパスを含めない。通知頻度を制限し、本文送信完了とサーバー保存成功を区別する。Task取消、VM停止、ログアウト/再ログイン後の古い応答・進捗を採用しない。実VZで1MiB以上の本文転送中の取消/停止をソケット単体テストと別に確認し、再起動後は所有する部分ファイルだけを確認・清掃する。

A4添付下書き要件: name/path/sizeを保持し、任意のゲストabsは表示/送信モデルから除外。uploads/単一basenameと非負の128MiB以下のサイズを検証。本文なし+添付ありの送信を許可し、両方なしは通信前に拒否。会話別所有権とstop/resetの世代を守る。ブラウザ同様の送信時クリア/失敗時復元を行い、新しい編集/添付を古い応答で上書きしない。カード除去はローカル下書きだけでゲストを削除しない。ファイル名/パスはUnicode正規等価性でなくUTF8バイトで識別する。会話作成/アップロード引継ぎとpicker/cardsの検証は後続必須ゲート。

A4.2転送所有権: feature側はJWT/任意経路を受け取らない認証済み型付きAPIを使う。空選択/非対応能力は会話作成前に拒否。新規は一度だけ会話を作成、既存は直接そのIDへ送る。本文と型付きカードを保持し、選択変更後も元の所有会話へだけ結果を保存して選択を奪わない。起点/対象ごとに重複を防ぎ、取消/stop/reset/削除で古い結果や進捗の復活を防ぐ。削除失敗では従来の下書きを保持。取り消したからといって受理済みゲストファイルを暗黙削除しない。picker/cards/UIと全体同等性は後続ゲート。
