# F5c 通信証跡のネイティブUI：要件・設計・順序

## 完全な対象と固定版

全21機能の受入条件を維持する。固定版e75ae371ad777ffd1eecdd28d2781a6519b05591のfinding-traffic-panel.tsx、traffic-picker-dialog.tsx、traffic-evidence-viewer.tsxを操作一覧の基準にする。元のDocker比較環境を保持し、ホストでエージェントコマンドを実行しない。

必要な操作は、役割・メソッド／状態・URL・時刻・注記・証跡IDの一覧、継承／旧形式の読取専用表示、通信追加、4役割と注記の編集、世代付きの上下移動、解除、要求／応答タブ、初期・追加のバイトプレビュー、バイナリ表示、原文全体の保存。候補選択にはホスト・メソッド・キーワード検索、0起点25件ページ、個別・ページ選択、既存紐付けの除外、ページをまたぐ選択数、元通信のプレビュー、明示的な追加・取消が必要。読み込み・空・失敗・再取得、確定変更後のレポート古さの更新、結果不明時の復旧、所有者を固定した確認、日英表示を維持する。記録URLの表示だけで接続・実行・ブラウザ起動しない。

Lazywebのdesktop検索 `http request inspector`（2026-10-28）は弱い近似メタデータのみ：Postman Inc250787のGET設定、Retool243659のヘッダ／本文、HTTPie248764の文書。画像の実見や同等性の証拠ではない。ARTEXの一覧→プレビュー→明示的操作と、読みやすい等幅の要求／応答・ラベルを維持する。キー操作・VoiceOver・画像・ブラウザ比較は手動解除後。

## 前提監査と構成

既存FindingTrafficService/Storeは紐付け一覧・詳細・バイトページ、追加・編集・解除・順序と送信／結果不明の所有権を扱うが、画面モデル・詳細UIには未接続。候補の`/api/traffic`と元通信の`/api/traffic/exchange?id=`の型付き取得が不足している。原文保存も未実装で、既存添付ダウンロードはダイジェスト検証まで。プレビューを保存の代わりにしない。全バイト転送と明示的な保存ダイアログ・原子的出力は別途の境界実装・試験が必要。

F5c1では固定版server.goのgetTraffic/getTrafficExchange、dto.goのTrafficExchangeDTO、traffic.Pageに基づく有限JSON契約を追加する。ページは0起点、件数1〜500（選択画面は25）、host/method/qをクエリ値として符号化。通信IDは数値のFinding IDではなく、上限付き不透明UTF8としてバイト差を保持する。取得停止中もメタデータ付きの記録履歴は表示できる。利用不可は`enabled:false`・空配列・メタデータ全欠落という索引なしの形だけとし、欠落・null・部分データを空成功にしない。ページ・件数は要求と一致させ、別SQLで取得した総数と一覧が完全な同時点とは仮定しない。元通信req/respはblob参照を含む不透明文字列。両経路とも認証済み固定GET・await前後の取消・200限定・4MiB上限とし、エラー本文を返さない。

次に候補・プレビューの所有状態、ウィンドウ／詳細／確認操作への接続、全バイト出力、ネイティブ操作、実ゲスト／ブラウザ比較を進める。選択はUTF8バイト単位で、ページをまたぐ明示的な選択を保持し、古い候補・既存紐付けの追加を防ぐ。書込の世代／不明ゲートを維持し、レポート再取得は確定後のみ。離脱・リセットは未終了の書込を解放せず子の活動を失効させる。親フィルタ・移動・通常編集も共通の処理中ゲートで制御する。

## 順序と受入

1. 候補API欠落RED→型・サービスGREEN→欠落/null/停止中履歴/Unicode/クエリ/状態/取消/上限の敵対的試験→レビュー・全回帰・ビルド・CI。
2. 候補／プレビューと親接続のRED→所有状態→確認UI・日英リソース、古さ・409・不明・取消の試験。
3. 認証済み全バイト転送・出力のRED→バイナリ・大容量・ハッシュ・中断・原子的出力の試験→明示的保存UI。ダイジェストやプレビューを保存完了と呼ばない。
4. 一覧・候補・編集・ビューアの操作一覧と画面外の日英・明暗試験。元ソースと記録データを保持。
5. 実際の非空ゲスト／比較API・永続化、その後に解除済みMacでの操作・VoiceOver・画像比較。実受入・F5・製品全体の条件は該当する証拠が揃うまで未完了。
