# T16 アーカイブ画面設計

固定e75ae371のTaskArchivesPanelとTablePaginationを基準にする。列はチェック、名前/説明/ID、元状態、カテゴリ、保管/受付日時、圧縮サイズと元サイズ/節約率、データ行数、状態/進捗/段階/エラー/警告、操作の9列。横スクロール可能なネイティブTableを使いWeb描画・権限・依存を増やさない。名前→説明→翻訳済みタスクIDの順で見出しを補う。文字列はそのまま、件数はバイト識別とDecimal集計で桁あふれを防ぐ。段階・状態は型付き英日ラベル、生診断はアプリ表示にしない。

Lazywebのdesktop archive restore table検索でAmplitudeのアーカイブ表とHarvestの復元/削除のある保管一覧を取得した。メタデータの一致は中程度0.454で見た目の同等性は主張しない。取得したImpeccable clarify（https://raw.githubusercontent.com/pbakaus/impeccable/main/.claude/skills/impeccable/reference/clarify.md）から具体的な操作名、削除の結果、固定ラベル、空/フィルタ/失敗の区別、正確な受付状態、英日の完全メッセージを適用する。検索は設計根拠で最終成果物ではない。画面取得は利用者の解除待ちとし、架空の画面やレポートは作らない。

画面モデルがタブと検索を保持する。タブ切替は双方の古い更新所有権を無効化してから.task(id:tab)で再開し、ダイアログ・送信・不明確認中は切替不可。ライブアーカイブ受付後に保管タブへ移り結果シートを残す。受付後の再取得は排他解放後の読み取りだけを予約する。復元再照合リビジョン変更でライブ一覧/詳細とカテゴリ再取得を一度だけ促す。停止は更新タスクをキャンセルしてタブ・条件・受付を保持、リセットは世代を替えライブへ戻す。言語変更で操作を再送しない。

検索は正規化せずサーバーへ送信する。状態・表示数変更は1ページへ。総ページ計算は桁あふれせず不正ページへ進めない。バインディングはviewOwnerとcontextIDを捕捉し、古い閉じる/選択/条件変更を新画面へ適用しない。処理中は条件操作不可。行の操作名にタスクIDを含め、ページ全選択は処理中を除き全/一部/なしを伝える。選択中の復元/削除可能項目を捕捉し、復元・再試行も明示確認する。完全削除は不可逆性とDecimalでの件数/サイズを示す。送信後シートはIDごとの受付・拒否・不明・未開始と受付のみの注意を示し、停止/閉じるを用意する。不明は捕捉したIDの確認まで自動再送しない。ライブ詳細と一括操作にもアーカイブを加える。

英日表/シートのオフスクリーン描画、キーと変数、古い所有者/ダイアログ、描画時の未送信、巨大件数・ページ・Unicode、タブ所有権と受付/復元通知をTDDする。試験だけでは実表示・キーボード・AX・VMジョブを証明しない。新規状態でVMと固定ブラウザの実ジョブ・永続性と全21機能の受け入れは未完了。

実行検証後の更新: 通知を単一タスクの再実行へまとめ、変更/一覧/詳細の排他中も要求を保持して弱参照とチケット付き監視で再開する。所有権のある読取確定リビジョンが変わるまで要求を消さず、停止/リセットで監視とタスクを解除する。検索はブラウザのキー入力ごとの再取得と異なり、ネイティブのReturn/検索ボタンで送信し草稿を保持する。バイト表示は同じ数量の2進単位をKiB/MiBと明記する。どちらの調整も実画面比較が必要。
