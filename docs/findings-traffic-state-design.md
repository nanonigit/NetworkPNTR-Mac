# F5b owned traffic state

Requirements: window-owned evidence summary, selected binding detail and one explicit body byte page must not accept replies from another finding/task/binding/side/offset or session. Fresh captured snapshots gate one deliberate write. Keep en/ja safe failures, raw user content and byte offsets; no automatic retries. Service contracts alone do not satisfy this phase.

Use FindingReadState generations for summary/detail/body and an observable FindingTrafficStore with selection owner, session and activity identities. Selection change clears dependent snapshots; binding change clears detail/body; side/offset change clears body. Refreshes preserve same-query last-good data as stale on error. Successful summary reconciliation removes a selected binding only if absent; failure must not erase it. Detail must finish before body paging so preview total can be tied to the immutable snapshot side length. Body response total must match that captured length. Explicit offset/next page actions are bounded by the selected body and byte values; no auto-fetch loop.

Prepare a write locally before marking it dispatched; invalid input produces zero requests and no uncertainty. Require active/current owner, fresh summary, no current summary-read/write collision and no unresolved unknown outcome. Pending detail/body read generations are invalidated before handoff. Invalidate reads before handoff. A valid response becomes the confirmed summary directly; preserve lastConfirmation if a subsequent refresh fails. Clear stale binding detail/body and reconcile membership. All post-handoff errors, including409/cancel/malformed success, retain an unknown finding ID and captured revision; reads do not acknowledge it. A current owner can explicitly acknowledge only that selected finding and exact revision after the write settles. This conservative divergence from browser reload-only errors is intentional and does not change backend APIs.

Stop invalidates activity/owner/reads, preserves uncertainty and busy while a write is pending, and discards its late success. Resume requires refresh and keeps unknown outcomes. Reset/logout changes session, clears all state and permits a fresh session; old cleanup/replies cannot change its newer busy/read state. Selection is refused while writing. Cancellation before dispatch is not unknown. No state method launches a task/agent or changes VM/network capabilities.
